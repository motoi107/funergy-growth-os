# v1118 キャッシュチップ：未登録を自動で 0 にする（Moto さん 2026-10-30 の依頼 ①）

## 1. 依頼の要点

- 登録されていない日は、自動で数値の 0 を保存します。対象は全店・全期間で、締めた期間も含みます。
- 未登録をエラー・警告・未対応の数に入れません。一覧・集計・通知で同じ判定にし、前の知らせも数えないようにします。
- 登録済みの金額は変えません。もとから入っていた 0 も正しい値として扱います。
- 取得の失敗・同期の失敗・読み込み中を未登録とみなして 0 で上書きしません。
- 不正な値と、ほかの勤怠・チップのエラーは今までどおり出します。
- 表示だけでなく保存値もそろえます。あとから本当の金額に直せます。
- 締めた支給・配分を確定し直しません。
- 埋めた数・期間・残りの数を報告します。読み込み直しや同期のあとにエラーが戻らないこと、2 回流しても重ねて足さないことを示します。

## 2. 今まで（v1117）の作り（コードで確かめたこと）

- 保存の場所は app_state の `cash_tips_<店>` です。形は `{日付: {lunch, dinner, lunchEntered, dinnerEntered, entered, by, at, editedBy, editedAt}}`。
  - 合流は日ごとで、時刻（editedAt か at）の新しいほうを採ります。側ごとに「入力済み」を持ち越します。
- 計算は前から 0 でした。`getCashTip` は記録が無ければ `{lunch:0, dinner:0}`、`tipForDay` は `cash.lunch||0` です。
  - だから未登録の日も支給額・配分は 0 として計算済みで、0 を保存しても金額は変わりません。
- 「未入力」と判定していたのは `cashTipMissing` です。クレジットチップか売上がある営業日で、営業している側に「入力済み」の印が無ければ未入力でした。
- 未入力を出していた所は次の 7 つです。
  - Store CMD・Tip の日別・日の振り分けの画面の赤い帯
  - Tip の期間の「エラーのある日」（Tip を確定できない）
  - エラーセンター（直近 14 日・要対応）と、その過去ログ（査定の参考の数）
  - 前日の未入力の通知（v1088）
  - 業務Bot の朝 9:00 のキャッシュチップ未入力の知らせ（LINE）
- 未登録の形は次の 4 つです（本番の数は `2_確認と見込み_読むだけ.sql` の ② で見ます）。
  - 記録が無い
  - 片方の側だけ入っている
  - 「入力済み」の印が無い（値が空・null・0 でも）
  - 「入力済み」なのに値が null か空の文字

## 3. v1118 の決まり

- 未登録は 0 として計算し、エラーにしません。
  - 画面には「未入力のため 0 として計算しています（翌日に自動で 0 を保存）」と薄く出します。
  - 自動で 0 を保存したあとは「自動で 0 を保存しています」と出ます。
- 自動の 0 は `<側>:0・<側>Auto:true` です。「入力済み」の印（`<側>Entered`・`entered`）と記録の時刻（at・editedAt）は付けません。
  - 前の版（v1117）は自動の 0 を「まだ入っていない」と読みます。だから前の版の合流でも、人が入れた値（Entered あり）が必ず勝ちます。
  - v1118 の合流は側ごとに、人が入れた値 ＞ 戻した印（`<側>Auto:false`）＞ 自動の 0 ＞ 入っていない、の順で決めます。同じ強さなら時刻の新しいほうです。
  - 人がその側を保存すると Auto の印は消えます。前の版で保存して Auto が残っても、Entered があれば人の値です。
  - 印の無い 0 でない金額（前からある記録）は、その金額で計算されているので「入っている」とみなします。サーバーも書き換えません。
- 不正な値は今までどおりエラーです。不正とは、数でない・マイナス・無限の値です。空・無しは 0 として正しい値です。
  - エラーセンターでは、EC_MIN_DATE（2026-07-01）から昨日までの記録のある日すべてを見ます。
    - 鍵は `tipinv|店|日`、fp は不正な値です。直すと消え、別の不正な値ならまた出ます。
  - Tip の期間の「エラーのある日」と、業務Bot の朝の知らせも不正な値だけにしました。
- 前の知らせは消さずに残し、数えません。
  - 過去ログの「キャッシュチップ未登録」（鍵 `tip|…`、鍵の無い前の記録は題名で見分けます）は数えず、件数を一行で出します。
  - 前の通知（refId `ctip_…`）は一覧と未読の数から外します。v1088 の新しい通知は出しません。

## 4. サーバー（migration `20261031090000`）

- `cash_tip_autofill(from, to, apply)`：終わった営業日（ハワイ時間の今日より前）の、まだ入っていない側に自動の 0 を書きます。
  - 書くのは、売上かクレジットチップのある日だけです。
    - toast_sales の行がある日（credit tip がある、か net_sales > 0）
    - daily_actuals_<店> に actual > 0 か credit tip の欄がある日
  - 売上の取り込みに失敗した日（行が無い日）には書きません。取得の失敗を未登録とみなさないためです。
  - 書くのは、入力済みの印も Auto の印も無く、値が無い・null・空の文字・0 の側だけです。
    - 人が入れた値（0 も）・印の無い 0 でない金額・不正な値・前の形の「entered」は変えません。
    - 包まれた形の行は飛ばします。FSP と Waikiki Garlic Shack も書きません。
    - 読めない日付（2026-02-30 など）は飛ばします（1 つの悪い日付で全体を止めない）。
  - 書くときは行を押さえます（for update）。そのあいだにアプリが書いた値を消しません。
  - 2 回流しても同じです（重ねて足しません）。apply=false は見込みだけで、何も書きません。
  - 書いた日と書く前の記録は `cash_tip_autofill_log` に残ります（run_id ごと）。
- `cash_tip_autofill_undo(run_id)`：その回で書いた側のうち、まだ自動の 0 のままの側だけを書く前の値に戻し、戻した印（`<側>Auto:false`）を残します。
  - 戻した側は次の回でまた書きません。v1118 の端末が持っている自動の 0 でも元に戻りません。
- 実行できるのは service_role だけです（ブラウザーの鍵では実行できません）。
- 毎日 2 回動かします（pg_cron、ハワイ時間 4:17 と 8:47、直近 62 日）。2 回目は朝 9:00 の業務Bot の知らせより前です。

## 5. 締めた期間・支給

- Tip の確定・締めの記録は触りません。金額は前から 0 なので変わりません。
- 前の版（v1117）の端末は自動の 0 を「入っている」と読みます。0 を書いた日は前の版でもエラーに出ません。

## 7. 限界

- 売上もクレジットチップも無い営業日には書きません（計算は 0 のまま、エラーにもなりません）。
- 前の版の端末は、自動の 0 を書いた日も更新するまで未登録のエラーを出します。
- 前の版の端末は戻した印を知りません。持っている自動の 0 をまた送ることがあります（計算は 0 のまま）。
