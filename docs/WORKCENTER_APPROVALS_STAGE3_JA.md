## サーバー

- SQL `supabase/migrations/20261123090000_work_requests_stage3.sql`（段階 2 のあと・2 回流しても同じ）。`wr_stage` は 6。
- `wr_s3_import(p)`：GM・CEO・段階 2 を使っているときだけ。端末は前の記録の id・種類・店・表示用の中身（段階 2 と同じ形）を送る（100 件まで）。
  - 状態・種類・店・申請した人・決めた人・決めた日は、サーバーが共通データ（`approvals` と分割の行・新しい印のほう）から読む。端末の言うことは使わない。
  - 店は前の記録の店（id か名前・本部の書き方）と同じときだけ。
  - 決めた日（ハワイ）は `decidedAt` → `_stT` → 申請の id のミリ秒。
  - 返す：結果（pending・history・known・in_wc・old・missing・deleted・kind・store・status）と、もう写した前の記録の id。
- 予算：
  - 承認待ちは、その店・その月の申請になる（あとの予算変更はその新しい版）。同じ店・同じ月にもう段階 2 の申請があれば写さない。
  - 写した履歴には額・日ごとを残さない（今の予算は承認したときと違うことがある）。あとの予算の版の元にもしない（`wr_submit_s2` に `not wr_s3_hist(x)` の 1 行）。
- 関数 work-requests：`s3_import`（形を整えて渡すだけ）・whoami `fn: 6`。本番に貼るのは非公開の 1 ファイル（PIN の確かめ入り・チャットも入っている）。

## アプリ v1159

- `wrS3Seen()`：この端末が聞いた「段階 3」（`_wr_s3_v1`）。メニューを作るとき・前の行き先を変えるときに使う。ログインのたび（`wrPing`）とワークセンターを開いたときに聞き直す。
- 閉じたあと：
  - メニューの承認センター（`navChildAllowed`）とワークセンターの「承認」タブを出さない。
  - 前の行き先（`approval`・`workTab=approval`）はワークセンターの申請へ。
  - 前の承認待ちの数（バッジ・ダッシュボード・今日のカード）は 0。
- 写す（GM・CEO）：はじめに空で呼んで「もう写した id」を受け取り、残りを 100 件ずつ。承認待ちは前の記録に段階 2 の印。写したら知らせる（1 回）。失敗したら次のログインでもう一度。
- 履歴の「前の承認タブから」（写したものだけ）・一覧の札「前の承認タブ」・詳細の「前の承認タブから写した」（前の状態・決めた人・日・理由・ボタンが無いわけ）。

## 限界

- 閉じるのは、端末が段階 3 を聞いてから（ログインの直後に聞く）。前の版（1158 まで）の端末は、前の承認タブを出したまま（写した承認待ちは段階 2 の印で押せない。印を付ける前に押すと、ワークセンターの反映は「もう決まっていれば記録だけ」）。
- 写すのは GM・CEO がログインしたとき。それまで、前の承認待ちは前のタブ（1158 まで）でしか見えない。
- 前の承認タブで途中まで承認していた分（「全員」の種類の一部の承認）は写さない（ワークセンターでは初めから）。
- 前のタブで経理の確認がまだだった承認済みも、履歴（確認なし）になる。
- 申請した人は前の記録の名前から社員を探す（見つからなければ名前だけ）。
- 段階 2 の SQL をあとで流し直すと、`wr_submit_s2`・`wr_stage` が前に戻る → ② も流し直す。
