## 3. エラーセンター

### 3.1 1 件ずつの印

検知ごとに `key`（どの不備か）と `fp`（中身）、店舗・日付を付けた。解除が効くのは同じ key で fp も同じとき。中身が変われば、解除していても「今の不備」にまた出る。

| 種類 | key | fp（変わるとまた出る） |
|---|---|---|
| キャッシュチップ未登録 | 店舗・日付 | なし |
| 退勤打刻漏れ | 店舗・日付・人 | 退勤の無い打刻の出勤時刻 |
| オーバーワーク | 人・週 | 上限と重さ（8h 以上の超過＝要対応に上がったら出す。時間が伸びても同じ重さなら出さない） |
| 従業員マスター | 不備の種類・人の ID | 不備にかかわる値（退職日と状態・役職と係数）。ほかはなし |
| 氏名・Email の重複 | 名前・Email | 人数 |
| オンボーディング | 1 件ごと | 状態 |
| 月次締め | 月 | なし（済んだ項目が増えても、解除したものは出さない） |
| 棚卸の異常値 | 店舗・棚卸の種類・品目（id・名前・無ければ行の番号） | 棚卸の月（日）と実棚・理論・差 |

### 3.2 並べ替えと絞り込み

- 並べ替え：重要度の高い順（初め）・種類ごと・店舗ごと（店舗マスターの順・店舗なしは最後）・日付の新しい順・日付の古い順。選んだ並べ替えはこの端末に覚える（`_ec_sort`・同期しない）。
- 絞り込み：店舗（その一覧にある店舗＋「店舗なし（本部・全社）」）・種類（件数つき）。複数の店にまたがるもの（オーバーワーク）は、どの店でも出る。
- PC は表（重要度・種類・店舗・日付・内容・直す／解除）、900px 以下はカード。

### 3.3 解除

- 行の「解除」→ 理由（対応した／問題ではない（誤検知）／この店は対象外）とメモ（任意・200 字まで）→「解除する」。「この店は対象外」はチップ・勤怠・棚卸で店舗のあるものだけ。
- 記録は共通データ `ec_resolutions`（OP_SYNC・LS_NEVER_FREE）。1 件は不備と中身の組（`key␞fp`）ごと：{ key, fp, why, memo, by, role, at, _at, off, 題名・店舗・日付など }。同じ不備の別の中身（翌月の棚卸・直した打刻）を解除しても、前の記録（誰が・いつ・どの理由）は残る。
- 解除・元に戻すの前にクラウドの最新を読む（6 秒で返らなければ進む）。読むあいだに「やめる」・×・外を押して閉じた、または別の画面が開いたら保存しない。保存のあいだは次の解除を開かない。
- 解除できる・元に戻せるのは CEO・GM・経理・事務Crew（6A）。見られるのも同じ（8A。事務Crew をナビのエラーセンターにも足した）。ほかの役職のエラータブには「見られる人」を出す（前は空だった。ワークセンター「今日」の件数・重要エラーは前と同じ）。
- 「解除済み」タブ：元に戻していない記録の一覧（新しい順・200 件まで・店舗と種類で絞れる）。理由・人・時刻・メモと、今も検知中か（同じ中身／中身が変わった／今の中身も解除済み／もう出ていない）。「元に戻す」。
- 件数（タブ・ワークセンター・ダッシュボード・Management Console）は解除していないものだけ。

### 3.4 合流（mergeEcRes）

- 記録ごとに `_at` の新しいほう。同じ時刻なら、キーを並べ替えた中身の文字列（`_logSig`）の大きいほう。クラウドの jsonb はキーの順を変えるので、そのままの文字列で比べると、書いたあとの確かめが通らず未送信が残り、端末ごとに勝ちが違った（4 回目のレビューで直した）。
- 元に戻すは `off:true` で上書き（消さない＝古い写しで解除が戻らない）。
- 大きくなり続けないように、元に戻してから 120 日・「対応した」から 400 日たった記録は、合流のときに小さな印 {key, fp, off, _m, _at} に縮める。印は 3 年で落とす。「対応した」は 400 日たつと解除でなくなる（同じ中身がまだ検知されていれば「今の不備」にまた出る）。「問題ではない」「この店は対象外」は縮めない。
- 書いたあとの確かめ（`_coversEcRes`）は合流と同じ決め方（縮めたもの・同じ時刻）。

### 3.5 過去ログ（査定用・7A）

- 毎日の記録（`ecSnapshot`）は解除していない不備だけ。key と fp も残す。店舗・人の数え方（題名から）は前と同じ。
- 記録はクラウドの解除を読み直してから（ほかの端末で解除したものを今日の記録に足さない）。過去ログを開いていれば、記録したあと描き直す。
- 「問題ではない（誤検知）」で解除した中身（key と fp が同じ記録）は数えない。v1088 より前の記録（key なし）は種類と題名で合わせる（棚卸は題名に月が無いので合わせない）。ほかの理由で解除したものは、解除する前の日の分を数える。数えなかった件数を画面に出す。
- 7A の文のとおり、「この店は対象外」で解除したものは数える。
- 同じ日・同じ題名の記録は 1 件のまま（1 日 1 件）。中身（key と fp）が違うもの（同じ日に「問題ではない」で解除したあとに重くなった・時刻が変わった）は、その記録の `parts` に足す。数えるのは「問題ではない」で解除していない中身があるときで、重さはその中身のいちばん重いもの。合流（`mergeEcLog`）は先に検知した記録を残し、中身は両方（key と fp の順に並べる）。書いたあとの確かめ（`_coversEcLog`）も中身まで見る（Codex のレビュー・下の 5b）。
