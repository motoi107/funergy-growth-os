    - AM が承認できるのは、写しで AM・その店を担当・社員の表でも AM で在籍・店の表の AM 欄もその人、がすべてそろうときだけ（社員 ID で比べる）。
  - ほか＝肩書き・役割からのグレード（G3 まで）。**社員の表に役割を書いても GM にも AM にもならない**（試験）。

- 同時の変更：読んだ版（rev）が違えば止める（conflict・何も書かない）。
- 段階（`wr_actions` がその人に今できることを返す。画面のボタンもこれだけ）：

| 状態 | 次 | できる人 |
|---|---|---|
| 承認待ち（pending） | 承認・差し戻し・却下 | ガソリン代：その店の AM（AM のいない店は GM）・GM・CEO。建て替え・事前経費：GM・CEO。自分の申請は不可 |
| 差し戻し中（returned） | 直して出し直す・取り下げ | 申請した人 |
| 経理の確認待ち（approved） | 確認・差し戻し | 経理・事務Crew（自分の申請は不可）。GM・CEO は「1 つ前に戻す」 |
| 支払・精算待ち（checked） | 支払・精算（日付・方法） | 経理・事務Crew・GM・CEO（自分の申請は不可・重複の候補が確かめ済みのときだけ） |
| 精算済み（paid）・完了（done・事前経費は ② で完了） | 1 つ前に戻す（理由） | 経理・事務Crew・GM・CEO |

- 差し戻し・却下・1 つ前に戻す・別の経費と確かめた、は理由が要る。
- 差し戻すと前の承認は外れ（履歴には残る）、出し直した版にもう一度承認が要る。
- 重複の候補：ガソリン代・事前経費＝同じ人・同じ日・同じ金額。建て替え＝同じ店・同じ日・同じ金額（だれが出しても）。取り下げ・却下は除く。
  - 同じ種類・日付・金額の送信は 1 本ずつ（advisory lock）にしてから探す。精算の前にもう一度探し、新しい候補があれば精算せずに印を付けて止める（`dup_found`。#123 のレビュー P2）。
  - 候補があると、理由を書かないと出せない（何も書かない）。理由を付けて出すと「重複の候補」の印が付き、承認する人か経理が「別の経費と確かめた（理由）」を記録するまで精算できない。自動では消さない・まとめない。
  - 見られない人の申請は番号だけ出す。
- ガソリン代の金額はサーバーが今の単価（app_state の mileage_config・読むだけ）で決める。
- 前からの申請（`wr_legacy_import`・GM・CEO・使い始めるときに 1 回・2 回流しても同じ）：
  - app_state の mileage_requests・reimbursements・expense_requests（`spl_` の行も）を写す。消したもの（`_deleted`）は写さない。
  - 状態：申請中 → 承認待ち／却下 → 却下／承認 → 承認センターの経理の確認（取り消していないもの）があれば確認済み、ガソリン代の月末処理・建て替えの支払済みは精算済み、ほかは経理の確認待ち。
  - 承認した人は記録があるときだけ（日時は前の画面の文字のまま）。無いものは「記録なし」。
  - 写したあとは新しい表が正。前からの申請も承認・確認・精算・取り下げはできる。
  - 社員 ID の分かる前からの申請は、差し戻し → 本人が前の記録の中身から直して出し直す（同じ番号・版が上がる）。社員 ID の分からないものは差し戻せない（承認か却下。#123 のレビュー P2）。
  - 写したあとに前の画面（1130 以前の端末など）で精算済みになったもの（建て替えの支払済・ガソリン代の月末処理）を精算するときは止めて確かめる（`legacy_paid`。二重に払わない）。
