## 3. ②：LaLa のリピート率（v1090）

### ToriTon で確かめたリピート率の定義（コードで確かめた範囲）

- 何を数えるか：Toast の注文の来店区分。ToriTon・Tenkichi は Customers のメニューの FT（初回）・RP（リピート）・SR（Super Regular）の商品、Totoya は丼のモディファイヤー（`index.html` の注記と、来店区分の診断の項目名から）。数えるのは Toast 取込（hyper-worker）で、日ごとに `toast_sales` の `first_time_count`・`repeat_count`・`super_regular_count`（ランチ・ディナー別も）に入れる。**hyper-worker のソースは手元に無いので、注文ごとか商品の数ごとか・取消の扱いは確かめていない。**
- 分子・分母：リピート率 ＝ リピート（RP＋SR）÷（初回 FT＋リピート）。単位は FT・RP・SR の数（アプリの表示は「リピート」「初回」「対象計」）。SR はリピートの内数（カードに「うち Super Regular」と出る）。
- 取得元：`toast_sales`（hyper-worker）→ アプリの日次実績（`daily_actuals_<店舗>` の `firstTimeBowls`・`repeatBowls`・`superRegular`、L/D 別）。営業日の区切りは Toast の営業日（`business_date`）。
- 未入力・未取込・0 件：その日の行に数が無ければ数えない（`has` が立たない）。月に 1 日も無ければ「—」（会議・KPI 一覧・月次サマリー）。対象計が 0 なら率を出さない。
- 集計：日次・月次・累計とも、期間の FT・RP を足してから割る（日ごとの率の平均ではない）。複数店も数を足してから割る。
- 除外：Waikiki Five Star Poke（F03）・Garlic Shack（F03-G）は来店区分を使わず手入力（KPI 管理）。ほかの店は手入力できない。

### LaLa への適用

- アプリの計算はどの店も同じ関数（`repeatStats`・`repeatStatsLD`・`keyKpiStats`・`computeKpiActuals`・`_qbRepeatRate`）で、LaLa（F06）・ToriTon（F01）を特別に扱う所は無い（試験で確かめた）。同じ日次実績なら同じ数字になる。
- 予実管理でリピート率を使う所：KPI 管理・ダッシュボードの総合スコア（`computeKpiActuals`）、月次サマリーの KPI 実績・リピーター分析・リピート率カード、予実管理の日次の表（日ごとのリピート率）、会議タブ（L/D 別も）、中間レビュー（会議タブと同じ `keyKpiStats`）、Qコミット（月・四半期・日次のグラフ）、施策分析（初回・リピートの人数）。
- LaLa の数字が出ないとすれば、元の `toast_sales` に LaLa の来店区分が入っていない（Toast の LaLa に Customers の FT・RP・SR が無い、または hyper-worker が LaLa を数えていない）。`db/lala-repeat-check.sql`（読むだけ）で確かめる。来店区分の診断（同期センター）は「店舗別 詳細オプション」で選んだ店（LaLa）でも動くようにした（前は先頭の店だけ）。
- 直したこと：Qコミットのリピート率は、来店区分のデータが無い月を 0% にしていた（`_qbRepeatRate`・`quarterActuals`・`qcCompute`）。null（データなし）にし、表は「データなし（未取得）」・差は出さない（`renderQcKpiTable`・`renderQCommitSummary`・`_qbProgLine`）。本当の 0%（初回だけでリピート 0）は 0% のまま。月次サマリーの注記の「リピート率等は手入力」は古いので直した。
- 目標値（報告）：会議タブ・中間レビューは KPI 管理で店に入れた目標だけを使い、無ければ未設定。KPI 一覧・Qコミットは店の目標が無ければ業態の初期値（食事 35%・居酒屋 40%）を使う。ToriTon の目標を写す所は無い。業態の初期値を「未設定」に変えるかは Moto さんの判断（変えるとほかの店にも効く）。
- SQL の結果（Moto さん 10/17 16:23 HST・`db/lala-repeat-check.sql` の 2 つ目）：ToriTon は 1 月〜10 月の毎日に数がある（本番の数字はここに書かない）。**LaLa は 9 月 15 日・10 月 17 日の行に来店区分の欄はあるが、初回・リピート・SR がどの日も 0。** アプリは対象計 0 を「データなし」にする（0% にしない）ので、今の LaLa の表示は「データなし」で正しい。
- 0 の理由はまだ分からない：LaLa の Toast に初回・リピートを押すもの（商品・ボタン）が無いか、hyper-worker が LaLa の分を見つけていない。`db/lala-repeat-check-2.sql`（読むだけ・1 つの表）で、ToriTon と LaLa の出数の表から来店区分らしい名前の商品・モディファイヤーを並べる。1 つ目（店舗の Toast の店）の結果も、この SQL に入れた（Supabase の画面は最後の結果だけを出すため）。
- 直し方（候補）：LaLa の Toast に ToriTon と同じ記録の仕方を入れる（店の運用）か、LaLa の記録の仕方に合わせて hyper-worker を直す（ソースが要る）。どちらでもアプリの計算は変えない。
