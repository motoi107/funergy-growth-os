# 新しいログインの試し（v1183・段階 1）：招待の URL ＋ PIN で端末を登録し、次から PIN なしで入る

依頼：Moto さん 11/14 夜の添付（ログイン・本人確認）→ UI案80 → 答え（11/14：B・名前を先に出す・GM／CEO はチャットの操作なしのロックを止める・スタッフは PIN＋LINE／テキストで送る 1 回だけの URL（48 時間）・試すのは GM・CEO が名前で選んだ人（D）・「まず社員に限定して試したい」／11/14 21:52 HST：GM・CEO は管理者セキュアページと同じメールとパスワード・PIN が要るところは今までどおり）。11/16 15:01 HST「ログインの手順と関数ください」。

入れる一式：`deploy/device-login-v1183/`（① 最初に確認 → ② SQL → ③ 確認 → ④ 関数 `device-login`（非公開の 1 ファイル）→ マージ → 端末を 1183 に → GM・CEO が人を選んで招待）。

## 1. この段階でできること

- GM・CEO が **従業員マスター ›「ログインの試し」**（メール認証）で、試す人を名前で選び、**招待のリンク**を作る（48 時間・1 回だけ・作り直すと前のリンクは使えない）。LINE・テキスト・コピーで本人に送る。
- 本人がリンクを開くと、名前を確かめて **自分の PIN** を入れ、その端末を登録する。PIN は今のサーバー（auth-pin）が確かめる（続けて間違えると auth-pin が止める・招待は 5 回間違えると使えなくなる）。
- 登録した端末では、次から開くだけで入れる（PIN なし）。入ったときの印は PIN のログインと同じ形なので、ほかの関数はそのまま動く。
- PIN を聞くとき：30 日開かなかった・この端末でログアウトした・本人が「開くたびに PIN」にした・経理（役割 office）の人はいつも。
- 端末は 1 人 5 台まで・90 日まで。本人はマイページ「この端末のログイン（試し）」で端末の一覧・外す・すべての端末からログアウト・「開くたびに PIN」。GM・CEO は「ログインの試し」で端末を外す・試しから外す。
- 試す人も、いつもの PIN のログインは今までどおり使える。ほかの人には何も変わらない（ログイン画面の下に「招待のリンクで登録」が 1 行増えるだけ）。

## 2. 守り（サーバー）

- **端末の鍵**：登録のとき端末で ECDSA P-256 の鍵を作る（取り出せない鍵・IndexedDB）。サーバーには公開鍵だけ。入るときはサーバーが出した 1 回だけの確かめの値（2 分）に端末が署名する。署名する文には「何をするか」（入る・ログアウト・端末を外す・設定）を含めるので、ほかの操作に使い回せない。確かめの値は 1 端末 10 分に 30 回まで。
- 招待の値はサーバーに **sha-256 だけ**置く。端末には招待の値・PIN・印・鍵の中身を残さない（localStorage には端末の番号と名前だけ）。
- 選べるのは在籍のスタッフだけ。**GM・CEO は選べない**（社員の表の役割・中身の役割・manager_auth のどれかが ceo・gm なら断る＝段階 2）。
- **PIN が初期のまま（0000）の人は登録できない**（auth-pin が印を出さない人）。
- 退職・止めた人は、登録も入ることもできない（入るたびに社員の表を確かめる）。
- GM・CEO の操作はメールのログイン（Supabase Auth）と manager_auth の役割（ceo・gm）。アプリが送る名前・役割は使わない。
- 表 5 つ（`dl_trial`・`dl_invites`・`dl_devices`・`dl_challenges`・`dl_events`）・関数 25（`dl_*`・security invoker・サーバーの鍵だけ）。公開の鍵では読めない・書けない。記録（`dl_events`）は 180 日（PIN・招待の値・印・鍵の中身は残さない）。

## 3. Claude が決めたこと（Moto さんに伝える・違えば直す）

- 段階 1 はスタッフだけ。GM・CEO（メールとパスワード）・共有の端末・新しい端末の知らせ・大事な操作の確かめ直し・**チャットの「操作がないとロック」を GM・CEO で止める**のは段階 2。
- 店のスタッフは、入ると所属の店で入る（応援の店は選ばない）。ほかの店で使うときは、いつもの PIN のログインで。
- この新しいログインで入った人がマイページの時給を見るときは、PIN を 1 回だけ聞く（給与の見込みは PIN の確かめで出しているため）。割引の記録も同じ。
- 端末の名前は端末の種類から付ける（「iPhone」など・本人が登録の画面で直せる）。
- 招待のリンクは画面を閉じるともう出せない（サーバーに値を置かないため）。
- 外した端末・止めた人は、今入っている画面も次に確かめたとき（開いたとき・画面に戻ったとき）ログアウトする。それまでに渡した印（12 時間）はほかの関数が使えるが、ほかの関数は今までどおり退職・止めた人を断る。

## 4. アプリ（v1183）

- `FUNERGY_DL`（index.html の別の `<script>`）：招待の画面（段階を上・主のボタンを下に固定・PC は 2 列）・登録・自動で入る・PIN の確かめ直し・ログアウト・マイページのカード・GM・CEO の「ログインの試し」（人を足す・招待・作り直す・取り消す・端末・外す）。
- 起動の最後に、登録した端末なら自動で入る（`_dlBootWhenReady`）。関数が無い（404）・SQL がまだのときは「まだサーバーで使えるようになっていません」と出し、いつもの PIN のログイン。
- ログアウト（2 か所）で `FUNERGY_DL.onLogout()`（この端末を「次は PIN」にする）。
- 日本語・英語。390px・1280px で横にはみ出さない。

## 5. 関数（Edge Function `device-login`）

- リポジトリの `supabase/functions/device-login/index.ts` は印を作る部品が無い（`signMark: null`）→ 入る・登録は 503 `sign_missing`。本番に貼るのは **非公開の 1 ファイル**（handler ＋ PIN のログインと同じ印を作る部品・Moto さんに直接渡す・リポジトリに置かない）。
- Secrets は足さない（auth-pin と同じ鍵）。Verify JWT は OFF。
- 呼べるのは `https://funergy-plus.com`（と `DL_ALLOWED_ORIGINS`）から。

## 8. 限界

- iPhone の Safari とホーム画面のアプリは別の入れ物。ホーム画面のアプリで使う人は、リンクをコピーしてアプリの「招待のリンクで登録」に貼る。
- 鍵は端末のブラウザの中（IndexedDB）。ブラウザのデータを消すと使えなくなる（いつもの PIN で入れる・GM・CEO がもう一度招待する）。端末で悪いスクリプトが動けば、取り出せなくても鍵は使える（HttpOnly のクッキーは独自ドメインが無いので使わない）。
- 招待のリンクを転送されると、PIN を知っている人なら使える（1 回だけ・48 時間・名前を出す・PIN が要る・GM・CEO の一覧に出る・外せる、で抑える）。
- 試す人も、いつもの PIN のログインは止めていない（PIN だけで入る道は残る）。
