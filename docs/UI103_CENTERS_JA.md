## 現状の問題（見つけたこと）

予実管理
- 客数の KPI は、前日までの実績を**月全体の計画**と比べている（`budKpiCard` の guestBudget＝plan.month.guests）。月の途中はほぼ赤になる。
- 実績が無い日（未取り込み・取り込み失敗）は「—」だが、予算は累計の分母に入っている。定休の 0 と未入力・未取り込みの区別が一覧で弱い。
- Toast の範囲取り込みの失敗は画面のメモリだけ（`_rgLastFailed`）。開き直すと失敗の日が分からない。
- タブ名の期間がそろっていない（「日次進捗」の中身は月の累計と日別）。年間計画だけ青・橙。
- Quarterly：「Q目標まで あと」の「客数 +N人/日」は `qcFillWays` の byGuest＝残り全額÷客単価÷残り日数（1 日に要る客数の合計）。**追加の人数に読めるので言葉の確認が要る**（計算は変えない・下の「確かめたい点」）。残り日数は定休も数える暦日。

ワークセンター
- 「今日」タブの中身（申請・チャットのタイル、前の承認待ち、エラー検知、承認のクイックリスト、重要エラー）が各タブと重なる。
- 「DM・チャット」がナビの小タブと中のタブの 2 か所。アナウンスは別の場所。
- 申請の詳細はモーダル。PC で一覧を見ながら詳細と操作ができない。

経理センター
- 経理ホームは本日の勤怠のカードが上で大きい。締め項目・出力・取り込みの状態がばらばら。
- 経理レビューの中タブ 10 個（確認する・レシート・建て替え・チェック・紛失届・ガソリン代・休暇申請・事前経費・区分・承認・報告・承認）。
- インボイス取り込み：段階（提出フォルダ → 取り込み・読み取り → 判定 → QuickBooks → 照合）の数が「取込状況」に隠れている。

## 推奨の画面構成（モックの内容）

- 予実管理：上に Daily/Monthly・Quarterly・Annual・予算設定・施策分析。期間の帯「2026年 › Q4 › 11月」と店。
  - Daily/Monthly：① 現在地（前日までの累計とペース・時点・実績の無い日の注記）② KPI カード（押すと計算・内訳・判定の決まり・時点）③ 確かめることの件数（未達・未取り込み・取り込み失敗・不整合の疑い・未入力・注意。定休は数えない）と「要確認の日だけ」④ 日次一覧（見出しと日付を固定・集計の行は上に分けて）⑤ 右に日の詳細（理由と確かめること）⑥ ランチ・ディナーはたたむ。
  - Quarterly：約束（Qコミット）→ 行動（重点項目のメモ）→ 結果（前の四半期と比べた数字）→ 残り。行動と結果は別に出す。「記録なし」は未実施と言わない。
  - Annual：12 か月の帯（確定・進行中・予定・予算開始前）を四半期ごとに。差の大きい月。押すと詳細と Daily/Monthly・Quarterly へ。見込みは出さない。
- ワークセンター：申請・承認（最初）・通知とチャット・自動チェック・業務Bot。「今日」タブは無し。
  - 申請・承認（PC）：左＝ビューと絞り込み／中央＝一覧（☐ でまとめて承認・帯で件数と精算の対象額）／右＝詳細（段階と担当・中身・領収書・重複の候補・履歴）と下の操作の帯。却下は離して置き、理由が要る。まとめて承認は確かめの画面 → 処理中 → 結果（一部できないときは理由と開き直し）。
  - スマホは 1 件ずつ（まとめて承認は PC）。
- 経理センター：経理ホーム（あなたの作業の一覧・11月の締め・出力・取り込みの状態・本日の勤怠は小さく右）／経理レビュー（左の状態と種類・中央の一覧・右の証憑と段階と操作）／インボイス取り込み（段階の帯と数・エラーと要確認の理由と次の対応・今すぐやり直す → 処理中 → 結果）。

## 状態の見せ方（色＋記号＋短い言葉）

- 途中（累計）：✓ 順調（白地・緑の線）／! ペース不足（黄）／! 遅れ（白地・赤の線、90% 未満）。月の途中で「未達」と言わない。
- 終わり：✓ 達成（緑）／▼ 未達（90% 以上は黄・未満は赤＝今の決まりの幅のまま）。
- データ：— 判定なし・✎ 未入力・☁︎ 未取り込み（グレーの点線）／⚠︎ 取り込み失敗（ピンク）／? 不整合の疑い（紫・自動チェックが見つけた食い違い。原因が分かるまで「エラー」と言わない）／暫定（タグ）／定休（0 は正常）。
- 処理：● あなたの対応（青）／○ 待ち（青い線）／↩ 差し戻し（オレンジ）／⋯ 処理中（灰）／✓ 完了（緑）。

判定の決まり：売上 100%／90%（`statusFromPct`）、客単価 目標／95%、原価率・人件費率 目標／＋3pt、ドリンク比率 目標／90%、総労働時間 目標以下、リピート率 データが無ければ判定しない — どれも今の決まり。新しいのは客数の「前日までの計画」（提案上の仮ルール）と、Quarterly のディナー売上などを 1 営業日あたりで比べる案（提案上の仮ルール）だけ。

## 作らないもの（決定 8：今回は UI の改善だけ）

- Qコミットの「期限・次にやること・できた／まだ」・上司の確認 → 今は行動の記録の欄に書く。
- 日ごとの取り込み失敗の保存 → 今は「Toast から取り込む」を実行した端末で、画面を開いているあいだだけ「取り込み失敗」と出す。開き直すと「未取り込み」。
- 通知をだれが読んだか・通知への返信 → 今は自分の既読だけ。
- 申請・承認の件数をサーバーで数える → 今は読み込んだ分を画面で数える。
- インボイスの原本を画面の中で見る → 今は新しいタブで開く（申請の領収書の画像のリンクだけ小さく出す）。
- 年間の見込み → 出さない。

## 変えないこと

計算・承認の段・権限・保存先・通知・取り込みの処理・ログイン・Supabase の設定・CORS・JWT の検証。画面に無い数・工程・進捗率（%）は作らない。

## 確かめたい点（実装の前に）

1. Quarterly の「客数 +N人/日」：言葉だけ「客数だけで埋めるなら 1 日 N 人（今の客単価）」に直してよいか（計算はそのまま）。
2. 客数の仮ルール（前日までの計画）を正式な決まりにするか、仮のまま「仮ルール」と画面に出すか。
3. 期間の終わりの言葉：注意の幅（90〜99%）を終わったあとは「▼ 未達（黄）」と言う（色の幅は今のまま）でよいか。

## 実装に進むとき（案）

UI だけの変更を小さく分ける：① 予実の名前・帯・色（Daily/Monthly・Quarterly・Annual）② Daily/Monthly の確かめることと日の詳細 ③ Quarterly の 4 つの欄 ④ Annual の帯 ⑤ ワークセンター（今日タブを外す・通知とチャット・申請・承認の 3 列）⑥ 経理ホーム・経理レビューの 1 つの一覧・インボイス取り込みの段階の帯。それぞれ e2e で今の操作（承認・確認・やり直し）が同じ関数を呼ぶことを確かめる。
