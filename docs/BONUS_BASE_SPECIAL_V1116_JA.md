# ボーナスの「無条件で基準額」と個人別の特別報酬（v1116）

Moto さん 10/29 18:42 HST の添付「ボーナスの基準額支給と個人別特別報酬の追加」。選択肢への回答（10/29）：基準額支給は「原資から先に取る」・特別報酬は「原資の中から払う」。

土台はボーナスの締め v1109（`docs/BONUS_CLOSE_V1109_JA.md`）と、特例でのグレード変更 v1115（PR #105・この PR はその上）。入れ方は `deploy/bonus-close-base-special-v1116/手順.md`。

入れるもの：サーバー（表 `bc_quarters` に列 `pay` を 1 つ・関数 7 つを足し 5 つを置き換え）・Edge Function `bonus-close`・アプリ（index.html・sw.js 1116）。

## 1. 何ができるか

| | 中身 | だれ |
|---|---|---|
| 無条件で基準額 | 評価をしていなくても、その人の基準額（グレード・日割り）をそのまま「通常賞与額」にする。行の札は「基準額支給」。「通常の評価計算に戻す」で元の計算に戻る | ボーナスの締めを書ける人（今は GM・CEO） |
| 特別報酬 | 通常賞与額に足す額（$1 単位・0 以上の整数）と理由・メモ（任意）。0 か「特別報酬を消す」で消える | CEO・GM だけ（サーバーが役職で確かめる） |

- 最終支給額 ＝ 通常賞与額 ＋ 特別報酬。
- 評価の点数・係数・評価の状態・Career Score は書き換えない（「無条件で基準額」にしても、ダミーの評価・点は作らない）。戻すと前と同じ係数・額になる。
- 基準額が無い（グレードの基準額が未設定）人は「基準額未設定」と出して、四半期の締めを止める（$0 やほかの値で埋めない）。
- 変えられるのは、まだ版が無いとき（作成中）と「修正を開始」のあいだだけ（v1109 の「未確定の部分に使う値」と同じ）。仮締め・確定の版は書き換えない。

## 2. 計算（Moto さんの回答どおり）

- F ＝ 「無条件で基準額」の人の基準額の合計（原資から先に取る。原資の調整で減らさない）。
- R ＝ max(0, 支給上限 − F)（支給上限 ＝ 通常原資 ＋ 特別原資）。評価で決まる人（調整前の合計 Se）は、今までどおり k ＝ min(1, R ÷ Se) で同じ割合（$1 単位・端数の配り方も v1109 と同じ）。
- 特別報酬（合計 SP）はその上に足す。**特別報酬のためにほかの人の額は減らさない**（指示書 4）。
- 合計が原資を超えても、指定した額（基準額支給・特別報酬）は減らさず、不足額を出す。不足額 ＝ max(0, 調整前の合計 ＋ SP − 支給上限)。「不足分を補う」で特別原資に足せる（v1099）。
- 基準額支給も特別報酬も無い四半期は、v1109 と 1 セントも同じ（アプリ・サーバーとも試験で確かめる）。

計算の例（合成の会社）：
- G2 の人（基準額 $1,000）を「無条件で基準額」＋ 特別報酬 $200 → 通常賞与額 $1,000・最終支給額 **$1,200**。ほかの人の額は変わらない。
- 原資 $20,000、G6 の人（$12,000）を「無条件で基準額」、別の人に特別報酬 $9,000、評価で決まる人の調整前の合計 $22,750 → G6 の人は $12,000 のまま、評価で決まる人は残りの $8,000 を ×0.352 で分け、特別報酬 $9,000 は減らさない → 最終支給総額 $29,000（原資を $9,000 超える）。不足額（だれも減らさずに払うのに足りない額）＝ $34,750 ＋ $9,000 − $20,000 ＝ $23,750。「不足分を補う」で特別原資に足すと全員が調整前の額になる。
- 本物のアプリ（合成の 57 名・原資 $20,000）：G2 の人を「無条件で基準額」（$1,000）、G4 の人に特別報酬 $200 → 評価で決まる 56 名は残りの $19,000 を ×0.133 で分け、G4 の人は $634 ＋ $200 ＝ $834、最終支給総額 $20,200。
- 原資 $9,000 で G6 の人（$12,000）を「無条件で基準額」→ その人は $12,000、評価で決まる人は $0（画面に注意を出す）。

## 3. 画面（成長カルテ › 査定一覧の上の「ボーナスの締め」）

- 一覧の列：支給方式・調整前・通常賞与額・特別報酬・最終支給額。行のボタン「無条件で基準額」／「通常の評価計算に戻す」・「特別報酬」。
- 合計：通常賞与合計・特別報酬合計・最終支給総額（見込み）・利用可能な原資（支給の上限）・不足額。
- 「無条件で基準額」の確認の画面：前後の通常賞与額・評価はそのまま残ること・理由（任意）。
- 特別報酬の画面：基準額（日割り）・支給方式・通常賞与額（見込み）・今の特別報酬・最終支給額（見込み）・金額・理由。小数・文字・マイナスは送る前に断る。
- 「支給方式・特別報酬の履歴」：操作した人・日時・前後の支給方式と額・理由（特別報酬は前後の額と前後の理由）。「修正をやめる」で戻したときも記録（pay_reset）。
- 個人ページ・計算の内訳・説明・本人に見せる表示：基準額支給・特別報酬を出す。本人に見せる表示には特別報酬の理由は出さない。
- 一覧にいない人（退職など）に基準額支給・特別報酬が残っていたら、締めの欄の「一覧にいない人」で外すまで保存を止める（黙って落とさない）。

## 4. 保存と記録（サーバー）

- `bc_quarters.pay`（四半期 × 従業員）：`b`（基準額支給）・`bAt`・`bBy`・`sp`・`why`・`at`・`by`・`nm`。書くたびに `rev` を進める（ほかの端末と同時に変えたら conflict・何も書かない）。
- 新しい操作：`pay_mode`（mode＝base／normal・GM・CEO）・`sp_save`（CEO・GM だけ。役職そのもので確かめる）。記録は `bc_events`（pay_mode・sp・pay_reset）。
- 版（仮締め・再確定）は、その四半期の基準額支給と特別報酬（理由も）をそのまま持っていなければ保存しない（`bc_pay_match`・`pay_mismatch`）。1115 以前の端末の保存は断られる（入っているものを落とさない）。
- 版の確かめ（`bc_snap_check`）：最終支給額 ＝ 通常賞与額 ＋ 特別報酬・基準額支給の人は通常賞与額 ＝ 基準額・評価で決まる人の合計 ＝ min(Se, floor(R))・人ごとに floor(調整前 × R ÷ Se) か $1 多い・F・SP の合計。
- 「修正を開始」「修正をやめる」は、その版の基準額支給・特別報酬に戻す（`bc_pay_from_snap`）。
- 確定の写し（アプリの `bonus_q.evSnap`）には支給方式・特別報酬の額を入れ、理由は入れない（「（理由はサーバーの版）」）。給与・ボーナス履歴には最終支給額（通常賞与額と特別報酬の内訳つき）。
- 支払・控除・給与・QuickBooks への送信はしない。評価・Career Score・賞与の設定・予算・売上は書き換えない。

## 6. 限界・残したこと

- 本番のデータ・実機（iPhone）では確かめていない。
- 「無条件で基準額」は四半期全体（グレードが途中で変わった人は区間ごとの基準額の日割りの合計）。区間の一部だけを基準額にはできない。
- 特別報酬の理由は確定の写し（共有データ）に入れないので、ほかの画面ではサーバーの版を見る（締めの欄）。
- 1115 以前の端末は、基準額支給・特別報酬のある四半期を保存できない（端末を 1116 にそろえる）。
