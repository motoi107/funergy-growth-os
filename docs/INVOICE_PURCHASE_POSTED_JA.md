# 仕入れタブに経理確認済みの invoice が入らない件（2026-10-29・アプリ v1112・migration 20261029100000）

## 1. 依頼と決定

- 依頼（Moto さん 10/29・添付）：「予実管理 ＞ 仕入れ」で、経理確認済みの invoice が仕入額・原価に反映されない。原因を推測で断定せずデータと処理箇所で裏付け、直し、反映されていない分を戻し、確かめる。
  守ること：経理確認の流れとファイル名の自動変更はそのまま／安定した識別子で結ぶ（名前の変更で失わない）／名前と確認状態が食い違うものを勝手に確認済みにしない／
  取り直し・作り直しで二重に数えない（訂正・確認の取り消しは今までの決まりで）／失敗を 0 件・0 ドルにしない／**この修復を理由に外部の会計へ送らない・送り直さない**／
  月は請求日・納品日の今の決まり／仕入額と棚卸のあとの原価を分ける／費目・税・値引き・返品・クレジットは今の決まり／手入力や別の経路と二重にしない／
  **予算・売上は変えない**／戻す前の状態を残す・分からない店や月を推測で埋めない・締めた月は今の決まり／関係のない大きな変更や画面の変更はしない。
- 決めたこと（Moto さん 10/29・選択肢の回答）：
  1. 経理確認済み＝**人が反映したもの**（Invoice取込の「この内容で反映する」・まとめて反映）。自動で反映したものは照合済みになってから。照合は今までどおり別の作業として残る。
  2. QuickBooks へ送ったかは **条件から外す**（経理確認済みなら原価に入れる。送ったかどうかは仕入れタブに別に出す。送り直しはしない）。

## 2. 原因（10/29 08:15 HST、本番を読むだけの SQL `db/invoice-purchase-trace-check.sql` で確かめた）

- 集計（`invoice_purchase_month`・20261019090000 から）は「経理の照合済み（`recon_status='reconciled'`）かつ QuickBooks へ送った記録あり（台帳の前の原本は照合済みだけ）」だけを確認済み（A）に数えていた。
- 経理の確認は Invoice取込の反映（`invoice_post`・人なら `posted_mode='manual'`）で、ファイル名の自動変更（v1071）もそこで起きる。照合（`invoice_reconcile`）は別の作業で、10 月は全店でほとんど進んでいなかった。
  → 人が反映した invoice のほとんどが「確認待ち（C・理由 unreconciled）」のまま、原価（`foodCostOf` は 10 月から A の原価対象だけ）に入らなかった。
- QuickBooks の台帳は送られていた（送信済みが大半。順番待ち・結果不明が少し）。集計の書き出し（5 分ごと）も動いていて、アプリが読む集計はサーバーと同じだった。
  名前の変更・識別子（invoice は doc id・原本は Drive の file id と sha256 で結ぶ。名前では結ばない）にも問題は無かった。
- 店ごとの件数・金額は公開リポジトリには書かない（Moto さんに直接）。

## 4. 守ったこと

- 二重に数えない：区分が C → A に移るだけ。アプリは 10 月から Drive の写しを数えず A の原価対象を足す（v1077 から変わらない）。作り直しは同じ中身なら書かない（試験）。
  アプリの登録と同じかもしれない invoice は照合まで入れない。開始前の Drive の invoice は今までどおりアプリの登録で数える（推測で足さない）。
- 訂正：反映済みを直すと照合は未照合に戻る（前から）。人が反映したものは確認済みのまま（直した値で）、自動で反映したものは照合まで待つ。照合を取り消しても、人が反映したものは確認済み。
- QuickBooks：台帳・送信の関数は変えていない。試験で台帳の行が 1 行も増えない・変わらないことを確かめた。
- 締めた月：集計の作り直しは今までの決まり（その月の invoice が変わったときだけ）。決まりを変えただけでは前のまま。
- 予算・売上・棚卸・食材移動の計算は触っていない。
