## 2. 何をするか

反映（人の「この内容で反映する」・まとめて反映・自動反映）→ 名前を変える（今までどおり）→ 台帳に積む（`invoice_qb_enqueue`・コミット）→ **その場で送り始める**（`EdgeRuntime.waitUntil`。画面への答えは待たない・画面を閉じても続く）。5 分ごとの取込も、待っている分を送る（始めの合図が消えた・やり直しの分）。

1 行ずつ（予約できた行だけ）：

1. **予約**：`invoice_qb_reserve`（送る担当が「このシステム」の行・やり直し 5 回未満・skip locked）。予約するのは、**いまの送る担当が「このシステム」で、Gmail の接続が「つながっています」のときだけ**（`invoice_qb_has_due`）。そうでなければ予約しない（行は待つ・やり直しの回数は使わない）。15 分を過ぎた「送信中」は `invoice_qb_sweep` が「結果不明」にする（今までどおり）。
2. **設定を読み直す**：`invoice_qb_send_context`（台帳 ON・送る担当・宛先・送り始め（`qb.since`）・反映済み・中身が台帳と同じ・名前を変え終わった・Gmail の接続・送り元の Gmail が `qb.from` と同じ）。だめなら送らない。送る担当が戻った・接続がだめになったときは、行を放す（`invoice_qb_release`：待ちに戻す・回数は数えない）。
3. **Gmail の送信済みを調べる**（全部のページ・ごみ箱に移したものも）：`in:sent "FPQB-SHA256-<SHA-256>"` と `in:sent "FPQB-ID-<Drive の ID>"`（印を丸ごと。前の転送と同じ検索で、Gmail が印をハイフンで分けても分けなくても見つかる。宛先は検索に入れず、1 通ずつ確かめる。前の形の件名も同じ検索で出る）。SENT の印・宛先（To）・件名の SHA の印・添付が 1 つでサイズが同じ、のメールがあれば送らずに「送信済み」（そのメールの ID・「前の転送で送った」または「この台帳の送信を見つけた」）。同じ Drive の ID で別の中身・添付を確かめられないものは「結果不明」（人が確かめる）。**調べられなかったら「送っていない」とはみなさない**（エラー）。
4. **原本の中身**：Drive から読み、SHA-256 が台帳と違えば送らない（`content_changed`：台帳の行は取り消し・ファイルは確かめ直し・知らせ）。
5. **送る直前**：`invoice_qb_send_check`（予約がまだ自分のもの・予約から 13 分以内・行と原本と設定が読んだときのまま）。
6. **1 通送る**：送り元の Gmail（`users.messages.send`。3 MB を超える原本はアップロードの口）。multipart/mixed で**原本の添付 1 つだけ**（本文・署名・CC・BCC なし）。添付名は今の名前、型は原本のまま。件名は `今の名前 FPQB-ID-<Drive の ID> FPQB-SHA256-<sha> FPQB-ATTEMPT-<attempt_key>`。
7. **記録**：Gmail の ID で「送信済み」（`result`：via gmail・送信開始と送信済みの時刻・きっかけ（post／auto／correction／worker））。記録できなければ 3 回まで書き直す。それでも書けなければ行は「送信中」のまま → 15 分で「結果不明」→ 下の照らし合わせで Gmail の ID を見つけて「送信済み」（送り直さない）。

送った結果：
- 5xx・時間切れ・ID が返らない → **結果不明**（自動では送り直さない）。15 分後から 15・30・60…分あけて 6 回まで Gmail の送信済みを調べ、見つかれば「送信済み」。見つからなければ人が「Gmail の送信済みを調べる」→「もう一度送る」（前からある「確かめて、もう一度送る」「送信済みにする（確かめた）」・経理・事務Crew・GM・CEO）。
- 4xx（429・403 の混み具合（rate limit）を含む）→ エラー。今までの待ち時間で 5 回までやり直す（回数は戻さない）。5 回で止まったら知らせる。
- 許可が切れた・取り消された・足りない（401・混み具合でない 403。送信でも送信済みの読み取りでも）→ その行は放す（**回数は使わない**）、Gmail の接続を「切れた」（401）か「許可が足りない」（403）にし、**予約をやめる**（行は待つ）。CEO・GM が「確かめる」で直っていれば（または「つなぎ直す」と）、待っている分から送る。
- 人が「確かめて、もう一度送る」と、結果不明の行は**もう 1 回だけ**送れる（5 回を使い切っていた行も。それ以上は増やさない）。

## 3. Gmail の接続（3A）

- Invoice取込 → 設定 → Gmail の接続（CEO・GM）。「Gmail をつなぐ」→ Google の画面（OAuth・PKCE・`gmail.send` と `gmail.readonly` だけ・送り元のメールをログインのヒントに）→ 関数の GET に戻る → アプリへ。
- つなぐときの印（state）はハッシュだけを DB に置き、10 分・1 回だけ。別のアカウント・許可が足りない・取り消した・期限切れ・印の使い回しはつながない（何も保存しない）。
- 覚えるのは更新の鍵（refresh token）だけで、DB の service role しか読めない表（`invoice_gmail_auth`）。画面・記録（invoice_events）・ログ・app_state には出さない。
- 送り元（`qb.from`）は SQL で 1 回だけ決める（画面からは変えられない・ひな形 `db/invoice-qb-sender.sql`）。つながるのは送り元と同じアカウントだけ。
- 送る担当を「このシステム」にできるのは、送り元の Gmail が 2 つの許可でつながり、**つないだあとに「確かめる」を押して通り**、台帳に送った原本があれば**それを送信済みに見つけられたとき**だけ（`gmail_not_ready`）。切り替えた時刻を `qb.route_since` に残す（知らせの起点）。
- 「確かめる」：新しい鍵・許可・アカウント・送信済みの検索に加えて、台帳でいちばん新しい送った原本（前の転送のものから）を、送る前と同じ検索で送信済みに探す（「送った原本を見つける」）。見つからなければ切り替えない（Claude に）。本物のメールで検索を確かめるため。
- 許可が切れた・足りないと出たあと、Google 側で直したら「確かめる」で「つながっています」に戻る（自分では戻らない）。
- 「切る」は覚えた鍵を消すだけ。**Google 側で許可を取り消す呼び出しはしない**（Drive の取込と同じ OAuth クライアント・同じアカウントのとき、Drive の取込まで止めないため）。
- OAuth クライアントは Edge Function の Secrets（`GMAIL_OAUTH_CLIENT_ID`・`GMAIL_OAUTH_CLIENT_SECRET`）か、無ければ Drive の取込のもの（`invoice_drive_credentials`）。戻り先は `https://<Project URL>/functions/v1/invoice-intake`（`GMAIL_OAUTH_REDIRECT_URI` で変えられる）。

## 4. 前の転送（ChatGPT）との切り替え（6A）

- 台帳の 1 行は送る担当が 1 つ（積んだときの `qb.route`）。このシステムは「このシステム」の行しか予約せず、ChatGPT（`qb_external_reserve`）は前の転送の行しか予約できない（このシステムの行は 409）。**同じ原本を両方が予約・送信することはない**ので、ChatGPT の 1 時間ごとのタスクを先に止めなくてよい（仕様の「新しい送信経路の準備・認証確認より前に停止しない」とも合う）。
- 切り替える前に積んだ行は ChatGPT が送り終える。0 になったら ChatGPT のタスクは「見るだけ」（新しい外部の口 `qb_external_monitor`：今の鍵で、台帳の数・止まっているもの・30 分以上待っているものを読むだけ）。
- 送る前にこのシステムも Gmail の送信済み（前の転送の印・前の形の件名も）を調べるので、前の転送が送った原本は送り直さない。
- このシステムが送るのは、送る担当が「このシステム」のあいだだけ。担当を前の転送に戻すと、このシステムの行で待っているものは送らない（ChatGPT も予約できない）。取込状況に「待ち」として残り、また「このシステム」にすると送る。
- 仕様の C は「既存台帳 API（qb_external_*）」と書いているが、このシステムの送信は同じ関数（invoice-intake）の中で動くので、HTTP の口ではなく、その口と同じ台帳の関数（`invoice_qb_reserve`・`invoice_qb_result`・`invoice_qb_sweep`）を使う。新しい鍵は作らない・Moto さんに鍵を貼ってもらわない。台帳の表を外から直接書き換えない。

## 9. 限界・確かめていないこと

- 本物の Gmail・Google の同意画面・OAuth クライアントの設定・LINE には接続していない（すべて偽物）。実際の送信の速さ（反映から送信済みまでの秒数）は測っていない。入れたあと 1 件で確かめる（手順.md の 8）。
- Intuit の受付・取込のエラーは見ていない（メールはブロック中）。QuickBooks に入ったかは QuickBooks で。
- Gmail の送信には冪等のキーが無い。二重送信を防ぐのは台帳の予約（1 行 1 送り手）と送る前の送信済みの検索で、件名の印だけではない。送信の答えが来ないまま実は送れていた場合は「結果不明」になり、送信済みで見つかるまで人が判断する。
- Google の「テスト中」の同意画面では許可が 7 日で切れる（手順.md）。許可が切れたあいだは送らない（行は待つ）。
- 知らせのメールは許可が切れていると送れない（アプリと LINE で知らせる）。
- 1 回に送るのは 20 行・100 秒まで（取込の中では、ファイルと名前の変更のあとの残りの時間だけ。残りは次の取込で）。1 行は残りが 20 秒以上のときだけ予約する。
- 中身が変わって取り消した行（原本の差し替わり）と同じ中身に原本が戻っても、同じ台帳の印は使えないので自動では積まない（ふつうは新しい中身を確かめて反映し直すので起きない。起きたら Claude に）。
- Drive から原本を読むときの時間の上限は今までの取込と同じ（このシステムの Gmail と Google の呼び出しは、答えの本文まで時間の上限の中）。
- 送り手が ChatGPT のときに台帳に積んだ行は、切り替えたあとも ChatGPT の担当のまま（6A）。
