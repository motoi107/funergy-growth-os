## 1. 決まり（UI案69 の答え）

| 番号 | 答え | 作り |
|---|---|---|
| 3A | だれでも DM・グループを作れる | 在籍の社員（G1 から）ならだれとでも DM（1 組に 1 つ）・グループ（自分のほか 1〜49 人）。店のタブレット（店舗の PIN）は使えない（だれが書いたか分からない） |
| 4A | 申請のチャットは関係する人が自動で入る | 申請した人・その申請を決める人・確かめる人（`wr_visible` で見られる人のうち決める段の人）が「自動」で入る。ほかの人は参加者か GM・CEO が加える。自動で入った人は、その申請を見られなくなったら読めない。加えられた人は読める |
| 5A | 24 時間まで直せる・消せる・GM・CEO は見えなくできる | 本人は送ってから 24 時間まで直せる（「編集済み」）・いつでも消せる（「削除されました」・本文は消す）。GM・CEO はほかの人のメッセージを理由つきで見えなくできる・元に戻せる（本文はサーバーに残す・画面には出さない） |
| 6A | 添付 | 次の段階（写真・PDF）。v1156 は文字だけ |
| 7A | 知らせはアプリの中だけ | 数（未読）と自分宛ての @。LINE には送らない |

ほかに UI案69 で決めた形：

- Ctrl（Mac は ⌘）＋ Enter で送る。Enter は改行。日本語の変換中の Enter では送らない。
- 参加者にいない人を @ すると「参加者に加えて、これまでの会話を見せますか？」（見せる／見せない／やめる）。加えてから @ を付ける。
- 送れなかったメッセージに「もう一度送る」「消す」。同じメッセージがサーバーで 2 つにならない（送信ごとの鍵 `client_key`・送り直しは同じ鍵）。
- 自分のメッセージに「既読 N」。

## 2. サーバー

- SQL `supabase/migrations/20261121090000_chat.sql`（先にワークセンターの申請の段階 2＝v1155 の SQL。無ければ何も変えずに STOP。2 回流しても同じ）。
- 表：`chat_threads`（会話・種類 dm／group／case・版）・`chat_members`（参加者・自動か・既読の番号・加わったときの番号）・`chat_messages`（本文・@・鍵・編集・削除・見えなくした人と理由）・`chat_sig`（「変わった」の合図）・`chat_sig_owner`（社員 ID → 印）。番号 `chat_chg_seq`。
- どの表も RLS ON・公開の鍵（anon・authenticated）では読めない・書けない。**例外は `chat_sig`**：ランダムな印・回数・時刻だけで、公開の鍵で読める（Realtime のため）。社員 ID・本文・会話は無い。印は本人だけが知る（`chat_sync` の答えでだけ返す）。
- 関数 `chat_*` 36 個（どれも security invoker・サーバーの鍵だけ）。だれかは `wr_actor`（関数 work-requests が PIN の印で確かめた社員 ID）。
- 決まりの数（`chat_limits`）：本文 2,000 字・グループ名 60 字・参加者 50 人まで・直せるのは 24 時間・1 回に 100 件・見えなくする理由 200 字。
- `chat_row` の申請のチャットは申請の id・番号・種類・状態・店を返す（チャットから申請に戻るため）。
- 関数 work-requests：`chat_` の 15 の頼み（sync・messages・mentions・people・open_dm・create_group・case・send・edit・delete・hide・read・add・remove（自分なら抜ける）・rename）。whoami は `fn: 5` と `chat`（SQL が入っていれば 1）。SQL がまだなら `chat_missing`（503）。
- 本番に貼る関数は非公開の 1 ファイル `work-requests_v1156_index.ts`（handler.mjs ＋ PIN の確かめ＋起動の行・Moto さんに直接）。v1155 の中身にチャットを足したもの（申請は今までどおり）。

## 3. アプリ（v1156）

- 開き方：G1（Crew）はメニューの「チャット」。店長・AM・GM・CEO・経理・事務Crew・Head Chef はワークセンターの「DM・チャット」タブ（メニューの「DM・チャット」でも同じ）。申請の詳しい画面に「この申請のチャット」。
- 画面：PC は 左に会話の一覧（すべて・DM・グループ・申請・@ 自分宛て・未読）＋右に会話。スマホ（820px 以下）は一覧 → 会話（戻るボタン）。広い PC は 1280px まで。
- 「今日」タブにチャットのカード（未読・自分宛ての @）。メニューの数（未読）。
- **この端末には何も残さない**：本文・参加者・既読はサーバーだけ。書きかけ・送れなかったメッセージはこのタブのメモリだけ（ログアウト・読み込み直しで消える）。共通データ・localStorage・IndexedDB には書かない（試験で確かめる）。
- ログアウトで全部捨てる（世代 `C.gen` を進め、遅れて届いた前の人の答えは使わない）。
- 「変わった」の合図：`chat_sig` の自分の印を Realtime で見る（合図が来たら 0.3 秒後に変わった会話だけ読む）。つながらないときは 60 秒ごと、会話を開いているときは 20 秒ごと。5 分ごと（裏にいるときは 15 分ごと）に全部読み直す。変わった会話は前の番号から 200 さかのぼって読む（番号を取った順と書き終えた順が前後しても拾う）。
- 既読はチャットの画面が見えていて、その会話を開いているときだけ・前へだけ進める。
- 文字は文字として描く（HTML は動かない）。リンクは http・https だけ。@ の名前は強調。
- 申請のチャット：申請を見られる人でも、自動で入る人でなければ「この申請のチャットには入っていません（申請した人・決める人・確かめる人が開くと始まります。GM・CEO が加えられます）」。

## 5. 限界

- 添付（写真・PDF）はまだ（6A は次の段階）。
- 書きかけ・送れなかったメッセージはこのタブだけ（読み込み直し・ログアウトで消える）。端末に残さないための決まり。
- 「既読 N」は相手が会話を開いたときに進む。こちらの画面の数は次の同期（合図・20 秒・60 秒）で変わる。
- 合図の表 `chat_sig` は公開の鍵で読める（印・回数・時刻だけ）。印を知らなければだれの合図か分からない。
- 知らせはアプリの中だけ。アプリを開いていない人には届かない（7A）。
- 申請のチャットに自動で入る人は、その申請を決める段の人。段階 2 の承認の順（AM → GM）が変わると、次に開いたときに入れ替わる。
- 実機（iPhone・日本語入力・Realtime）・本番のデータでは確かめていない。
