## 3. アプリ（v1156）

- 開き方：G1（Crew）はメニューの「チャット」。店長・AM・GM・CEO・経理・事務Crew・Head Chef はワークセンターの「DM・チャット」タブ（メニューの「DM・チャット」でも同じ）。申請の詳しい画面に「この申請のチャット」。
- 画面：PC は 左に会話の一覧（すべて・DM・グループ・申請・@ 自分宛て・未読）＋右に会話。スマホ（820px 以下）は一覧 → 会話（戻るボタン）。広い PC は 1280px まで。
- 「今日」タブにチャットのカード（未読・自分宛ての @）。メニューの数（未読）。
- **この端末には何も残さない**：本文・参加者・既読はサーバーだけ。書きかけ・送れなかったメッセージはこのタブのメモリだけ（ログアウト・読み込み直しで消える）。共通データ・localStorage・IndexedDB には書かない（試験で確かめる）。
- ログアウトで全部捨てる（世代 `C.gen` を進め、遅れて届いた前の人の答えは使わない）。
- 「変わった」の合図：`chat_sig` の自分の印を Realtime で見る（合図が来たら 0.3 秒後に変わった会話だけ読む）。つながらないときは 60 秒ごと、会話を開いているときは 20 秒ごと。5 分ごと（裏にいるときは 15 分ごと）に全部読み直す。変わった会話は前の番号から 200 さかのぼって読む（番号を取った順と書き終えた順が前後しても拾う）。
- 既読はチャットの画面が見えていて、その会話を開いているときだけ・前へだけ進める。
- 文字は文字として描く（HTML は動かない）。リンクは http・https だけ。@ の名前は強調。
- 申請のチャット：申請を見られる人でも、自動で入る人でなければ「この申請のチャットには入っていません（申請した人・決める人・確かめる人が開くと始まります。GM・CEO が加えられます）」。

## 5. 限界

- 添付（写真・PDF）はまだ（6A は次の段階）。
- 書きかけ・送れなかったメッセージはこのタブだけ（読み込み直し・ログアウトで消える）。端末に残さないための決まり。
- 「既読 N」は相手が会話を開いたときに進む。こちらの画面の数は次の同期（合図・20 秒・60 秒）で変わる。
- 合図の表 `chat_sig` は公開の鍵で読める（印・回数・時刻だけ）。印を知らなければだれの合図か分からない。
- 知らせはアプリの中だけ。アプリを開いていない人には届かない（7A）。
- 申請のチャットに自動で入る人は、その申請を決める段の人。段階 2 の承認の順（AM → GM）が変わると、次に開いたときに入れ替わる。
- 実機（iPhone・日本語入力・Realtime）・本番のデータでは確かめていない。

## 6. v1156 の直し（アプリ v1158・同じ SQL の置き換え）：Codex #150 の P2 2 つ

PR #150 は Moto さんが 11/13 19:19 HST にマージした（main `bf9df59`）。マージの前に Codex（issuecomment 6869797305・`7250686`／6870029872・`95f9ff9`）が blocked・P2 2 を出していた。チャットの SQL・関数（`deploy/chat-v1156/` の ①〜④）は本番にまだ入れていない。

- **P2-1（SQL）**：`chat_add` が加え直すとき `history_from = least(前, 新)` だったので、外した人・自分で抜けた人を「これまでの会話を見せない」で加え直しても、抜けていたあいだ（と前）の会話が読めた。
  - 直し：新しく加える人・外された／抜けた人を加え直すときは、**いま選んだ範囲**（見せない＝次の番号から・見せる＝初めから）。小さいほうを取らない。
  - いまいる人を加えても何も変わらない（範囲は狭まらない）。
  - 申請のチャットに自動で入っていて、いまも申請を見られる人を加えると、読める範囲は今のまま（加えた人になる）。申請を見られなくなっていた自動の人は、いま選んだ範囲から。
  - SQL `20261121090000` の `chat_add` 1 つの置き換え（入れる一式の ② も同じ・試験で 1 文字も違わないことを確かめる）。③ に 10 行目（直しが入っているか）。前の ② を流していたら 10 が NG → 今の ② をもう一度流す。
- **P2-2（アプリ）**：開いている会話の読み直しが最新の 100 件だけで、写しに足すだけだった。そのため、それより前のページで見えなくした・直した・消したことが、もう開いている端末に届かなかった。
  - 直し：最新のページは、その範囲の写しを**置き換える**（届かなかったもの＝読めなくなったものは消す）。
  - 前に読んだページも 100 件ずつ取り直す（4 ページ＝最新と合わせて 500 件まで）。それより前・取り直せなかったページの写しは捨てる（「さらに読む」でサーバーから取り直す）。
  - 閉じていたあいだに会話が変わっていたら（`chg` が違う）、開くときに前の写しを出さない（見えなくした本文を一瞬でも出さない）。変わっていなければ前の写しをすぐ出し、裏で読み直す。
  - 一覧から消えた会話（`gone`）の写しも捨てる。
- 試験（合成データ）：
  - chat-server 9（足した 1：外す → 送る → 見せないで加え直す（Codex の順番）・自分で抜けた人・見せるで加え直す・いる人・申請の自動の人 2 通り。前の SQL では落ちる）。

    - 捨てたときの「さらに読む」の印：取り直したページがもう「前がある」と言っている。

## 7. PR #152 のレビューの直し（アプリ v1158 のまま・SQL は変えない）

Codex（issuecomment 6872721025・`9a54c3a`・blocked）の P2：会話の写しを捨てた（閉じていたあいだに変わっていたので開くときに捨てた＝`freshCache`）あとに、その前に頼んだページの答えが遅れて届くと、捨てる前の本文（見えなくしたもの）を戻して出していた。次の最新のページも読めないと、そのまま「読めた」扱いで残った。

- 直し：会話ごとに写しの世代 `ep` を持つ。`freshCache` で世代を進め、読み込みのとちゅうなら読み直しを予約する（`again`）。最新のページ・前のページ（`refreshBelow`）・「さらに読む」の答えは、頼んだときの世代と違えば使わない（成功・失敗とも）。読み直しが失敗したら、写しは空のまま「もう一度」を出す（前の本文を出さない）。
- 試験（合成データ）：chat-app 15（足した 2：前のページの遅れた答え（Codex の順番そのもの：答えはサーバーが隠す前に作る → 隠す → 一覧の同期 → 閉じて開く → 遅れた答え → 最新は 503）・最新のページの遅れた答え（次の読み込みも 503）。どちらも `9a54c3a` の index.html では落ちる）。わざと壊す 3 通り（最新のページの世代の確かめ・前のページの世代の確かめ・世代を進めない）すべてで落ちる。
