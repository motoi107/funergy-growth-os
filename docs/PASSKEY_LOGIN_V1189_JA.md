# v1189 パスキーとメールのコードでログイン（ログインの段階 3・UI案92）

入れる一式：`deploy/passkey-login-v1189/`（手順.md）。SQL：`supabase/migrations/20261208090000_passkey_login.sql`。関数：device-login（`handler.mjs`・`mail.mjs`）。アプリ：`FUNERGY_PK`（index.html の別の `<script>`）。

## 決まったこと（Moto さん 11/17 12:38 HST・UI案92 の答え）

1. A：Supabase Auth のパスキー（ベータ）を使う。
2. A：ログインの方式（PIN ↔ メール＋パスキー）とメールを変えるのは **GM だけ**。
3. 送り手（招待とコードのメール）は **GM の会社のメール**（Gmail API）。**アドレスはリポジトリに書かない**（SQL の `dl_mail.from_addr` に、Moto さんが `4_送り手_SQL.sql` で入れる）。
4. A：招待は 7 日。
5. B：自分の端末は **12 時間ログインしたまま**（開くたびにパスキーを聞かない）。GM が止められる。
6. A：GM・CEO・経理はメールとパスワードのまま（パスキーも本人がマイページで足せる）。
7. A：v1183 の「ログインの試し」はやめる。
8. A：ログインの画面の一番上に「パスキーでログイン」。メール＋パスキーの人には PIN の段を出さない。
9. A：店の共有の端末にはパスキーを残さない（自分の電話で QR を読む・メールのコード）。
10. A：ログインが先。このあと (b) RLS の 1 段目。

## 流れ

1. GM：PIN の一覧 →「ログインの方式」→ その人の「メール＋パスキーにする」→ メールを入れ、「本人に伝えた」にチェック → 招待のメール（7 日）が届く。**この時から、その人は PIN では入れない**（PIN の値は消さない）。
2. 本人：メールのリンクを開く → 名前と、送り先（伏せたメール）を確かめる →「コードを送る」→ 6 桁のコード（10 分）→「自分だけが使う端末」なら「この端末にパスキーを保存」も選べる → ログイン。
3. 次から：
   - 自分の端末：開くとそのまま入る（12 時間）。過ぎたら一番上の「パスキーでログイン」（指紋・顔）。
   - ほかの端末・共有の端末：「パスキーでログイン」→ ブラウザが出す QR を自分の電話で読む。または名前を選んで「登録したメールにコードを送る」。共有の端末ではログインを残さない・パスキーを保存しない。
   - PIN が要るところ（割引の記録など）は、今までの PIN を聞くことがある（PIN の値は残っている）。
4. GM・CEO・経理：今までどおりメールとパスワード。マイページで自分のパスキーを足すと、一番上の「パスキーでログイン」でも入れる（ログインしたままにはならない・UI案90 の答えのまま開くたびに入れる）。

## サーバー

- 表（サーバーの鍵だけ・RLS ON）：`dl_people`（人ごとの方式・メール・確かめた時刻・版）・`dl_pk_invites`（招待・7 日）・`dl_pk_codes`（コード・10 分・5 回まで間違えてよい・60 秒あけて・1 時間に 5 回まで）・`dl_pk_sessions`（ログインのあいだ・12 時間）・`dl_mail`（送り手）。招待・コード・ログインのあいだの値は **sha-256 だけ**（値そのものは残さない）。
- メールの確かめが済んだ人だけ Supabase Auth の利用者を関数が作る（パスワードなし・`app_metadata.fdl = 'pk'`）。GM・CEO・経理・業務Bot のメールと同じなら作らない（`email_taken`）。失効・PIN に戻す・メールを変えると、関数がその利用者を消す（パスキーもログインもすべて消える）。
- パスキーで入ると、端末は Supabase のログイン（Bearer）で `pk_login` を頼む。スタッフはその場で関数が「ログインのあいだ」を作り、印（PIN のログインと同じ形）を出す。アプリは Supabase のログインをすぐ閉じる。GM・CEO・経理は v1185 の `email_login` と同じ道。
- PIN の照合（auth-pin）：`dl_pin_blocked` が「メール＋パスキーの人」を止める（社員の ID が当たればその人だけ・無ければ在籍で同じ名前の人）。auth-pin v1186 は止めた人に `use_email` を返す → アプリはパスキーとメールのコードの段へ。
- 送り手：GM が「Google でつなぐ」（Gmail の `gmail.send`・`openid`・`email`）。つないだアカウントが `from_addr` と違えば保存しない。トークンは `dl_mail` にだけ（サーバーの鍵だけ）。
- `login_info` は `pk:true` と、メール＋パスキーの人の社員の ID（名前・メールは出さない）を返す。
- v1183 の「ログインの試し」：SQL が招待と端末を止め、試す人を空にして、スイッチ `trial_off`。アプリは入口・マイページのカードを出さず、端末に残った鍵を消す。

## アプリ v1189（`FUNERGY_PK`）

- 端末に残すのは 2 つだけ：`_pk_sess_v1`（ログインのあいだの値・社員の ID・名前・期限。**自分の端末を選んだときだけ** localStorage、ほかはメモリ）と `_pk_own_v1`（自分の端末か。初めは電話なら「自分の端末」、PC は「共有」）。印・Supabase のログイン・メールは残さない。
- 入ると PIN のログインと同じ道（`finishStaffLogin`）。30 分ごと・画面に戻ったときに印を取り替える。GM が止めた・退職：その場でログアウト。
- ログアウト：サーバーのログインのあいだも終える（12 時間を待たない）。
- 組み込み：名前を選んだとき（`loginPickPerson`）・PIN の段（`doStaffLogin` の `use_email`）・戻る（2 か所）・場所を選んだとき・ログアウト（2 か所）・起動（`_dlBootWhenReady`）・ログインの画面の言葉・マイページ（パスキーの一覧・足す・消す・ログインしたまま）・PIN の一覧（GM の「ログインの方式」）。
- サーバーが前の版（関数・SQL）なら、パスキーの入口を出さず、今までどおり PIN。

## Claude が決めたこと（Moto さんに確かめる）

- GM・CEO・経理はパスキーで入っても**ログインしたままにしない**（UI案90 の 3「開くたびに入れる」のまま）。
- 「自分の端末」の初めの値は端末の種類で決める（電話＝自分・PC＝共有）。本人がチェックで変えられる。
- メール＋パスキーの人も、PIN が要るところ（割引の記録・チャットの「続ける」）では前の PIN を使う。
- 一番上の「パスキーでログイン」は、場所・名前を選ぶ段で出す（PIN・メールの段では出さない）。
- 「メール＋パスキーにする」は GM だけ（CEO も GM と同じにするなら 1 行）。GM・CEO・経理（manager_auth の人）には使えない（メールとパスワードのまま）。

## 限界

- Supabase のパスキーはベータ。設定（RP ID・許可する origin）を間違えるとパスキーは使えない（メールのコードでは入れる）。
- QR（ほかの端末）は、電話の Bluetooth と、その端末のブラウザがパスキーの QR に対応していることが要る。
- 送り手は Gmail の 1 日の上限（Workspace で 2,000 通）・迷惑メールに入ることがある。送り手のつなぎが切れると招待もコードも送れない（GM の画面に出る）。
- メール＋パスキーの人のメールは `dl_people` にある（サーバーの鍵だけ・リポジトリには無い）。
- v1188 以前のアプリの端末：メール＋パスキーの人は PIN で入れない（auth-pin が `use_email` → 前のアプリはメールとパスワードの段を出すが、その人のアカウントは無い）。**全部の端末を 1189 にしてから**「メール＋パスキーにする」。
- 本番に貼る関数は、リポジトリの handler・mail に非公開の「印の部品」（v1183 から）を足した 1 ファイル。Claude が作って直接渡す（リポジトリの `index.ts` の印は `sign_missing`）。
- P3（記録だけ）：メール＋パスキーの人のマイページにも「ログインの PIN」のカードが出る（PIN は割引などで使うので消していない。言葉を変えるなら UI 案から）。
