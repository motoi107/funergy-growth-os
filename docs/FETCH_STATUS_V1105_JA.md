# 売上・予算・勤怠の「取得の状態」の帯（アプリ v1105・UI案60 ① 1A・2A）

依頼：Moto さん 10/21 18:49 HST の添付の ①（ログインのときの「売上・予算の最新情報を取得できない」）。v1104 で原因（保護が止まる）を直したうえで、UI案60 の回答 1 A（ダッシュボード・予実・会議に、対象ごとの「最終取得」・取れなかったら「前回の情報を表示中」と［もう一度］・ログインの知らせは出さない）と 2 A（ログインの画面では今までどおり Toast の売上の保存を待つ）。

## 1. 何を出すか

- ダッシュボード・予実（予実管理・会議・仕入れ・人件費・KPI 管理・日次・月次）の上の帯：**売上**・**予算**・**勤怠** ごとに
  - 取れた：`売上 19:42 取得`（ハワイ時間。端末がハワイ以外なら `HST` を付ける。今日でなければ日付も）。店が複数なら、いちばん古く取れた店の時刻。
  - まだの店がある：`売上 19:42 取得 · まだ：LaLa`
  - 取れなかった：`売上：取れませんでした（LaLa）。前回 18:10 の情報を表示中［売上をもう一度］`（前に取れたことが無ければ「前の情報もありません」）。
  - まだ一度も取れていない：`売上：まだ取れていません［もう一度］`
  - 自動のやり直しで新しく取れた：`新しい情報を取りました：表示を更新`（押すと描き直す。勝手に描き直さない＝入力中の画面を消さない）。
  - 未送信の保存があれば「未送信 N」。［最新情報を取得］（今までの同期）・［診断］はそのまま。
- 前の「同期 ◯分前」「最終同期 ◯分前」（予実・会議・仕入れの見出しの下）は、この帯に置き換えた（チップ管理の「最終同期」はそのまま）。
- ログインの直後の知らせ「売上・予算の最新データを確認できません…」（v1101〜v1104）は出さない。代わりに帯に出す。

## 2. 何をもって「取れた」とするか

- 売上：Toast の売上（`toast_sales`）を店ごとに読めたか（`syncStoreActualsFromToast`）と、売上・予算の保護（v1101）が確かめる売上・日報の記録を読めたか。
- 予算：保護が確かめる予算の記録を読めたか（起動のとき・［最新情報を取得］・［予算をもう一度］で `FUNERGY_FINANCIAL_SAVE.refresh`）。保護の無い入れ方では出さない。
- 勤怠：Toast の勤怠（`tip_labor`）を店ごとに読めたか（`fetchTipLaborFromDB`）。
- 「取得」の時刻はこの端末で通信が通って答えを読めた時刻。Toast の取り込み（夜の自動の取り込み）がいつのものかは分からないので出さない。
- 記録はこの端末だけ（`_fetch_status_v1`・同期しない）。

## 3. 取れなかったとき

- Toast の売上を読めなかったら（HTTP の失敗・通信なし・答えが配列でない）、空の行として扱わず何も書かない（前は空として扱い、同じ値を書き直していた）。印 `_err` で「行が無い」と分ける。前の月の取り込みで読めなかったときは、その月を「済み」（凍結）にしない。
- 自動のやり直し：3 回まで（15 秒・30 秒・60 秒）。画面が見えていない・通信が無いあいだは回数を使わずに待つ。自動では取れなかった店だけを読む（まだ一度も読んでいない店は読みにいかない）。そのあとは押したときだけ。押したときは、取れなかった店とまだの店を読んで描き直す。

## 4. 試験（`tests/fetch-status-v1105.test.mjs`・合成データ）

読めない 3 通りで書かない・0 と出さない／まだ・一部・全部・失敗（前回の時刻）の出し方／保護の記録が読めないと売上と予算の両方／自動のやり直しの回数と間隔・見えないあいだ・押したとき／自動で取れたら「表示を更新」・まだの店は読まない／勤怠・帯を出す画面／ハワイ時間／起動の知らせが無いこと・前の「最終同期」を外したこと。
