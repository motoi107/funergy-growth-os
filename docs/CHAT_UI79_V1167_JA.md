## 2. Claude が決めたこと（Moto さんに伝える・違えば直す）

- **申請のチャットがあることだけは、申請を見られる人に伝える**：参加していない人が「この申請のチャット」を押すと「参加者だけが開けます（管理する人に加えてもらってください）」。会話の名前・人数・中身は出さない（そうしないと、2 つ目のチャットを作ろうとしてしまうため）。
- **管理する人**：グループ・申請のチャットを作った人が最初の管理する人。人を加える・外す・名前を変える・管理する人を決めるのは管理する人だけ。管理する人が 1 人だけなら、その人は「管理を外す」ができない。管理する人がいなくなったら（抜けた・外された）、作った人、いなければいちばん前から入っている人がなる。だれでも自分で抜けられる（申請のチャットも）。DM には管理する人はいない。
- **前からある会話の移し替え**：前の版で自動で入っていた人は、**いまその申請を見られる人だけ残し、ほかは外す**（前の版で「参加者の一覧には出るが読めない」だった人）。だれも今より多くは読めない。前の SQL を流し直して自動の行が残っても、確かめるまで読めない。
- **加えても申請そのものは見られるようにならない**：会話の上の申請の番号・状態（ref）は、その申請を見られる人にだけ出す。
- **@ で参加者でない人を出すのは管理する人だけ**（加えられる人だけ）。
- **ロックはチャットだけ**（アプリ全体ではない）。端末の種類（店の共有 PC／自分の端末）はチャットの一覧の上の盾のボタン（「チャットの守り（この端末）」）で選ぶ。初めは、タッチのスマホなら自分の端末・ほかは共有 PC。選んだ種類はこのタブのメモリだけ（ログインし直すと初めに戻る）。
- **ロックを続ける**：店の共有 PC はログインの PIN（サーバーの auth-pin が確かめる・続けて間違えると止まる）、自分の端末は「続ける」だけ（個人のチャットの暗証番号は v1168）。ロック中に「別の人に替わる」でログアウト。
- **知らせ**：ロック中も、あなた宛ての @ でも「新着メッセージがあります」だけ。右下のボタンは数だけ。

## 9. E2EE（エンドツーエンド暗号化）の案（今回は入れない＝6A）

**今回の守り**：読めるかはサーバー（関数 work-requests と SQL）が、ログインした本人と参加者かで決める。表は公開の鍵では読めない・書けない。写真は非公開の置き場所と 5 分のリンク。ただし**データベース・バックアップの管理者（Supabase の管理画面・サーバーの鍵を持つ人）は本文・写真を読める**。

**E2EE にすると**：参加者の端末だけが鍵を持ち、サーバーには暗号にした本文・写真だけを置く。データベース・バックアップの管理者も読めない。代わりに：

| 影響 | 中身 |
|---|---|
| 複数の端末 | 端末ごとに鍵。新しい端末は、ほかの自分の端末で許可（QR など）するか、鍵の控え（パスフレーズ）で入れる。会話の鍵を参加者の端末ごとに渡し直す |
| 端末をなくした | 鍵の控えが無ければ、その端末だけにあった鍵の前の会話は読めなくなる。会社として取り戻す道は作れない（作るとその道が管理者の入口になる） |
| 履歴の検索 | サーバーで検索できない。端末で開いた分だけ端末の中で検索 |
| 前の会話の移し替え | 今の会話はサーバーに読める形で残っている。移すには参加者の端末が暗号にし直し、サーバーの元を消す。バックアップに残った前の分は、バックアップが入れ替わるまで残る |
| 添付 | 端末で暗号にしてから上げる → サーバーは中身の確かめ（名前だけ変えたファイルを断る＝v1161）ができない。小さい写真も端末で作る |
