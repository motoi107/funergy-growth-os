## 1. 前（コードで確かめた・総点検の P1）

- 合流の決まり（`OP_MERGE`・`OP_MERGE_PREFIX`）の無い app_state の行と、app_settings の設定は、保存のたびに**端末の値を丸ごと**送っていた（`syncMasterToSupabase` → `supaUpsert`）。
  - app_state：会議・議事録・食材移動・シフトの設定（区分・人数・役割）・店の休み・食材マスター v2 と通し番号・会計 PL の設定・Tip の時間の設定・研修など約 40 のキーと、`inv_` で始まる一部。
  - app_settings：KPI・店のポジション・目標・Tip の決まり・勤務の条件・スキルの決まり・評価の段階・グレードの軸・非表示の画面など約 30 のキー。
- 古い写しの端末の保存・送れなかった変更の送り直し（`flushOutbox`）は、そのあいだにほかの端末が足した・直した・消した分（別の店・別の記録）を消していた。
- 取り込みは、送れていない手元の変更があると「手元を丸ごと残す」か「クラウドで丸ごと置き換える」のどちらか（v1136 の `_pullKeepLocal`）で、片方の変更が消えた。

## 2. いま

### 2-1. 直す前の値を覚える

- 保存（`lsSet`）で中身が変わったとき、まだ覚えていなければ、直す前の値（この端末が最後にクラウドから受け取った・送った値）を `whole_base_v1/<キー>` に覚える（`wbOnEdit`）。
  - この端末だけ（`isLocalOnlyKey`。送らない・受け取らない・同期の対象の外）。
  - もう覚えていれば、送れるまでそのまま（2 回目の保存で上書きしない）。
  - **そのキーに送れていない変更があるとき（v1148 以前の送信待ち・直す前の値を覚えていない送信待ち・送っている途中）は覚えない**（6 の直し）。手元の値にはその変更が入っているので、それを直す前の値にすると「この端末では変えていない」と読み、クラウドの値に戻してしまう。送れるまでは今までどおり丸ごと送り、送れたあとの最初の保存で覚える。
  - 起動・取り込みの途中の保存（`_supaBooting`。すぐには送らない＝前から）でも覚える（6 の直し）。取り込みがその行をクラウドの値で置き換えたら、直す前の値も外れる（2-3）。
  - 端末の保存（IndexedDB）を読み終える前の保存（`_idbState==='init'`）は、直す前の値を確かめられないので覚えず、そのキーに印（`_wbUnk`・この起動のあいだだけ）を付け、丸ごと送れるまで覚えない。印は、丸ごと送れて端末の値が送った値のままのとき・重ねて送れて端末に残りが無いときに外す。
- 送れたら忘れる。取り込みのときに送るものが無ければ忘れる。

### 2-2. 送るとき（`wbPush`・`syncMasterToSupabase` の中）

- クラウドの今の行を読み、3 つ（直す前・手元・クラウド）を比べて、**この端末で変えた所だけ**をクラウドの最新に重ねて書く。
- app_state：読んだ行が変わっていないときだけ書く（`_opCasWrite`・cas）。ほかの端末が先に書いたら、少し待って読み直し、重ね直す（6 回まで）。
- app_settings：表に「読んだ行が変わっていないときだけ書く」が無いので、書いたあと読み直し、書いた値と違えば読み直して重ね直す（4 回まで）。
- 重ねた結果がクラウドと同じなら書かない（ほかの人の変更を戻さない・行の時刻を進めない）。
- クラウドを読めない・書けないときは書かず、送信待ちに残す（理由は「設定 › 診断と記録」）。直す前の値も残る。
- 送っているあいだにこの端末でまた直したら、その変更を書けた値に重ね、直す前の値を書けた値にする（次の送信で送る）。
- 直す前の値が無い（v1148 以前に送れなかった変更・覚える前の変更）ときは、**今までどおり丸ごと**送る。

### 2-3. 取り込むとき（`wbIncoming`）

- `_applyKvRows`（ログイン・「最新に更新」）・`pullOpKey`・`pullSettingKey`・`supaPullAllMasters` の設定の取り込みで使う。
- 送れていない手元の変更があれば、同じ重ね方で手元を作り直す（手元を丸ごと残す・丸ごと置き換える、ではなく）。端末に書けたら、直す前の値をクラウドの値にする（書けなければ前のまま）。
- 送っている途中なら手元を残す（v1136 と同じ）。
- 送るものが無いのに直す前の値が残っていれば忘れて、今までどおりクラウドの値を取る。

### 2-4. 重ね方（`wbMerge3`）

- 入れ物（`{…}`）は欄ごと。
- id のそろった記録の並び（どの記録にも文字か数の id があり、重ならない `[{id:…},…]`）は id ごと。並びはクラウドの順、手元で足した記録は手元で前後にあった記録のそばに入れる。
- それ以外の並び・数・文字・真偽は 1 つの値。
- 両方が同じ所を違う値にしたら、新しく直したほう（手元の最後の保存の時刻 `_pend_edit_at` と、クラウドの行の時刻。どちらも端末の時計）。分からないとき（設定の表には行の時刻が無い）は手元（前と同じ）。
- 片方が消し、片方が直した所は、直した値を残す。
- 両方が同じ id の記録を新しく作ったら、その記録は丸ごと 1 つ（欄を混ぜない）。
- 食材マスター v2 の通し番号（`ing_v2_seq`）は大きいほう（番号を戻さない）。
- 両方が同じ所を直していたら「設定 › 診断と記録」に 1 行（どのキーの、どの所か・どちらを残したか。中身は出さない）。

### 2-5. 対象の外（今までどおり）

- 合流の決まりのあるキー（`OP_MERGE`・`OP_MERGE_PREFIX`・`sl_manual_`。`dailyops_template_<店>` も `dailyops_` の決まりがある）。
- 関数 secure-state で読み書きするキー（v1139〜v1148）。
- 分けた行（`spl_…`）・分けて保存するキー（`_SPLIT_KEYS`）。
- マスターの表（`m_stores` などの rows）・この端末だけのキー。

## 4. 限界

- 設定（app_settings）は「読んだ行が変わっていないときだけ書く」ができないので、2 台がほぼ同時に書くと、読み直す前のごく短いあいだに片方の書き込みが消えうる（読み直して違えば重ね直すので、たいていは両方残る）。
- 同じ所を両方が直したときに残るのは、端末の時計で「新しく直したほう」。設定は行の時刻が無いので、いつも送った端末のほう。
- id の無い並び（文字の並びなど）・id が重なる並びは 1 つの値（片方の変更だけが残る）。
- 両方が同じ id の記録を新しく作ったら 1 つだけ残る。
- 直す前の値が無い変更（v1148 以前に送れなかった変更と、それが送れるまでのあいだの保存・端末の保存を読み終える前の保存・ほかのタブが同時に直したとき）は今までどおり丸ごと（そのとき、ほかの端末のあとの変更を消すことがあるのは前の版と同じ）。端末の保存を読み終える前の保存の印はこの起動のあいだだけなので、印を付けたあと送る前に開き直すと、次の保存はその変更を「変えていない」と読む（その変更はほかの所と同じくクラウドの値になる）。
- 共有の端末で、ほかの人の送れていない変更があるキーを今の人が直して送ると、その変更も今の人のログインで送られ、送信待ちから外れる（前の版の丸ごとの送信と同じ。v1149 で変わったことではない。Claude のルーティンのレビューの P3）。
- 同期センターの道具「この端末からアップロード」（確かめの画面で「ほかの端末で新しく変えたものが消えることがあります」と出るもの・クラウドが壊れたとき用）は今までどおり丸ごと書く。
- マスターの表（rows）の書き方と、ほかの端末で変わったことを知らせる合図は次の段（2c の 2 つ目）。
