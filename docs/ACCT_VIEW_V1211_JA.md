## 1. 原因（合成データで再現）

- 経理レビュー › 申請（GM 承認済みの申請・処理済み（今月））は、申請のサーバー（関数 work-requests）が「だれか」を `wr_actor` で決めて返す。
- `wr_actor` で事務Crew（office_crew）になるのは、**manager_auth に事務Crew のメールのアカウントがある人だけ**だった。
- PIN でログインする事務Crew は、GM・CEO が「経費の申請の権限」で「事務Crew と確かめる」（`wr_exp_grants.crew`・v1184）を押していても、**G1 のスタッフ**として返っていた。
  - 共通ルール（v1190）を使い始める前：経理レビュー › 申請が 0 件（自分の申請だけ）。
  - 使い始めたあと：閲覧者として一覧に出ても、「確認した」「差し戻す」「支払」が出なかった（経理の確認はサーバーが office・office_crew だけに許す）。
- 承認・閲覧の共通ルール（`ar_role_rows`・v1190）と経費の申請の権限（`wr_exp_base`・v1184）は、前から同じ確かめで事務Crew として数えていた。`wr_actor` だけが違っていた。
- 再現の試験：`tests/acct-view-v1211.test.mjs` の 1 つ目（直す前の SQL で、確かめた事務Crew の一覧が 0 件・ボタンなし）。

## 2. 直し（新しい権限は作らない・GM の役割にもしない）

サーバー（SQL `supabase/migrations/20261217090000_wr_actor_crew_grant.sql`・関数 2 つの置き換え）：

- `wr_actor`：次のすべてに当たる人を、事務Crew のメールのアカウントと同じ `office_crew` として返す（印 `src = 'crew_grant'`）。
  1. manager_auth のアカウントが無い。
  2. GM・CEO が確かめた AM・G3 以上の写し（`wr_people`）が無い（G2 以下の古い写しは確かめを使う）。
  3. 今も従業員マスターで事務Crew（`wr_exp_crew`＝役割 office_crew か、肩書き Office Crew／Office Staff）。
  4. GM・CEO が「事務Crew と確かめた」（`wr_exp_grants.crew = true`）。
- `wr_exp_base`：`src = 'crew_grant'` のときは確かめを読み直す（確かめを外した直後の変更の記録が正しくなるように）。
- 権限：どちらもサーバーの鍵（service_role）だけが呼べる（前の版と同じ。`create or replace` は前の権限を残し、念のため取り消し直す）。
- 2 回流しても同じ。前の SQL（v1184 の `wr_exp_grants`・v1135 の `wr_person_conf`）が無ければ何も変えずに STOP。

これで、確かめた PIN の事務Crew は、事務Crew のメールのアカウントの人と同じに：

- 経理レビュー › 申請の一覧・件数・金額・絞り込み・1 件の中身・承認の履歴・処理済み（今月）・まとめて確認。
- 申請に付けた領収書（チャットのファイル）を開く。
- 経理の確認（確認した・差し戻す・支払・精算・事前経費の実費を結ぶ）。

アプリ（v1211・index.html・sw.js）：

- ワークセンター › 休暇：経理・事務Crew（個人のログイン）は休暇を承認できない（`canApproveVacation`）。G4 の経理（Accounting Manager など）では管理の一覧が空のカードで出ていた。→ 経理・事務Crew には「全店の休暇（見るだけ）」（承認待ちと、これからの承認済み・GM と同じ範囲・ボタンなし）を出す（`vacAcctViewHtml`）。ほかの人の見え方は変えない。
- 申請の画面は変えていない（サーバーの答えが変わるので、v1210 の端末でも申請の一覧とボタンは出る）。

## 3. 変えないもの

- GM の役割にしない。GM・CEO だけのもの（給与・賞与・ほかの人の成長カルテ・ボーナスの計算・経理出力の給与の CSV）は今までどおり見られない（関数 secure-state の full は CEO・GM だけ）。
- **訂正（#218 の Codex の P2・11/24）**：前の版のこの行は「関数 secure-state は manager_auth だけを見る」と書いていたが誤り。secure-state も PIN の人の役割を work-requests の whoami（`wr_actor`）で決めるので、確かめた PIN の事務Crew は secure-state でもメールの事務Crew と同じ範囲になる（4 の下）。
- GM・CEO だけの操作（共通ルールの設定・代理・例外・まとめて承認など）は断る（試験 6）。
- 確かめていない事務Crew・肩書きを自分で書いただけの人（従業員マスターは公開の鍵でも書ける）・店のスタッフ・確かめを外された人・退職した人は変わらない。
- manager_auth のアカウントの人と、AM・G3 以上と確かめた写しのある人の決め方は変えない（試験 8）。
- Invoice取込（経理レビュー › 書類・照合・QuickBooks の状態）は今までどおりメールのアカウントで入る（v1059 から事務Crew のアカウントは経理と同じ）。

## 4. 広がること（Moto さんに伝える）

確かめた PIN の事務Crew は、事務Crew のメールのアカウントの人と同じになるので、次もできるようになる：

- 経費の申請を本部とすべての店舗で出せる（前から事務Crew のアカウントと同じ決まり）。
- 経理の確認（確認した・差し戻す・支払・結ぶ）。
- Google の評価・口コミ（v1209・#216）を全店で見られる（事務Crew は全店の決まり）。
- **関数 secure-state でも事務Crew のメールのアカウントと全く同じ範囲**（Moto さん 11/24「メールの事務Crewと全く同じ」で認めた・#218 の Codex（7134072683）が見つけた広がり）：全店の Tip と期間の確定・変更の記録・グレード履歴・全店の通知・生年月日のあるなし・カードの照合・本部の Career Score。GM・CEO だけのもの（給与・賞与・ほかの人の成長カルテ）は見えないまま。
- 戻るまでの時間：確かめを外す・従業員マスターで事務Crew でなくなる・退職・PIN の期限のどれも、申請（work-requests）は次の呼び出しから、**secure-state は最大 60 秒あと**（whoami の答えを 60 秒覚える）。確かめたときに広がるのも最大 60 秒あと。カードの照合は社員の表を毎回見るので、退職はすぐ止まる。

ほかに：

- 申請のチャットには自動では入らない（今までどおり、関係する人を選んで作る）。
- G1 の事務Crew に入れた確かめは、Office Crew Leader（G2）に上がったあと画面から外せない（前から・`wr_exp_base` が G2 以上を full にするため）。
- 前の SQL（`deploy/work-requests-v1131`・`v1131-v1132`・`v1131-v1133`・`v1135`、`deploy/three-fixes-v1184` の 2）をあとで流し直すと、`wr_actor`・`wr_exp_base` が前に戻る（③ の 1・2 が NG になる → ② をもう一度）。
