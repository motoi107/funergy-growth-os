# 引き継ぎ記録の書き方

作業ごとに `docs/handoff/<作業ID>.md` を 1 つ作ります（作業 ID はブランチ名の `claude/` より後ろ）。
個人の Claude・Team の Claude のどちらが続けても、このファイルと PR と GitHub のコードだけで再開できるように書きます。
手順そのもの（開始・交代・Codex）は `docs/DEV_WORKFLOW.md` にあり、ここには書きません。

## 決まり

- 交代する前に更新し、**ブランチの最後のコミット**にして push します（`docs/DEV_WORKFLOW.md` の 6）。
- 書くのはソフトウェアのことだけです。秘密の値・本番の数・人の名前・給与・非公開の関数の中身は書きません（非公開ファイルは名前と sha256 の先頭だけ）。
- 実行していない試験を「合格」、受け取っていないレビューを「レビュー済み」、説明しただけの設定を「済み」と書きません。分からないことは「未確認」と書きます。
- 作業が終わってマージされたら、要点を `docs/AI_SHARED_MEMORY_JA.md` の先頭に足し、このファイルは残します（消しません）。

## ひな形

```markdown
# <作業ID>：<短い題>

- 目的：
- 担当 Claude：個人 / Team（交代したら「個人 → Team（11/15 10:20 HST）」のように足す）
- ブランチ：claude/<作業ID>　PR：#<番号>（base main）
- 基準コミット（main）：<SHA>
- 保存済みコミット：<SHA>（この記録の 1 つ前のコミット）
- 状態：作業中 / レビュー待ち / Codex の指摘の修正中 / マージ待ち / マージ済み

## 変更内容
- （ここに書く）

## 未完了
- （ここに書く）

| 確かめたこと | コマンド・方法 | 結果 |

|  |  | 通った / 落ちた / 未実行 |

## Codex の判定と対応
| 判定の head | 判定 | 指摘 | 対応コミット | 状態 |

|  |  |  |  | 未対応 / 対応済み・再レビュー待ち / 解消を確認 |

## 本番反映
- アプリ：未マージ / マージ済み（<日時>・main <SHA>）
```
