## 2. 元データ

- 日ごとの分母・分子：`toast_sales` にある。
- 丼 × モディファイヤーの日ごとの数（商品名・ID）：`toast_item_modifier_sales`（v961）。10/17 の時点では Marujuu だけに行があった。Totoya にあるかは `db/totoya-upgrade-check.sql`（読むだけ）で確かめる。
- 注文番号・時刻・取消：どこにも保存していない。依頼の「その日の注文・伝票番号」を出すには、取り込み（hyper-worker）に注文ごとの行を保存する表を足す（お客様の情報は保存しない・同じ注文は 1 行）。前の日は取り込み直すと入る。
- 取消・返金・Void の扱いと名前の当て方（部分一致か）：hyper-worker の中にあり、アプリからは見えない。最新の hyper-worker のソース（非公開）で確かめる。

## 5. 決まったこと（Moto さん 11/14 20:14 HST）

- UI案81 の形で作る。
- アップグレード率の期間は**ハワイ時間の昨日まで**（味噌汁・茶漬けの 2 つの数だけ。いくらシャワー・丼数は今までどおり今日も入る。過去の月は変わらない）。
  KPI 設定・会議・ダッシュボードなど、`totoyaKpiCalc` を通るところはどれも同じになる。月の初日は「数なし」（0% にしない）。
- 読むだけの SQL `db/totoya-upgrade-check.sql` を渡した。最新の hyper-worker（v1160）のソースは非公開で受け取った（リポジトリに入れない）。

## 6. hyper-worker v1160 で確かめたこと（非公開のソースを読んだ）

- 数えるのは丼の商品（店の丼の設定の ID・カテゴリー）の品に付いたモディファイヤー。名前（小文字・前後の空白なし）に aosa → 分母だけ、そうでなく crab・today・udon・chazuke のどれか → 分母と分子。1 つの品に複数付けば全部数える。数＝品の数量（無ければ 1・会計を分けた 0.5 なども）。日の合計を四捨五入して保存。
- テイクアウトの丼も入る。取消の注文・会計・品は入らない。返金は分けていない（取消でなければ入る）。
- 注文ごとの行はどこにも保存していなかった（`toast_item_modifier_sales` は Marujuu だけ）。

## 7. 作ったもの（v1171）

- SQL `supabase/migrations/20261130090000_toast_upgrade_lines.sql`：
  - `toast_upgrade_lines`（モディファイヤー 1 つ 1 行：注文番号・会計の番号・時刻・ランチ／ディナー・テイクアウト・丼・モディファイヤー・種類・数・数えたか・取消の理由）。
  - `toast_upgrade_days`（その日の印：種類ごとの数・分母・分子・hyper-worker の版）。
  - どちらも公開の鍵は読むだけ（RLS・SELECT だけ）・書くのはサーバーの鍵（hyper-worker）。お客さんの情報は入れない。
  - 確かめ `db/toast-upgrade-lines-check.sql`（読むだけ）・戻す `db/toast-upgrade-lines-rollback.sql`。
- hyper-worker v1171（非公開の 1 ファイル・Moto さんに直接）：数え方は 1 文字も変えず、同じループで数えたものをそのまま行にする。取消の行は「対象外」として残す（削除された注文は書かない）。
  書く順：印を消す → 行を消す → 行を入れる（500 ずつ）→ 印を書く。途中で失敗しても売上の保存とその日の成功は変えない（答えに `upgradeLines`）。丼の商品が無い店は書かない。
- アプリ v1171（`FUNERGY_UP`）：
  - 重要 KPI のタイル（予実 › 日次進捗）：率（今までと同じ `keyKpiStats` の数・昨日まで）・目標・前週比 pt・「分子 X ÷ 分母 Y 件」・「内訳を見る ›」。
  - 内訳の画面：PC は 2 列（左：率・目標との差・式・味噌汁のアップグレード／茶漬け／合計・モディファイヤーごと・分母の内訳・前週比／右：日ごと・選んだ日の丼ごと・注文ごと）。スマホ（820px 以下）は「まとめ」「日別」のタブ。
  - 日の状態：数がある／店休／取り込めていない（売上 0 ではない）。種類ごとの数と注文は印のある日だけ。印の数が日次と違う日は使わず注意を出す。印の無い日は「明細はまだありません（取り込み直すと入る）」。
  - 前週比：直近 7 日（昨日まで）とその前の 7 日。店ごとに同じ曜日の対で、どちらかに数が無ければ両方外す（`wowStats` と同じ考え方）。率の差（pt）と相対（%）。
  - KPI 設定で手入力の数を使っている店は、タイルの率はその数、内訳は Toast の数と出す。
  - `misoSub` の言葉を直した（分子＝アップグレード・分母＝味噌汁・茶漬けの数）。
  - 何も書かない（読むだけ）。店の ID は画面の onclick に入れない（番号で渡す）。名前はエスケープする。
