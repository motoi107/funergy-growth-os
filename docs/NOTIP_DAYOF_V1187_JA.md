# v1187：No Tip を「その日の時点のシフト数」で決める

- 決定：Moto さん 10/18「No Tip はその日の時点のシフト数で決める」。PR #76 の `893e429` で一度入れたが、Codex（`82e7954`）の P2（端末に前の月の勤怠が無いと、No Tip を終えた人を $0 にする＝端末によって額が変わる）で `395b625` で外していた。
- いつから：Moto さん 11/17「**12/1 から**」（`TIP_NOTIP_DAYOF_START = '2026-12-01'`）。12/1 より前の日の配分は今までどおり（支払った期間の額を変えない）。
- 変えたのは index.html と sw.js（v1187）と試験だけ。SQL・Edge Function・保存の形は変えない。

## 1. 前（v1186 まで）

- 配分の No Tip は、その人の **今日の時点** の実シフト数（`workedShiftCount`）で決めていた。
- 数えるのは **その端末にある勤怠の写し**（`tip_labor_<店>_<日>`）だけ。前の月の勤怠を読んでいない端末では少なく数え、No Tip を終えた人を No Tip（$0）にした＝端末によって額が違う。
- 日付で決めていないので、No Tip の期間（店ごとのシフト数）を過ぎると、No Tip だった過ぎた日の配分にもその人が入った。

## 2. いま（12/1 の日から）

その日・その枠（ランチ・ディナー）の **前までに働いたシフト数** で決める（`tipNoTipOn`）。

- 数えるのは、初回勤務日（無ければ入社日）から **その日の前の日まで** と、ディナーのときは **その日のランチ**。
- 1 シフトの数え方は前と同じ（所属の店の勤怠・ランチとディナーで 1 つずつ・Tip の対象時間が 0 より大きい枠）。
- 例：No Tip が 3 シフトの店。11/20 ランチ・11/21 ディナーで 2 シフト働いた人は、12/5 のランチ（3 シフト目）が No Tip、12/5 のディナー（4 シフト目）から配分に入る。
- 決め方の順は今までどおり：Waikiki・80/90/100 の外の役職 → その日に初回勤務から 3 か月 → その日までに効く承認 → 初回勤務日が無い（従業員マスターの係数） → シフト数。どれも **その日** で見る。

### どの端末でも同じ額にする

- 数える勤怠は、このログインのあいだに **DB（tip_labor）から読めた日だけ**（メモリだけ・端末には残さない）。端末の写しは使わない。
- 初回勤務日からその日までを読めていなければ「まだ分からない」として、その店の勤怠を初回勤務日からその日まで DB から読む（1 店 1 回にまとめる）。
- 読めるまでの配分は **仮**（前の決め方＝今日の時点）で出し、印（pending）を付ける。読み終えたら画面を描き直す。
- 読み込みは、ログインの同期・月の読み込み・Toast から直接の取り込み（DB に書けたときだけ）でも記録する。Toast から取ったが DB に書けなかった勤怠は数えない（ほかの端末が持っていないため）。
- DB の行が 1,000 行（上限）に届いた読み込みは、途中までかもしれないので「読んだ」にしない。
- 読めなかったら 30 秒あけて、見ている画面がもう一度頼む。

### 仮のあいだにしないこと

- **確定しない**（`confirmTip`：知らせを出して止める）。
- **出力しない**：店ごとの Tip 一覧（CSV）・全店まとめ（CSV）・経理まとめ（Excel）・配分表の CSV。押したときは読み終えるまで待って（最大 20 秒 × 2 回）から計算し直す。それでも読めなければ止めて知らせる（仮の額を出さない）。
- 配分表の上に「No Tip を決めるための勤怠を読み込んでいます」と、対象の人の名前を出す。
- マイページのチップ見込みに「・確認中」、チップ内訳に「読み終えると額が変わることがあります」。

## 3. ほかに変わること

- 期間の配分に使った率（名前の横の「80%→90%」・CSV の Tip Rate 列・確定の記録の rates）は、**枠ごと** に数える（`_tipRateSlotUsed`）。No Tip を終えた日の「ランチは No Tip・ディナーは配分」でも、その日の率を数える。12/1 より前は両方の枠が同じ印なので前と同じ。
- チップ内訳（マイページ）の下の文：Store Leader の 50% の再分配があるかを正しく出す（前は `estimateMyTip` が印を返さず、いつも「日次配分がそのまま最終額です」だった。8/1 から再分配は無いので、出る文は同じ）。

## 4. 限界（前からのものを含む）

- 数えるのは **所属の店** の勤怠だけ（応援の店で働いたシフトは数えない＝前と同じ）。
- 勤怠の手動修正（勤怠データの画面で直した時間）は数えない（前と同じ。DB の Toast の勤怠で数える）。
- Toast の GUID の無い店（DB に勤怠が無い）の人は、今までどおりその端末の写しで数える（その日の前まで）。
- 読み込んだ勤怠はこのログインのあいだだけ。DB の勤怠があとで直ると、次に読み込んだとき（ログインの同期・月の読み込み・ほかの店の読み込み）から変わる。
- その日（今日）のディナーの No Tip は、その時点で DB にある今日のランチで決まる（今日の途中は端末によって読んだ時刻が違う。期間の確定は期間が終わってから）。
- 表示の率（Tip Rate の画面の「No Tip」・`effectiveTipRate`）は今までどおり今日の時点（この端末の写し）。配分の額は v1187 の決め方。
- 初回勤務から 3 か月まで、店ごとに 1 回、最大およそ 3 か月分の勤怠を読む（1 回の読み込みは 1 店の 100 行ほど）。
