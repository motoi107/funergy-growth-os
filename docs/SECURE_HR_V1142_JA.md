## 3. 関数 secure-state v1142

- **`hr_get`**（`key`＝3 つのどれか）：範囲の分だけ返す（`value`・`updated_at`・`level`＝all／scoped／none）。
- **`hr_op`**（1 件ずつ。サーバーが行を読み、その 1 件だけを直し、読んだ行が変わっていないときだけ書く（変わっていれば読み直して 5 回まで。だめなら 409））：
  - 応募者 `put`（`create`）：足す（同じ ID があれば 409・上書きしない）・直す（見られる店の人だけ・もう無ければ 410・同じ中身なら書かない）。
    `_` で始まる欄（`_prior` など）は捨てる。足す・直すのは応募者を見られる人だけ（応募店舗は今までどおりどの店でも選べる。見られない店にすると一覧から外れる）。
  - 応募者 `reject`：サーバーがクラウドの応募者から不採用ログの 1 件を作り（印 `aid`＝応募者の ID）、応募者を外す。同じ応募者の記録がもうあれば足さない（答えが届かずに押し直しても 2 つにならない）。端末の言う名前・電話は使わない。
  - 不採用ログは不採用にすることでしか書けない（`hr_op` で直接は書けない）。
  - お悩み相談室 `post`：相談した人の名前と店はサーバーが決める（社員の表の名前・配属の店）。
  - `reply`：自分の相談か、管理者（範囲の店）だけ。管理者の返信かどうか（`byMgr`）はサーバーが決める。管理者が返信すると未対応 → 対応中。
  - `status`・`assign`：管理者だけ。担当の名前はサーバーが決める。
- **`hr_match`**：上の確かめ。
- 行が配列でない（形が違う）ときは、空とみなして上書きしない（500）。社員の表・店の表を読めないときは何も返さない（全部を返すことはない）。
- 答えにはいつも `hrfn:1`（アプリが関数の版を見分ける）。v1139〜v1141 の分（成長カルテ・賞与・Career Score・単価・Score管理）は変えていない。

## 4. アプリ v1142

- `hrRouted(key)`：PIN かメールのログインがあり、関数が前の版と分かっていなければ、この 3 つは関数で読み書きする。
  関数の答えに `hrfn:1` が無ければ 10 分は今までどおり REST（公開の鍵）で読み書きする（v1141 の関数でも今までどおり動く）。
- 端末の写しは**関数の答えだけ**（REST の取り込み（`_kvPullRows`）では取らない・行の一覧でも飛ばす）。
- 今のログインで関数から読めるまで、一覧を出さない（「サーバーから読み込んでいます…」）。前の人の写し・前の版の全部の写しを見せない。答えを頼んだあとにログインが変わったら捨てる（共有の端末。v1140 の Codex P1 と同じ形）。
- 保存は 1 件ずつ。**クラウドに入ったときだけ「保存しました」**。通信できない・断られたときはそのことを言い、入力の画面は閉じない。
  答えが届かずに押し直しても 2 つにならない（足す応募者の ID は画面を閉じるまで同じ・相談と返信は送信の印 `cid`）。
- 応募者を直すときは、読んだときの記録（`base`）も送り、サーバーは**この端末が変えた欄だけ**を今の記録に重ねる（ほかの端末で変わった状態・Onboarding の印を古い写しで戻さない）。同じ欄をほかの端末も変えていたら 409（読み直して、もう一度）。
- 採用 → オンボーディングは、つなぐのに失敗して押し直しても、同じ応募者のオンボーディングをもう 1 つ作らない。
- 1 行を丸ごと送る前の道（`lsSet`・送信待ち）では書かない。前の版で送れていなかった変更は送らず、この端末の `_hr_unsent` に控え（新しい 3 件）を残して知らせる。
- ログアウトで写しを消す。
- 名前・メモ・理由などはエスケープして描く（一覧・応募者の画面・不採用の一覧・相談のカード）。ID の形が合わないものにはボタンを出さない。
- 関数が前の版（答えに `hrfn` が無い・関数が無い）・ログインの印が無い（店のログイン）なら今までどおり REST（③ の SQL のあとは読めない）。PIN の確かめ先が一時的に答えない（503）だけでは REST に切り替えない（失敗として出す）。
- 関数から置いた写しには印（`_hr_src`・この端末だけ）を付ける。REST の道に切り替わったら、その写し（一部だけかもしれない・前の人のもの）は画面に出さず消し、**REST でクラウドの行（全部）を読み直すまで書かない**（一部だけの写しで 1 行を丸ごと上書きしない）。③ のあとは REST では読めないので、書かない（保存していないと出す）。
- ログインのたび（関数で読み書きしているとき）、今のログインで関数から置いたもの以外の写し（前の版の全部の写し・前の人の写し）を消す。前の版で送れていなかった変更は控え（`_hr_unsent`）に移す。控えと印はログアウトで消す。

## 7. 残る限界

- 社員の表（役割・肩書き・店）と店の表（ブランド・店名・中身の data）は、まだ公開の鍵で書ける（段階 (b) で閉じる）。GM・CEO が確かめた写しの無い人（G2 以下）は、自分の行の役割を sl か g2・店をほかの店に書き換えると、
  その店の応募者と不採用ログ（G3 と同じ範囲）が見える（G4 の範囲・相談の管理にはならない。社員の表の書き換えは `employee_field_log` に残る）。店の表のブランドを書き換えると、ブランドで当たる応募者が変わる。
  G2 にも応募者を見せるのは今の画面と同じ。閉じるなら G2 は見せない（Moto さんの判断）。
- 名前で当てる「自分の相談」は、同じ名前の人がいると両方に見える（社員の表の名前で決めるので、自分の名前を書き換えると別の人の相談が見える。`employee_field_log` に残る）。
- 通知（`notifications`）は公開の鍵で読める 1 行のまま（前から）：新しい相談の知らせに相談の題名（140 文字まで）と相談した人の名前、採用の知らせに採用した人の名前が入る。本文・電話・メール・不採用の理由は入らない（通知は 2c・ワークセンターで直す）。
- v1140・v1139 の戻す SQL を ③ のあとに流すと、この 3 つも公開の鍵で読めるようになる（それぞれの版より前の決まりに戻すため）。
- 履歴書は前からファイル名だけを記録している（ファイルそのものは保存していない）。オンボーディング（`onboardings`）は今回は外していない（本人入力の機密は v1067 の ob-private）。
- 1141 以前の端末は、③ の前は 1 行を丸ごと送る（前からある動き）。
- 応募者の ID は時刻なので、範囲の外の ID かどうか（403）と、無い ID（410）は分かる（中身は分からない）。`hr_match` に回数の制限は無い（応募者を足せる人だけ。当たった分の日付・店・理由・メモだけ）。
