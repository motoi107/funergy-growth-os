## R1 / P1：別端末での後保存がボーナス履歴を消す（既存指摘の追試）

箇所：`index.html` 59958 行（`_bonusWritePay`）、9517〜9527 行（`mergeMapByTime`）、57549 行（`saveKarte`）。

端末 A がボーナスを履歴に記録した後、A の履歴をまだ受け取っていない端末 B が同じ人の面談など別の欄を保存すると、B の従業員レコード全体が勝ち、A の `payLog` が消える。今回付け足したレコード全体の `_at` は、B の保存時刻より古いため保護にならない。

再現：A の記録 `_at=1000`・履歴 1 件 → B の別欄の保存 `_at=2000` → 本物の `mergeMapByTime` で合流すると履歴 0 件。既存試験の「古い `_at` のままの写し」だけではこの順序を検出できない。

対応：履歴を四半期・ID 単位で独立して合流するか、別の同期キーへ分離する。削除・再記録の競合も規定し、「A が記録した後に B が別欄を保存」の試験を残す。この根本のレコード単位合流は main にも存在するため、今回初めて導入された不具合とは扱わない。PR が説明する履歴保護が不十分で、既存指摘が未解消という確認。

## R2 / P1：最新の評価を受け取っていない端末が古い賞与額を確定できる（既存指摘の追試）

箇所：`index.html` 62575〜62585 行・62614〜62618 行（`kevLockQuarter`）。

確定がローカルの `bonus_eval` を読み、同期完了や入力の版の確認なしに `evSnap` を作る。評価を項目ごとに合流しても、この固定済みスナップショットは更新されない。

再現（架空）：端末 A が能力の段階を 4→5 にして再度「評価完了」。調整前の額が $3,270→$3,390。未同期の端末 B はオフラインでも旧額 $3,270 で査定を確定できる。後で A の段階 5 を受信しても、表示・履歴に使う固定額は $3,270 のまま。

対応：確定前に必要な同期の成功を待ち、評価・設定・原資・対象者などの入力の版を確定書込み時にも照合する。競合・オフライン・同期失敗時は確定せず再確認を求める。単に画面を再計算するだけでは別端末の変更は検出できない。

## R3 / P1：原価・勤怠が未取得でも「0%」を高評価として賞与に使う（追加）

箇所：`index.html` 62336〜62344 行（`kevCosts`）。

会計 PL がない月の代替として `plComputeStore` の `cogs` / `labor` を無条件に数値として採用する。しかしこの関数は仕入れ・棚卸・勤怠をまだ取得していなくても 0 を返す。新しい評価側はデータの存在を確認せず、未取得を原価率・人件費率 0% と解釈する。

再現：売上・予算だけあり、仕入れ・棚卸・勤怠が空の合成データを、本物の `foodCostOf`・`plComputeStore`・`_laborCoreForYmRaw` から評価した。Food/Labor の実績率はいずれも 0%、結果点はいずれも 75 点、G4 の FL 係数は 1.03、`blocked=null`、確定前の問題一覧は空になった。「暫定」の表示と 75 点の上限は出るが、未取得による賞与増額と確定は止まらない。

対応：各店舗・月についてデータの取得・入力状況を判別し、未取得を `null` / 不足として扱う。明示的に確認した 0 と区別する。FL の結果を賞与に反映する設定では、不足がある間は確定できないようにする。結果比率 0% の設定は従来どおり結果の不足で止めない。

## R4 / P2：査定確定後に入力した根拠・コメントを読めなくなる（追加）

箇所：`index.html` 62565〜62572 行（`kevSnapSeg`）、62882〜62897 行（`kevSnapMainHtml`）。

評価中に入力した能力・知識・仕事の質の根拠、FL の実施内容・根拠・次の改善、本人へのコメントを `evSnap` に保存していない。確定後はスナップショット専用画面へ切り替えるので、これらの説明欄が消える。特に段階 3 以外で必須とした根拠を、確定後の面談で確認できない。

再現：能力の根拠・全体コメント・FL の次の改善に固有のテスト文字列を入力。確定前の HTML には全て存在し、確定後の `evSnap` と HTML には全て存在しない。元の `bonus_eval` には残るため、データそのものを全削除する不具合ではない。ただし確定時の記録に含まれず、通常の閲覧では確認できない。

対応：入力した説明・確認状態・評価者・評価完了日時を区間のスナップショットに含め、確定後も読み取り専用で表示する。確認のために査定確定を解除する必要がない形にする。
