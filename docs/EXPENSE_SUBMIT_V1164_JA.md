# v1164：社員が経費の申請を出せない不具合の復旧（ガソリン代・建て替え経費・事前経費）

依頼：Moto さん 2026-11-14 07:56 HST の依頼書「ワークセンター『申請/承認』の統合と経理レビューへの引き継ぎ」の **最優先**（社員が経費申請を提出できない不具合を復旧する）。
申請/承認の統合（A案・B案の UI 案から）は、この復旧を前提にせず、あとで別に進める。

## 1. 再現（G2 のテスト用アカウント・合成データ）

本物のブラウザ（Chrome）で v1162 の `index.html` を動かし、関数 work-requests は本物の handler と本物の SQL（本番と同じ順の 10 本・PGlite）にした（`tests/e2e-wr/`）。G2＝社員の表の役割 `g2`・肩書き Crew Leader・店 F01。PIN でログイン。

| 入口 | 種類 | v1162 で止まるところ |
|---|---|---|
| マイページ | ガソリン代 | ボタンは出る・用紙も開く → **送るとサーバーが断る（403 forbidden「この操作はできません」）** |
| マイページ | 建て替え経費 | **ボタンが出ない**（マイページに建て替えの入口が無い） |

G4（役割 g4・Store Manager）・AM・GM は、マイページの管理者の側（PGD）に経費の入口がもともと無かった。

## 2. 原因

1. **経費の申請をサーバー（ワークセンターの申請・v1131）に移したとき、出せる人をサーバーで決めた**（ガソリン代 G3 以上・事前経費 G4 以上・建て替え G2 以上）。いっぽうアプリは G2（`g2`）を役職の上で `sl`（G3 相当）として扱う（`ROLE_ALIAS`）ので、マイページの「ガソリン代」が G2 にも出る → 送るとサーバーが断る。画面とサーバーの決まりが食い違っていた。
2. **使い始めたあと（`wr_live`）、前の画面の「申請」は新しい用紙に案内するはずが、建て替え経費だけは案内せず、保存の時点で止めていた**（`saveReimbursement` を「移りました」にして入力を捨てる）。前の用紙はそのまま開けるので、入れてから捨てられる。
3. 入口が画面ごとにばらばら（マイページはガソリン代・事前経費だけ・管理者の側は無し、レシート管理は建て替えだけ）。

保存されたのに見えなくなった申請：この 5 つの経路では、断られたか捨てられたので**サーバーにも前の形にも保存されていない**（試験で確かめた）。古い版の端末（前の形で保存する）が残っていた場合に備えて、GM・CEO のログインで前の形の申請を写す（下の 3-4）。

## 3. 直したこと

### サーバー（SQL `20261125090000_wr_expense_g2.sql`・関数の貼り替えは無し）

- `wr_exp_kinds(a)`：出せる種類。**G2 以上（と AM・GM・CEO）は 3 種**（グレードは肩書きと役割の大きいほう＝`wr_grade`。経理の Accountant は G4、事務Crew でも肩書きが Office Crew Leader なら G2 なので 3 種）、G1 の経理・事務Crew（Office Crew・Office Staff など）は建て替えだけ（今までどおり）、**ほかの G1 は無し**。
- `wr_can_submit`：種類は `wr_exp_kinds`、店は今までどおり（自分の店・応援。AM は担当の店。CEO・GM・経理・事務Crew はどの店・本部）。
- `wr_whoami`：`exp_kinds` を返す（画面はこれで入口を出す＝画面とサーバーで同じ決まり）。
- グレードは今までの `wr_actor`（GM・CEO が確かめた写しと社員の表の狭いほう・写しの無い人は G3 まで）。承認・経理の権限は変えていない（出せるようになっても承認はできない）。
- 前の SQL（`exp_kinds` が無い）のときは、アプリは前のサーバーの決まりで入口を出す（入れる順がずれても、出せないボタンを出さない）。

### アプリ v1164

- 入口を 1 つに（`wrStartExpense(kind)`）：**マイページ（社員の側・管理者の側の両方）とレシート管理の上に同じカード**「経費の申請」＝出せる種類のボタン ＋「自分の申請」（新しい 5 件・番号・状態・次の担当・「すべて見る」でワークセンターの自分の申請）。どちらから押しても同じ用紙・同じ権限の確かめ・同じ保存。
- 用紙は出せる種類だけ。事前経費は「用途・予定額・予定日」が先（部門・プロジェクト・人数は任意）。領収書・実費は要らない。
- 送ったあと：番号・今の状態（例「GM 承認待ち」）・「自分の申請を見る」。
- レシート管理の登録で種別「建て替え経費」を選ぶと、新しい用紙が開く（前の用紙に入れさせない）。前の用紙を開いたままの人が「申請する」を押したら、入れた中身（支払った人・金額・支払先・用途・メモ・領収書）を**新しい用紙に写して開く**（まだ送らない・確かめて押す）。
- 前の画面のガソリン代・事前経費の「申請」も同じ入口へ（出せない種類なら理由を出す）。
- 前の画面に残った経費の申請：GM・CEO がログインしたとき 1 回、前の形（app_state の mileage_requests・reimbursements・expense_requests）から、まだ写していないものだけを写す（`legacy_import`・何度でも同じ）。写したら「n 件を写しました」。
- 事前経費の経理の確認が済んだものは、本人のカードで「事前承認済み」（支払・精算には入れない＝前から）。
- G1：入口は出ない（読み終わるまでも出さない）。サーバーも断る。
