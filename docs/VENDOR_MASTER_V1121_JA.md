# v1121：業者マスターの削除・無効化・区分（10/30 の依頼 ③）

依頼：Moto さん 10/30 の添付「Funergy+ 修正・改善依頼（全7項目）」の ③。

1. 似た名前の業者が残っている。
2. 削除しても消えない・また出てくる。
3. 区分（仕入れ業者・工事関係業者）を足す。

Moto さんの回答（10/30・選択肢）：

- 重複は Moto さんが「業者の統合」の画面で統合する（Claude は自動で統合・削除しない）。
- 工事の業者 35 件は業者マスターに移す（工事関係業者）。

## 1. 原因（コード）

### 削除がもとに戻る

業者マスターは Supabase の `vendors` 表に 1 業者 1 行で入っている。

- **クラウドに残る**
  - 削除（`deleteVendor`）は、端末の一覧から外して `lsSet('m_vendors', 残り)` するだけだった。
  - クラウドへは、残りの業者を丸ごと upsert（`syncMasterToSupabase`）する。消した業者の行は消さないので、クラウドに残っていた。
- **取り込みで戻る**：次のログインの取り込み（`supaPullAllMasters`）は、クラウドの行で端末の一覧を置き換える。そのため、消した業者が戻っていた。
- **古い端末が書き戻す**：ほかの端末は古い一覧を持っている。その端末がどれか 1 つの業者を保存すると、全部を upsert する。そのため、消した業者も、ほかの人が直した欄も、古い写しで書き戻されていた。
- **うその「削除しました」**：クラウドに入ったかを見ずに「削除しました」と出していた。保存（`saveVendor`）も同じだった。

### 重複

- 同じ業者が別のカードで残っている（表記ゆれ・読み取りの違い）。
- 業者の統合（v1083）で「まとめる」までは別の業者になる。
- 候補は 10/30 に読むだけの SQL（`db/vendor-duplicates-check.sql`）で洗い出し、Moto さんに報告した。業者の名前と件数はリポジトリに書かない。

### 区分

- 業者マスターのカードに区分の欄は無かった。
- 工事・設備の業者は、画面のコードの中の一覧（`CONSTRUCTION_VENDORS`）を出すだけで、保存も編集もできなかった。

## 2. 変えたもの（index.html・sw.js・SQL。版 1121）

### クラウドとの合わせ方

- **送る**
  - この端末で変えた業者の、変えた欄だけを送る（`vendorPushDirty`）。
  - 読んだときの姿（`vendor_base_v1`。この端末だけ・同期しない）と比べる。
  - 送る前にクラウドの今の行を読み、ほかの人が変えた欄はそのままにする（`vendorMerge3`）。
  - 書いたあと読み直して、クラウドに入った姿を端末にも入れる。
- **取り込む**：クラウドの行に、この端末でまだ送れていない変更を重ねる（`vendorMergePulled`）。前に読んだのにクラウドから消えた業者は、端末からも外す。
- **状態と区分の時刻**
  - 状態と区分は時刻（ISO）の新しいほうを使う。
  - 時刻は、前の時刻より必ずあとにする（端末の時計が遅れていても通る）。
- **クラウドの見張り**（`supabase/migrations/20261101090000_vendor_state_guard.sql`）
  - 書き込みの時刻（`vstAt`・`vcatAt`）が今の値より古い・無いときは、その組の欄を今の値のまま残す。
  - v1120 以前のアプリが古い写しを丸ごと送っても、削除・無効・区分は戻らない。ほかの欄は今までどおり書かれる。
  - ブラウザの役割（anon・authenticated）は、この関数を直接は呼べない。

### 状態（`vst`）

| 状態 | 中身 |
| --- | --- |
| （空） | 使う |
| `inactive`（無効） | 記録は残す。請求書・食材・小切手の選ぶ候補（`getVendorsPickable`）から外す。業者マスターの「無効」に出る。使うに戻せる。 |
| `deleted`（削除） | どこにも出さない（`getVendors` が外す）。行は消さず、削除の印と履歴をクラウドに残す（古い端末から戻らないように）。 |

- 状態を変えた人・時刻・理由を `vstLog` に残す（20 件まで）。編集の画面の「状態の履歴」で見られる。
- 削除・無効にできるのは経理・事務Crew・GM・CEO。
- 削除できるのは、使われていない業者だけ。数えるもの（Invoice取込は名前とカードの id の両方で数える）：
  - アプリの請求書
  - 商品
  - 食材（大文字小文字・空白だけ違う名前も数える）
  - Invoice取込の件数
  - 業者を選ぶ待ち
  - この業者にまとめた名前
- Invoice取込の件数はメール認証のあとで読む。読めていないと削除できない。
- 使われている業者は、無効にするか「業者の統合」でまとめる。
- クラウドに入ったことを読み直して確かめてから「削除しました」「無効にしました」と出す。入らなかったと分かったら、この端末も元に戻して理由を出す。
  - 入ったかどうか分からない（送ったあとの答えも読み直しも届かない）ときは、この端末を戻さずに「確かめられませんでした」と出す（未送信に残り、あとで送る）。
- 保存も、クラウドに送れなかったら「この端末に保存しました。クラウドへはまだ送れていません」と出す（未送信に残り、通信が戻ると送る）。

### 区分（`vcat`）

- 仕入れ業者（`purchase`）・工事関係業者（`construction`）・未分類（`none`・無いもの）。
- 一覧の札と絞り込み（すべて・仕入れ業者・工事関係業者・未分類・無効）。編集の画面で選ぶ。
- 既存の業者はすべて未分類から始める。
  - Invoice取込の「食材」「食材以外」（`kind`）では決めない（工事の業者が入っていることもあるため）。
  - 未分類のうち `kind` がある業者は、名前を見てチェックしたものだけを仕入れ業者にする画面を出す（経理・事務Crew・GM・CEO）。
- この区分は一覧と絞り込みだけに使う。invoice の勘定科目・原価・Invoice取込の `kind` は変えない。

### 工事関係業者

- 画面の中の一覧（35 件）を、業者マスターのカードにする（`vendorSeedConstruction`）。
  - 区分は工事関係業者。
  - 工事の分類・メモ・住所・W9・W9 のメモ・担当者・電話・メール・LINE を移す。
- id は名前から決める（`vc-…`）。クラウドに無いものだけを入れる（ignore-duplicates）。
  - 人が直した連絡先や、削除の印は上書きしない。
  - 何度動いても同じ。クラウドから業者を読んだあとにだけ動く。
- 工事関係業者の絞り込みでは、工事の分類ごとにまとめて出す。編集の画面に工事の分類・W9 の欄。

### そのほか

- 業者マスターの一覧・編集の画面の名前などをエスケープした（前は名前をそのまま HTML に入れていた）。
- 工事関係業者は、レシート・小切手の業者の自動の当てはめ（`matchVendorBest`）に使わない（選ぶ一覧には出る）。
- 請求書の業者の候補（datalist）もエスケープした。
