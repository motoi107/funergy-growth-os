# 特例でのグレード変更（キャリアスコア評価なし）v1115

## 1. 依頼

Moto さん 10/29 17:28 HST「Funergy+ 修正依頼：評価なしでの特例グレード変更」。キャリアスコアの評価をしていなくても、特例としてグレードを変えられるようにする。通常の変更が初期。特例で省くのはキャリアスコアに関する条件だけ（権限・対象・グレードの組み合わせなど、ほかの確かめは残す）。理由は必須。保存の前に確認。履歴に特例と分かる形で残す。ダミーの点や評価の自動確定は作らない。

## 2. 今の作り（変える前）

- グレードは役職名（肩書き）から決まる（`empGrade`）。変えるのは 3 つの入口：従業員マスターの保存（`saveEmp` → `ghBeforeSaveEmp`）・昇格申請の承認（`approveLssRequest` → `ghGate`）・育成の Leader 昇格（`approveAdvance` → `ghGateStage`）。
- G2 以上から変わるとき（`ghEvalNeeded`）は、GM・CEO が「前のグレードの期間の評価を確定」（UI案38・v1058）しないと保存できない。確定には Career Score が要り、2026 Q3 からは理念に未採点があると確定できない。→ 評価をしていない人のグレードを変えられなかった。
- G1 から変わるときは、もともと Career Score の条件は無い（v1115 でも選ぶ所は出ない）。

## 3. 変えたもの（index.html・sw.js。アプリだけ。SQL・関数なし）

- 「グレードが変わります」の画面（3 つの入口で同じ）に「グレードの変え方」：
  - 通常のグレード変更（初期）：今までどおり。前のグレードの期間の評価を確定してから。
  - 特例でグレードを変更する（キャリアスコア評価なし）：GM・CEO だけが選べる（ほかの役職は灰色で「特例は GM・CEO だけが使えます」）。
- 特例を選ぶと：説明「キャリアスコアの評価を伴わずにグレードを変更します。変更理由と操作履歴が記録されます。」・対象従業員（役職の前 → 後）・現在のグレード・変更後のグレード・適用日（確定日の翌日。今の仕組み。確定日を変えるとすぐ変わる）・G3 からのときは職種（G3 の期間）・今の Career Score の状態（まだ評価がありません／評価途中（採点していない項目 N）・今の点。どちらも「そのまま残ります」）・特例変更の理由（必須・500 字まで）。
- G3 からのときの職種（オペレーション／サーバー／キッチン）はボーナスの職種係数の区分で、評価ではないので、通常の変更と同じく決める（役職名やこの四半期の選択から決まればそのまま、決まらなければ選ぶ。選ぶまで進めない。確定日を変えると表示も変わる）。ただし専門職・オフィス用の評価表の人は、2026 Q3 からの賞与では職種で基準点が変わらないので、特例では聞かない（「使いません」）。
- 理由が空・空白だけ（見えない文字だけも）なら「内容を確認する」を押せない。見えない文字は Unicode の決まり（Default_Ignorable_Code_Point・制御文字・書式文字・私用・未割り当て）でまとめて除き、残りに文字・数字・句読点・記号が 1 つも無ければ理由なし（結合する記号だけ・点字の空白だけも不可）。500 字は除いたあとで数える。押すと確認の画面（対象従業員・役職・グレード・確定日と適用日・変更種別「特例変更」・理由・メモ・操作者・Career Score の状態）→［特例で変更して保存］（承認のときは［特例で承認してグレード履歴に記録］、Leader 昇格は［特例で昇格してグレード履歴に記録］）。［戻る］で入れたものは残る。確認のあとで理由・変え方を変えたら、もう一度確認の画面を通る。
- 保存（承認・昇格）の直前にも、権限（GM・CEO）・理由・確定日とグレード履歴をもう一度確かめる（画面の表示だけに頼らない）。だめなら何も変えない。
- 役職とグレード履歴は今までどおり一緒に保存する（どちらかが保存できなければ両方とも戻し、同期にも送らない・v1058 のまとめた保存）。
- グレード履歴の記録に `mode:'special'`・`reason`・`spBy`・`spAt`（特例を決めた人と日時。新しい記録なら `by`・`at` と同じ）・G3 からのときは `track`（前後のグレードは `from`・`g`、適用日は `d` の翌日）。評価（`prevEval`）は残さない（前に通常のほうで評価を確定していても、特例を選んだら使わない）。同じ日・同じグレードの記録が先にあれば特例の印を足す（もう特例の印があれば前のまま）。
- 履歴の表示（成長カルテのグレード履歴・すべての変更の一覧・グレード履歴の編集の画面）に「特例（評価なし）」の札と「特例変更（Career Score の評価なし） 理由：…」。グレード履歴の編集で日付・メモを直しても、特例の印と理由は残る。
- 評価が無い人の「Career Score」の欄に「評価をせずに変えるときは、上の「特例でグレードを変更する」を選べます（理由が必要）。」
- 版 1115（APP_VERSION・SW_BUILD）。

## 4. 変えていないもの

- Career Score の点・未評価・評価途中・確定の状態（0 点・評価済み・基準達成にしない。自動で確定しない）。過去の評価の記録。
- 通常のグレード変更の決まり（評価の確定が要る）。権限（評価の確定と同じ GM・CEO）。確定日とグレード履歴の確かめ。役職と専門職の組み合わせ（v1103 の確かめ）。
- ボーナス：特例の記録には評価が無いので、前のグレードの期間は今までどおりその四半期の Career Score（固定した評価か正式な評価）で計算する（`bonusSegEval` が null → 四半期の評価）。無ければ「未評価」で、その四半期の確定が止まる（今までどおり）。G3 の期間の職種係数は、特例の記録の `track`（`ghSpecialSegTrack`。通常の変更の `prevEval.track` と同じ扱い）。確定した四半期・給与・ボーナスの記録は書き換えない。
- 給与は今までどおり役職（肩書き）の既定と個別の設定から。
