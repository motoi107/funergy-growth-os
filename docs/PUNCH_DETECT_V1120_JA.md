# v1120：未登録の打刻検知の漏れ（10/30 の依頼 ④）

依頼：Moto さん 10/30 の添付「Funergy+ 修正・改善依頼（全7項目）」の ④。Tip管理には出ているのに、従業員マスターの「未登録の打刻検知」に出てこない人がいる（報告のあった人の名前はリポジトリに書かない）。

Moto さんの回答（10/30）：

- 「検知に出して後からでも結べる様にして」
- Toast の仕組みのアカウント（Toast Generic Login・LaLa の Server Default）は「外す（Botと同じ）」

## 1. 原因（コードと、本番を読むだけの結果）

- Toast の勤怠の取り込み（`syncTipLaborFromDB`）は、Toast の名前で従業員を探す。探すときに在籍・退職を区別しない（同じ名前・大文字小文字・名前の一部）。
- 同じ名前の在籍の人がいないとき、v1111 の決め方では退職の記録に打刻を入れる。もう一度入った人の Toast の名前が前の（退職した）記録と同じだったので、10 月の打刻が退職の記録に入っていた。
- 「未登録の打刻検知」（`unregisteredClockIns`）は、勤怠の行の名前が従業員マスターにあれば登録済みとみなしていた。在籍か退職かも見ていなかった。そのため一覧に出なかった。
- チップの配分（`calcTipDistribution`）は退職の人を数えない。Tip管理の「勤怠はあるのに配分に出ていない出勤者」には「退職扱い」として出ていた。この打刻の分のチップは配分に入っていない見込み（画面では確かめていない）。
- 同じ形（Toast の名前が退職の記録と同じ）の打刻はほかの店にもあった。どれも 9/25 までの打刻で、退職日の前のものなら一覧には出ない。
- 名前の一部で別の人に入っている打刻は、本番を読んだ時点では無かった。ただし取り込みの決め方は名前の一部でも人を決めるので、これからも起こりうる。
- Toast の仕組みのアカウント（Toast Generic Login・LaLa の Server Default）は人ではない。名前がだれにも当たらないので、いつも「未登録」に出ていた。業務Bot は 10/4（PR #31）から外している。

## 2. 変えたもの（index.html・sw.js。版 1120）

### 一覧に出す打刻（`unregisteredClockIns`。各行に `kind`）

| kind | 中身 |
| --- | --- |
| `none` | 今までどおり：名前がだれにも当たらない打刻 |
| `resigned` | 新しく出す：Toast の名前が退職した人の記録と同じで、退職日より後の打刻がその記録に入っている |
| `part` | 新しく出す：取り込みが、名前の一部が同じ人に入れた打刻 |

`resigned` の決まり：

- Toast の名前が退職の記録の名前と同じ（大文字小文字・空白・ハイフンだけ違う）か、その退職の記録の別名のとき。名前の一部で退職の記録に入ったものは `part`。
- 退職日が入っていない（または YYYY-MM-DD でない）退職の記録は、どの打刻が退職のあとか分からないので出す。
- 同じ名前の在籍の人がいれば、その人の打刻なので出さない。

`part` の決まり：

- Toast の名前とその人の名前が、大文字小文字・空白・ハイフンだけの違いなら出さない。
- 別名（Toast での名前）で結んであれば出さない（退職の記録に入っているときは、在籍の人の別名だけ）。
- Toast の仕組みのアカウントでも、人に入っていれば出す（その人の勤怠・チップに入っているため）。

`resigned`・`part` の行には、今その打刻が入っている人（`emp`：記録の id・名前・状態・店・応援・退職日）を付けた。

### 出さない打刻（`toastSystemAccount`）

だれにも入っていない打刻だけ、業務Bot（`isBotSystemAccount`）と同じ決まりで外す：

- Order Only・Kiosk
- 全店の Toast Generic Login
- LaLa（F06）の Server Default

名前は NFKC・小文字にし、空白・`_`・`-`・`.`・`*` を同じとみなして比べる。外すのは一覧からだけで、取り込み・勤怠・チップの元のデータは変えない。

### 画面（従業員マスターの「未登録の打刻検知」）

- `resigned` の行
  - 札：「退職の記録に入っている」
  - 説明：どの退職の記録に入っているか（状態・店・退職日）、退職の人はチップの配分に入らないこと
  - 打刻のある店が所属・応援に無いときは、在籍に戻したらその店を入れるよう案内する
  - ボタン：［在籍に戻す］（今までの `restoreEmployee`。メールの認証が要る）・［今の従業員に結ぶ］・［記録を開く］
  - 名前が空白・ハイフンだけ違う在籍の人がいれば、その人を出し、［〇〇さんに結ぶ］を先にする（在籍に戻すと同じ人が 2 人になる）
- `part` の行
  - 札：「名前の一部で入っている」
  - ボタン：［〇〇さんで合っている（結ぶ）］（結ぶ画面をその人を選んだ状態で開く）・［ほかの従業員に結ぶ］・［新しく従業員登録］
  - 今入っている人が退職していれば、［合っている］は出さない
- 結べない人（本当の役職が CEO・GM・AM・経理でない人）には、［在籍に戻す］・［結ぶ］を出さない。
- 退職日は文字をそのまま出さない（エスケープ）。
- 従業員の前の欄 `toastName` は使わない（取り込み（v1111 から）もチップの配分も読まないため、ここで登録済みとみなすと打刻が隠れる）。
- AM は今までどおり担当の店の行だけ。
- ダッシュボードの知らせは「未登録・結び直しが要る打刻」に変えた。

結ぶと、今までの v1111 の仕組み（別名・勤怠の取り直し）で、その名前の打刻が結んだ人に移り、一覧から消える。在籍に戻しても消える。

## 3. 変えていないもの

- Toast の勤怠の取り込みの決め方（名前の一部で人を決めるところも）
- 勤怠・チップの元のデータ、チップの配分の式
- 名前の一部が同じ人を自動で同じ人とみなすこと（しない。人が確かめて結ぶ）
- グレードなどを推測して登録すること（しない）

## 5. 限界

- 取り込みは名前の一部でも人を決め、完全一致の人より前に並ぶ部分一致の人を選ぶことがある（前から）。この版では一覧に出すだけで、取り込みは変えていない。
- 名前の一部で入った打刻が同じ日にもう 1 つあると、取り込みはあとの打刻で上書きする（前から）。結べば、その名前は確かな当たりになり、同じ日の 2 つは足される。
- 1 日に 2 つ足した行（`toastNames`）のうち 1 つだけが名前の一部のときは、その日の時間すべてを数える（まれ）。
- 在籍の人が所属・応援に無い店で打刻した場合もチップの配分に入らない。これはこの一覧には出さず、Tip管理の「勤怠はあるのに配分に出ていない出勤者」（別店所属・応援未設定）に出る（前から）。
- 判定はこの端末にある勤怠の写し（`tip_labor_`）だけで、期間は 14〜60 日（前から）。
- 実機・本番のデータでは確かめていない。
