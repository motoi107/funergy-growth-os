## 1. 何が起きていたか（Codex のレビュー 6596546334・`3aa92e4`）

v1132 では、GM・CEO の端末が**正式な値を書いてから**サーバーに「反映した（apply）」を記録していた。書く前の確かめ（evalFresh）は読むだけだったので、そのあとの待ち時間に、ほかの端末の操作が入っても止まらなかった。

| P2 | 起きたこと | どこ |
|---|---|---|
| 1 | スキル：読み込み（pullOpKey）のあいだにほかの端末が「反映しないで閉じる」→ 閉じた申請のレベルが書かれた（申請は閉じた・値は 2） | `skillApply` |
| 1 | Tip Rate：確かめの画面を開いているあいだにほかの端末が閉じる → 古い画面で保存すると Tip Rate の決定ができた | `applyTipRaise` の包み |
| 2 | Career Score：読み込みのあいだにログインが別の人に変わる → その人の名前で承認・点を書いた（`_wrOk` が承認できる人の確かめを飛ばす） | `csApply`・`approveLssScoreRequest` |

マージ済みの main（`f235f04`）で、スキルの場面を合成データで再現した（閉じた申請・Grill＝2）。

## 2. 直し方

### サーバー（SQL `20261106090000`・関数 v1133）

- 申請の行に押さえ（`apply_key`・`apply_emp`・`apply_by`・`apply_at`）。
- **反映の操作を 4 つに分けた**：
  - `apply_start`：押さえる（状態は変えない）。鍵＝この操作の client_key（アプリだけが知っている）。版（rev）が合うときだけ。
  - `apply_done`：反映した（反映済み）。`apply_fail`：反映できなかった（反映エラー・理由が要る）。`apply_cancel`：やめた（何も変えていない・承認済みのまま）。
  - この 3 つは**押さえたときの鍵（claim）が合うときだけ**（同じ GM のほかの端末・ほかのタブも通らない）。
- 押さえているあいだ（**30 分**）、ほかの人・ほかの端末は押さえられない・「反映しないで閉じる」もできない。30 分たっても終わっていなければ、やり直す（押さえ直す）か閉じられる。押さえた人は 30 分を過ぎても鍵が合えば記録できる（ほかの人が押さえ直す・閉じるまで）。
- 前の版（v1132）の `apply` はもう出さない・通さない（v1132 の端末は反映を始めない＝書かない）。
- 「要対応」は `apply_start`・`apply_done` で数える（押さえているあいだ、押さえた人以外の「要対応」からは消える）。
- `wr_stage` は 3。関数の whoami は `fn: 3`。
- 1 段目・2 段目の中身は変えていない（2 段目の `wr_actions_eval`・`wr_act_eval`・`wr_list` を置き換えた）。2 段目の SQL をあとで流し直したら、この SQL も流し直す（入れる一式の ② は 3 つを順に入れるので、② を流せばよい）。

### アプリ v1133

- スキル・Career Score：「正式な値に反映する」→ **押さえる → 読み込む → ログインが同じかを確かめる → 書く → 鍵で記録**。押さえられなかったら（ほかが先に進めた・閉じた）何も書かず、最新を出す。
- Career Score：読み込みのあとにログインが変わっていたら書かない・承認しない（P2-2）。`approveLssScoreRequest` の `_wrOk` は、今のログインが GM・CEO のときだけ。
- Tip Rate：確かめの画面を開くときは押さえない（開いたまま閉じても、ほかの端末を待たせない）。**保存を押したときに押さえ**、保存で新しい決定ができたら記録、できなかったら（画面を閉じた・選び直した・確かめでやめた）`apply_cancel`。
- 記録が届かなかった（通信）とき：押さえたまま。「この端末で反映しています」と出し、もう一度押すと**記録だけ**する（スキルは同じ値を書くだけ・Career Score は承認済みなら記録だけ・Tip Rate は決定をもう 1 つ作らない）。
- 反映中の知らせ：だれが・いつから反映しているか／30 分たって止まっている（値を確かめてから、反映し直すか閉じる）。
- 前の版のサーバーなら分かる言葉：関数が前の版（`fn` が 3 でない）・SQL が前の段（`sql` が 3 でない）。

## 4. 限界（残ること）

- 押さえた端末が止まる（電池・通信・ページを閉じる）と、その申請は 30 分だれも反映・閉じることができない。
- 押さえた端末が 30 分より長く止まったあと（Tip Rate の確かめの画面の `confirm` を開いたままなど）、ほかの人が閉じるか押さえ直してから元の端末が保存すると、正式な値は書かれ、記録はできない。そのときはその端末に「正式な値は書きましたが、反映の記録ができませんでした」と出す（値を確かめてもらう）。
- ログインが変わって書かなかったとき、押さえは 30 分で切れるまで残る（次の人の印では押さえを外せない）。
- 正式な値（スキル・Career Score・Tip Rate）は今までどおり app_state（公開の鍵で書ける）。サーバーが守るのは申請と反映の記録の順で、正式な値そのものではない（v1132 と同じ・Codex も同じ判断）。G4 の制限も画面だけ。
- 実機（iPhone）・本番の DB・日英の実画面・速さは確かめていない。
