## 7. GM 承認 → 経理レビュー（今の処理）

- 申請はサーバーの `wr_requests`（work-requests の関数）。GM・CEO の承認（1 件 `approve`・まとめて `bulk_approve`（v1190 の共通ルールのとき））で `status` が `approved`（段階 2 の種類は `acct`）になる。
- 経理レビューは `list`（`scope:team, state:open`）を読み、`approved`・`checked`・`acct` を出す（`renderWrAcct`）。**写しや経理用の台帳を作らない**ので、載せ忘れ・二重の掲載は起きない。版（`rev`）で同時の操作を止める。
- 経理の操作は `check`（確認）・`pay`（精算を記録・ガソリン代と建て替え）。処理済みは `acct_done`（処理した日の月）。
- 共通ルール（v1190）を有効にしたあと、CEO などの段が残る案件は `route` に残る段が出る →「GM 承認済み・ほかの承認待ち」として経理は見るだけ（今の `status` は最終承認まで `pending`。一覧の箱は `route` から作る）。
- 差し戻し・取り下げ・中身の変更は `status` と `rev` が変わる → 次に読むと最新になる。前の版で `check`・`pay` を送ると 409。
- 10 種類の対応は UI案94 の「操作の流れ」の表（レシート・立替経費・チェック・紛失届・ガソリン代・休暇申請・事前経費・業者マスター・区分承認・報告承認）。**GM 承認の流れが無いもの**：レシート・チェック・区分承認（経理の確認だけ）、業者マスター（直接登録）。紛失届は GM・CEO の承認が共通データの画面（サーバーの外）。報告承認は閉じた前の画面。
