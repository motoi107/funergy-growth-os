## 1. 原因（コードで確かめたこと）

出数（`menu_mix_<店>_<年.月>` の `items`＝レシピごとの出数）を書く所は 2 つあり、決まりが違っていた。

| | ログイン・月の読み込み（`loadMenuMixFromDB`） | メニュータブの「Toast 同期」（`syncMenuFromToast`） |
|---|---|---|
| 日別の行（`business_date` あり）| 同じ商品の行を**足す**（v698） | 1 行ずつ**代入**（最後の行の数だけが残る） |
| 月のまとめの行 | 日別の行があれば使わない（v739） | 日別の行と一緒に代入（どちらが残るかは並び次第） |
| 共通レシピ（Totoya 共通・全店共通）| 使う（v737） | 使わない（店舗専用だけ） |
| 今日（ハワイ）の途中の数 | 月の出数に入れる | 入れる |
| 中身が同じとき | 毎回書き直して送る | 毎回書き直して送る |

- そのため「Toast 同期」を押すと、その月の出数が**最後の 1 日の数**（または月のまとめの行の数）になり、次のログインで足した数に戻り、また押すと崩れる、を繰り返していた。
- どちらも今日の途中の数を月の出数に入れていたので、同じ月でも見るたびに数が動いた（前日までの集計ではなかった）。
- ログインのたびに、全店の出数を変わっていなくても書き直して送っていた（速さに関係）。

合成データでの前後（同じ商品・10/28 に 10、10/29 に 12、今日 10/30 に 5 の途中の数）：

| | v1123 | v1124 |
|---|---|---|
| 「Toast 同期」 | 5（今日の行だけが残る） | 22（10/29 まで） |
| ログイン・月の読み込み | 27（今日の途中の 5 を含む） | 22（10/29 まで） |

## 2. 変えたこと（アプリ v1124）

- 1 つの決まり `menuMixFromSales` を両方が使う：
  - 日別の行が 1 件でもあれば日別だけ（月のまとめの行と足さない）。同じ商品の行は足す。
  - 日別のときは**ハワイ時間の昨日まで**（`business_date` が `bizToday()` より前）。今日の分は明日の読み込みで入る。月のまとめの行だけの月はそのまま。
  - 店舗専用のレシピを先に、共通のレシピは同じ GUID が無いときだけ。
- 書くのは `menuMixApply`：中身（出数・売上）が変わらなければ書かない・送らない。結べた出数が 1 つも無いとき（月の 1 日・紐づく商品なし）も書かない。手で入れた出数（Toast の行の無いレシピ）はそのまま。
- 知らせ：「出数を同期」「Toast 同期」の結果に「10/29まで（ハワイ時間の昨日まで）」（過去の月は日付だけ）。今日の分しか無いときは「今日の分は明日から入ります」。
- 「出数を同期」を押したときは、一度読んで固定した過去の月も読み直す（前は何も出さずに終わっていた）。自動の読み込みは今までどおり 1 回だけ。
- 変えていないもの：Toast からの取り込み（hyper-worker）・`toast_item_sales` の行・レシピの同期（商品名・カテゴリー・売価）・出数を手で入れる画面・理論原価の計算式・保存のキー。

## 2b. Toast から入れた古い出数を消す（PR #114 の Codex `fbc4bd8`・Claude の再レビューの P2）

- 不具合：`menuMixApply` は今回の集計に入った商品だけを書き換えていた。v1123 までに「今日の途中の数」を入れた商品で、昨日までの行が 0 件のもの（今日だけ売れた商品など）は、古い数が残り、「ハワイ時間の昨日まで」と出しながら今日の途中の数を出し続けた。
- 直し：Toast から入れた数を 1 品ごとに覚える（入れ物の `_auto`：レシピ ID → `{ n：入れた数, t：そのときの 1 品ごとの印 _im }`）。この店で Toast と結ばれたレシピ（`menuMixFromSales` の `linked`）で、今回の集計に無いものは：
  - Toast から入れたまま（数も印も `_auto` と同じ＝そのあと誰も直していない）なら消す。
  - 人が入力・修正した数は残す（これからは手入力として扱う）。直すと 1 品ごとの印（v834 の `_im`）が進むので、同じ数に戻しても、ほかの端末で直して合流で入ってきても、Toast の数とはみなさない。
  - `_auto` の無い前の記録（v1123 まで）は消さない（Toast の数か人の数か分からない）。
  - Toast と結ばれていないレシピ・ほかの店のレシピは触らない。
- `setMenuMix` に印の時刻を渡せるようにした（`at`）。Toast から入れるときは、`_auto` の `t` と 1 品ごとの印を同じ時刻にする。数が変わらない品は印を進めない（今までどおり）ので、`t` も今の印のまま。
- 数だけの `_auto`（この直しの前のビルド `2cb3151`・本番には出ていない）は信用せず、次に書くときに外す。
- 結べた出数が 0 件でも、消すものがあれば書く（月の 1 日に、前の月の分ではなくその月の今日の途中の数が残っていた場合など）。消すものも無ければ今までどおり書かない。
- Codex の再レビュー（`65bdac0`・P2）：最初の直し（`2cb3151`）は、`_auto` の無い前の記録で `toastSrc` があれば結ばれたレシピの数を消していたので、v1123 までに人が直した数・入れた数も消えうる（保存した入力を黙って消す）。→ 前の記録は消さないようにした。
- 限界：前の記録（v1123 まで）に残っている「今日の途中の数」は、この版では消さない。その月の今日の分は、次の日に「昨日まで」の集計に入って正しい数に入れ替わる。Toast の行があとで消えた（取り消し・結び直し）商品の前の数は残る（その月を手で直す）。
- 限界：Toast と結ばれたレシピで、今回の集計に入った商品の数は、今までどおり Toast の数で書き換える（人が直した数も。v1123 も同じ）。

## 4. 限界・残り

- 過去の月は、自動では一度読むと固定する（前から）。月が替わった直後、前の月の最後の日の行が Toast から入る前に読むと、その日が入らないまま固定される。そのときは「出数を同期」で読み直せる（v1124）。
- LaLa など、店によっては Toast からの出数の行が欠けている日がある（`db/menu-sync-status-check.sql` の `missing_days`）。これは Toast の取り込み（hyper-worker）の側で、アプリの直しでは埋まらない。店・日ごとの欠けは 2 段目の画面で「取り込みが欠けている日」として出す（UI案65）。
- 2 段目（UI案65 の画面）：絞り込み（店・カテゴリー・商品）、期間（昨日・直近 7 日・直近 30 日・今月・先月・任意）、タブ（概要・メニュー別・推移）、POS（Toast の売上）との照合、スマホは 2 列。期間の集計は日別の行をそのまま読む（月の入れ物を足し合わせない）。
- 速さの前後（ログインで書き直さなくなった分）は、本番の端末で測っていない。
