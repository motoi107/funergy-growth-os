## 3. 判定の決まり（初期値＝UI案61 の決まり A・設定案）

1. 使うのは正式な記録だけ。
   - 店舗用・部門別：lss_emp_ の承認された点。承認待ちの申請と採点の画面で入力中の点は混ぜない。
   - オフィス用：いちばん新しい確定した評価（conf）。自己評価・上長の評価の途中は使わない。
2. 根拠の項目が 3 つ以上ある強みだけを見る。
3. 根拠の項目がすべて採点済みで、すべて 2（継続してできる＝今の役職の期待レベル）以上。
4. 3（模範）の数が根拠の項目の半分以上。
5. 並びは、3 の割合 → 根拠の項目数 → 表の順。主な表示は上から 3 つ。
6. 当たる強みが無ければ「得意分野を確認中」。評価途中（採点していない項目がある）は、根拠がそろった強みだけを「現時点で確認できている強み」として出す。

- 合計点やカテゴリーの得点率では選ばない。採点していない項目を 0 点や推測で埋めない。当たらない強みは出さない（灰色の「未獲得」アイコンは作らない）。
- 「強みの決まり」（GM・CEO）で変えられるのは 2 つだけ。
  - 根拠の項目の数：3〜6 つ以上。
  - 3（模範）の数：半分以上（初期値）・1 つ以上・すべて。
- 決まりを変えても、変わるのは表示だけ。保存は共通データ `cs_strength_rule`（`{rule:{minItems, top, at, by, hist, _at}}`）。
  - 保存の前にクラウドの最新を読む。開いたあとでほかの端末が変えていれば保存しない。
  - 「初期値に戻す」は `reset:true` を新しい時刻で書く（`_deleted` は合流で時刻より先に勝つので使わない）。
- 一文は、上から 2 つの強みの短い言い方をつなぐ（例「新人育成と接客で力を発揮する人」・英語「Shines in … and …」）。評価途中は「現時点では、」を付ける。決まった文の組み合わせだけで、推測で書き足さない。

- 「教える」ことを根拠にするのは S4（G の教え方・E9 新人教育力）だけ。ほかの強みは高い点でも「教えられる」とは書かない。
- 表に入っていない項目は強みに使わない（点・総合点には今までどおり入る）。
- **経理・調理（8 軸 × 4 項目）**：軸ごとに 1 つ（AC-A〜AC-H・CK-A〜CK-H）。根拠はその軸の 4 項目。店舗用の 8 カテゴリーを当てはめない。
- **サービス・マーケ**：今は各軸 1 項目なので、根拠が 3 つに届かず「この評価表は分野ごとの項目が少ないため、強みを判定していません」と出す（点は内訳で見られる）。
- **オフィス用（7 カテゴリー × 5 項目）**：カテゴリーごとに 1 つ（OF-A〜OF-G）。
  - 根拠は、その人の担当で採点する項目だけ。配点 0 の区分（G1・G2 の O-G＝育成記録）は使わない。
  - 根拠に出す「見られている行動」は、その項目の説明（評価の時点の定義）。

## 5. 状態ごとの見え方

| 状態 | 出すもの |
|---|---|
| 未評価（記録なし） | 「まだ評価がありません。評価が入ると、確認できた強みがここに出ます。」（オフィス用は「確定した評価がまだありません」） |
| 評価途中 | 根拠がそろった強みだけ＋「採点していない項目が N あります…」。1 つも無ければ「得意分野を確認中」 |
| 評価確定・当たる強みなし | 「得意分野を確認中」＋「評価はそろっています。強みとして出す決まり（…）に当たる分野は、まだありません。」 |
| 承認待ちあり | 正式な評価で出し、「点の変更の申請が承認待ちです…（申請中の点は混ぜません）」 |
| 評価項目が入れ替わった（専門職の変更など） | 「評価項目が入れ替わったため、強みを確認中です」（同じ ID が別の質問を指すので判定しない） |

- 根拠（強みを押す）では、次を出す。
  - できること。
  - 根拠の項目（ID・名前）と評価（評価基準の名前と点：「模範となっている（3）」「継続してできる（期待レベル）（2）」）。
  - 評価日・評価者（記録全体の日付と人。今の記録は項目ごとに持っていない）、「5 項目すべて 2 以上・3 が 4 つ」。
  - 2 と 3 の評価基準の説明。
- 操作と読み上げ：
  - 強みは `<button>`（キーボードで Tab・Enter）で `aria-pressed`。根拠は `aria-live="polite"` の場所に入れ替えるので、選んだ強みと根拠が読み上げられる。
  - 押せる所は 44px 以上（強みのボタンは 104px）。「強みをすべて見る」は `aria-expanded`。

## 6. 伸ばしていること

- 成長カルテの「次期の目標」（面談の合意事項・`growth_karte` の goals）から 1 つだけ出す。
  - 選ぶのは、終わっていない・文のある目標のうち、期限のいちばん近いもの（期限の無い目標はあと）。
  - 無い人には出さない（作らない・推測しない）。
- 回答 3（「ある人とない人がいます」）を、強みを出す画面（My ページ・Career Score の画面・成長カルテ）に、ある人だけ出す、と読んだ。違えば 1 か所（`cssProfileHtml` の `opt.grow`）で直せる。

## 7. 変えないもの

- 採点（0〜3）・項目・配点・8 カテゴリー（G2 も全部）・総合点・基準点（賞与 ① と同じ）・昇格の判定・賞与の計算・グレード。
  - 強みの判定はどれにも使わない（試験で、賞与・昇格・点の表示のブロックに強みの関数が出てこないことを確かめる）。
- 何も保存しない（判定と描画は書き込まない）。新しく保存するのは「強みの決まり」だけ（GM・CEO が変えたとき）。
