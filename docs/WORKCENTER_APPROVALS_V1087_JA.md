## 2. 保存の穴（先に直したもの）

### 2.1 承認センター（approvals）

前は、どちらかの記録に保存時刻（`_mut`）があると、新しいほうの記録をまるごと採っていた。2 台の端末で別々の役割を承認すると（AM と GM など）、あとから保存したほうの記録には先の承認が無いので、先の承認が消えた（書いたあとの確かめも保存時刻だけを見るので通っていた）。

v1087 の合流（`_apMergeOne`）：

- 承認（`signoffs`）は役割ごとに足し合わせる。各承認に承認した時刻（`_t`）。同じ役割が 2 つあれば新しいほう（合流の順によらない）。
- 自分の承認の取り消しは、役割と取り消した時刻（`_soX`）を残す。その時刻より前の承認だけを落とす（あとで承認し直したものは残る）。
- 状態：決まったもの（承認・却下・取り下げ）が承認待ちに勝つ。両方決まっていれば、決めた時刻（`_stT`）が新しいほう。
- 承認の取り消し（承認待ちに戻す）は版（`_gen`）を 1 つ進める。前の版の承認・状態・経理の確認はすべて負ける（前の版の保存時刻より大きくする）。
- 経理の確認（`acct`）は時刻（`t`）が新しいほう（取り消しも時刻で）。決めた時刻より前の確認は使わない（承認を取り消して決め直したとき、前の確認が戻らない）。決めるときに確認の印を外す。
- 合流した記録の保存時刻は大きいほう。合流した中身が、保存時刻のいちばん新しい写しと違えば、その 1 つ先（前の版の端末は保存時刻で記録をまるごと選び、同じなら手元を採るので、合流した中身を採るように）。同じものをもう一度合流しても変わらない。
- 前の版のアプリで「承認を取り消す」をした記録（承認待ち・承認なし・決めた時刻は写したまま・あとで保存）は、今までどおり取り消しを採る。写っていた経理の確認は外す。
- 2 台でほぼ同時に承認すると、承認はそろったのに確定していないことがある（それぞれの端末では 1 つ足りなかった）。承認待ちの一覧に「確定する」（この申請を承認した人と GM・CEO）。
- 書いたあとの確かめ（`_coversApprovals`）は「手元の分を足してもクラウドが変わらないか」で見る。

### 2.2 申請の記録（ガソリン代・事前経費・休暇）

`mergeReqTomb` は、両方決まっていると保存した端末の写しを採っていた。古い写しを持つ端末が別の申請を保存すると、あとからの精算確定・承認の取り消しが元に戻った。

- 状態を変えた時刻（`_stT`）を、承認・却下・承認の取り消し・月末の精算確定で付ける。時刻が違えば新しいほう。削除はいつも勝つ。時刻が同じ（どちらも無いを含む）ときは今までどおり。
- `_stT` を付けるのはこの 3 つの記録だけ。ほかに `mergeReqTomb` を使う記録（シフト変更・オンボーディング・紛失届・備品発注）は今までと同じ動き。

### 2.3 建て替え経費（reimbursements）

決定（承認・却下）・支払済・支払済の取り消し・承認センターからの反映と取り消しで、保存時刻（`invTouch`）を進める。前は進めなかったので、古い写しの端末の保存で「申請中」に戻ることがあった。

### 2.4 通知

クラウドから届いた通知は、手元の通知と合わせてから書く。前はクラウドの値で置き換えたので、まだ送れていない通知（電波の無いときの承認の知らせなど）が手元から消えた。

### 2.5 押す前に読み直す

承認する・却下・代理で全承認・確定する・自分の承認を取消・承認を取り消す・経理の確認は、押す前にクラウドの最新（`approvals`）を読み直す（8 秒で返らなければ読めなかったものとして進む）。ほかの端末でもう決まっていれば、知らせて何もしない。読めない（同期 OFF・電波なし）ときは手元のまま進む（合流で消えない）。

承認センターを開いたとき、1 分より前に読んだきりなら裏で読み直し、変わっていれば描き直す。画面に「クラウドの最新 HH:MM」と「最新に更新」。

## 3. 通知と承認センター

### 3.1 どの画面で決めても

申請の画面で決めたときも、承認センターの案件を済みにし（決めた人・時刻）、申請した人に「〇〇 が承認されました」（却下も）を出す。

| 画面 | 関数 | 案件の探し方 |
|---|---|---|
| ガソリン代 | `approveMileage`・`rejectMileage` | ref（申請の ID） |
| 事前経費 | `approveExpense`・`rejectExpense`（今は画面にボタンなし） | ref |
| 休暇 | `approveVacation`・`rejectVacation`（今は画面にボタンなし） | ref |
| 建て替え経費 | `_applyReimburseDecision` | ref |
| Tip Rate | `approveTip` | ref（v1087 から）。前の申請は名前と率 |
| Leadership（昇格・Tip Rate の申請） | `approveLssRequest` | ref（v1087 から）。前の申請は名前と種類 |
| 予算 | `approveBudgetSeg`・`rejectBudgetSeg` | ref（店舗）と月 |
| 月間行動計画 | `ccApprove`・`ccReturn` | ref（月）。Head Chef への知らせは前から別にある |

- 手元に案件が無ければ（ほかの端末で出された申請）、クラウドを読み直してからもう一度探す。無くても申請した人と経理には知らせる。
- 申請した人が取り下げたら（ガソリン代・事前経費・休暇）、承認センターの案件は「取り下げ」。
- 休暇の画面で承認を取り消したら、承認センターの案件も承認待ちに戻す（版を進める）。前はもう一度承認する入口が無かった。
- 承認センターで押したとき、申請の画面でもう決まっていれば（前の版で画面から承認した・取り下げた）、申請は書き換えずに承認センターを合わせる（承認したものを却下に変えない）。承認待ちの一覧にもその印。
- 承認センターで Tip Rate・Leadership を承認しても、申請（`tip_requests`・`lss_requests`）には反映しない（前から。率・役職は申請の画面で承認したときに変わる）。
- 申請の画面で決めた案件には印（`via:'page'`）。Tip Rate・Leadership を申請の画面で決めたものは、承認センターの「承認を取り消す」を断る（率・役職を戻す処理が無い。取り消すと、次の却下が「画面で承認済み」に合わせられて承認に戻ってしまうため。申請と結んでいない前の案件は印で見る）。
- 承認センターで同じ決定になっている申請を、あとから申請の画面で決めたときは、申請した人・経理に二度は知らせない。違う決定（承認センターで却下・画面で承認）なら、クラウドを読み直したあと、承認待ちの案件が無いときだけ、いちばん新しい案件を画面の決定に合わせて知らせる（月間行動計画・予算は同じ月・店舗で出し直すので合わせない。古い回の記録は書き換えない）。

### 3.2 経理と事務Crew への知らせ（2A）

最後の承認で「承認済み：〇〇（処理してください）」（宛先 office・office_crew）。押すと承認センターの「経理の確認」タブ。通知の中にも「確認した」。

経理が処理する種類（`AP_ACCT_TYPES`）：経費・建替経費・ガソリン代・休暇・スキル・採用・退職。予算・月間行動計画・シフト変更は入れない（Claude の判断。違えば 1 行で直せる）。退職は前から「退職手続き開始」が届くので、この知らせは出さない（タブには出る）。

Tip Rate と昇格（Leadership）は、承認センターでは反映しないので、申請の画面で承認して反映したときに「承認済み：Tip Rate／昇格（処理してください）」を出す（開く画面は付けない。Tip Rate・Leadership の画面は経理・事務Crew のメニューに無い。経理の確認タブにも出ない）。

### 3.3 経理の確認タブ（1A）

- 承認が済んで、まだ経理が確認していないもの（v1087 から決まったもの・上の種類）。新しい順。
- 「確認した」で確認した人と日時（`acct`。時刻は決めた時刻より後にする＝端末の時計がずれていても数える）。押せるのは経理・事務Crew。GM・CEO は見るだけ（「経理の確認待ち」）。店舗の役職にはタブが出ない。
- 確認したものは「履歴」に「経理確認：名前 日時」。経理・事務Crew は「確認を取り消す」。
- 承認センターは「承認待ち」「経理の確認」「履歴」のタブになった（前は 1 ページに承認待ちと過去ログ）。

### 3.4 事務Crew（3A・4A）

- 承認待ちの通知：宛先に経理（office）がいれば事務Crew にも出す。ガソリン代・休暇・経費・予算は、初期の承認ルートに経理がいないので、経理にも事務Crew にも出ない（設定の承認ルートで経理を足すと両方に出る。ただし経理の承認も要るようになる）。
- 店舗を決めた通知（`toStore`）は、事務Crew も経理と同じく全店。
- 承認センター・ワークセンターの承認待ちで、事務Crew にも本部の申請（店舗なし）。
- 退職の「退職手続き開始」も事務Crew に。建て替え経費の「承認待ち」も。

### 3.5 事前経費の承認済み

事前経費の画面で、経理・事務Crew にも「承認済み（直近）」を出す（40 件）。承認待ちのカードは今までどおり GM・CEO だけ。
