# ワークセンターの申請 v1132（2 段目：評価の変更 3 種・スキルマトリクスの表示・G4 の直接の変更を止める）

11/02 の依頼の ⑨⑩。UI案68 の決めてほしいこと（答えが無いのでおすすめ＝すべて A）：6A＝G4 は申請だけ（GM の承認を通らないと正式な値は変わらない）・AM（G5）は今のまま／7A＝評価の変更を決めるのは GM・CEO／9A＝スキルマトリクスの表示は「自分の表示設定」として人 × 店ごと。1 段目（v1131・PR #123）の上。

## 1. 今の作り（コードで確かめた・v1131）

- スキル Lv：G4（`curRealRole==='g4'`・役割は am 扱い）はスキルマトリクスの「スキル編集」（`openStaffSkillEdit` → `saveStaffSkillEdit`）で、だれのどのポジションでも直接「承認」の Lv にできる（役割・本人・グレードの確かめなし。`skill_requests` を通らない）。スキルの画面でスタッフの申請（`skill_requests`）も 1 人で承認できる（`submitSkillReview`）。
- Career Score：G4 の採点はもう GM の承認待ち（`lssNeedsApproval`・`lss_requests` の score・承認は `approveLssScoreRequest`）。
- Tip Rate：G4 にも承認と「引き上げ」のボタンが出る（`approveTip`・`applyTipRaise` は役割を確かめない）。
- スキルマトリクスの行：店の在籍の人（所属・応援）。人 × 店の表示・非表示の設定は無い。

## 2. 作り（v1132）

### サーバー（migration `20261105090000_work_requests_eval.sql`・関数 work-requests）

- 種類 skill（SK）・cs（CS）・tiprate（TR）を出せるのは、GM・CEO が確かめた G4（AM・GM・CEO は今までどおり直接）。対象は自分の店の、自分より下のグレードの在籍の人（自分は不可）。
- 同じ人・同じ種類の決まっていない申請（承認待ち・差し戻し中・承認済みで反映前・反映エラー）があれば新しく出せない（`open_same`・その番号を返す）。
- 段階：GM の承認待ち → 承認済み（反映待ち）→ 反映済み。反映に失敗したら「反映エラー」→ GM・CEO がもう一度反映。反映の記録は 1 回だけ（`apply`）。差し戻し・却下は理由が要る。本人は直す・出し直す・取り下げ。
- 適用の開始：スキル・Career Score は承認の日から。Tip Rate は申請で選んだ日（期間の初日）から（反映のときに Tip Rate の画面の確かめを通す）。
- スキルマトリクスの表示：表 `wr_views`（人 × 店・非表示の人の社員 ID・版）。自分の分だけ読める・書ける。
- 1 段目の `wr_submit`・`wr_act`・`wr_actions` は名前を変えて残し（`_exp`）、種類で振り分ける。

### アプリ v1132

- G4：スキル編集の保存は「GM に変更を申請」（変えたポジションだけ）。スキルの申請の承認はスキルの画面ではしない（承認センター：G4 → GM）。Tip Rate の承認・引き上げは出さず「GM に変更を申請」。Career Score の採点は今までどおり GM の承認待ちで、ワークセンターの申請（CS）にもなる。
- GM・CEO：ワークセンターの「申請」で今の値と申請の値の差を見て承認 → その端末で反映（スキル・Career Score）／Tip Rate の画面の確かめを開いて反映。
- スキルマトリクス：「表示対象」（自分の表示設定・店ごと）。非表示にしても評価・Tip・給与・申請の対象は変わらない。
