# 中間レビュー v1122：デモをやめて本番に・中間レビューだけのメールの認証をやめる（10/30 の依頼 ⑥）

Moto さん 10/30 の添付「修正・改善依頼（全7項目）」の ⑥。ブランチ `claude/mid-review-live`（v1121 の上）。SQL `20261102090000_mid_review_live.sql`。アプリ v1122。Edge Function `mid-review` は変えない。

## 1. 原因（v1121 まで）

- 中間レビューは「非公開確認」の段階で作ったので、デモ（架空の店・見本の数字・デモの切り替え・デモを作り直すボタン）が残っていた。デモの記録は本番と同じ表に `env = 'demo'` で入っていた。
- 中間レビューのサーバーは、担当・閲覧設定・期限・確認完了の取り消しなどに **メールのログイン** を求めていた（`mr_need_email`）。PIN のログインで入れるのは、前もって利用者の表（`mr_members`）に社員と結ばれた行がある人だけだった。CEO・GM の行は manager_auth のアカウントから作られ、社員 ID が無いことがあった。
- そのため、メールを登録していない人・メールでログインしていない人は、権限があっても設定を開けず、AM は SQL で足してもらうまで入れなかった。

## 2. 変えたこと

### サーバー（SQL `20261102090000`・関数 7 つの置き換えと、利用者・スイッチの行）

| 何を | どう |
|---|---|
| メールの認証 | `mr_need_email` は何もしない。役職は今までどおり `mr_members` と manager_auth・社員の表で毎回確かめる（`mr_member_role`）。 |
| PIN で入った人の行（`mr_pin_actor`） | 社員の有効な行があればそれ。無ければマスターから作る：**CEO・GM**＝その社員と結ばれた manager_auth のアカウント（ユーザー ID）、**AM**＝社員の表で在籍の AM。SQL で止めた行（CEO・GM・AM）は作り直さない。社員と結ばれていない CEO・GM の行（メールで作られたもの）は、同じアカウントなら結ぶ。設定で staff として作った行の人がいま AM なら am に、CEO・GM ならその行を止めて CEO・GM の行を使う（入力担当は社員で決まるので、ほかは動かない）。同時に 2 回入っても行は 1 つ。 |
| AM | SQL を流したときに、在籍の AM の行を作る（店舗の管轄で選べるように）。退職・止めた人は作らない。 |
| Head Chef・Corporate Chef・入力担当・閲覧者 | 今までどおり GM・CEO が担当・閲覧設定で選ぶ（自動では作らない）。 |
| スイッチ | 「非公開確認」と「本番の店の入力」を ON。店舗公開・通知は OFF のまま。 |
| 権限（`mr_can`・`mr_whoami`） | 設定は GM・CEO（入り方は問わない）。デモの理由（demo）・メールの理由は出さない。 |
| デモ | `mr_store`・`mr_list` はデモを頼まれたら `gone`（410）。`mr_demo_reset` も `gone`。デモの行は表に残す（読まない・書かない）。 |
| 権限の確かめ | 7 つの関数とも、ブラウザの役割（anon・authenticated）からは使えず、service_role だけ。 |

### アプリ v1122（中間レビューの画面だけ）

- デモの切り替え・デモの店・デモの Qコミットのカード・デモを作り直すボタンを外した。帯は「本番の数字（会議タブと同じ・読むだけ）」「店舗公開 OFF・通知 OFF」「PIN でログイン中：名前（役職）」。
- メールのログインの画面・覚えたメールのログインの読み直しを外した。入り方は PIN のログインの印だけ（`window._hwSession`）。同じ人の印が新しくなっても画面と入力は残し、別の人なら前の人の読み込み・入力を捨てる（v1068 の R3 と同じ考え）。
- 言葉：PIN のログインが無い・期限切れ・サーバーがまだ v1122 でない（前のサーバーがメールを求めた）ときの文。
- 保存・提出・返信・確認の流れ、版（v1073）、競合のときの入れ直し（B）、会議タブと同じ数字、Qコミットへの反映（店舗公開のときに ON）は変えていない。

## 3. 過去のデータ

- 本番の店の下書き・提出版・返信・確認・変更の記録は、そのまま使う（書き換えない）。
- デモの行（`env = 'demo'`）は消さない。読まれず書かれない（画面にも数にも出ない）。
- 利用者の表：SQL が在籍の AM の行を足し、staff の行の人がいま AM なら am にする。ほかの行は変えない。止めた行は止めたまま。

## 6. 残ること・限界

- 入力担当が未設定の店は、だれも入力できない（GM・CEO が選ぶ。今までどおり）。店長を自動で入力担当にするかは決まっていない。
- PIN が初期のままの人・店舗のログイン（共有の PIN）は入れない（PIN のログインの印が出ないため・v1061 から）。
- CEO・GM は manager_auth に社員 ID が無いと PIN では入れない（確認の SQL の `ceo / gm accounts without an employee id`）。
- 店舗公開（店のスタッフみんなが見る）・通知は OFF のまま（別の段階）。
- 実機（iPhone・2 台）では確かめていない。Edge Function の 1 ファイル（PIN の確かめ入り）は変えていないので貼り直しは要らない。
