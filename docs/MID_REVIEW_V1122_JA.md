# 中間レビュー v1122：デモをやめて本番に・中間レビューだけのメールの認証をやめる（10/30 の依頼 ⑥）

Moto さん 10/30 の添付「修正・改善依頼（全7項目）」の ⑥。ブランチ `claude/mid-review-live`（v1121 の上）。SQL `20261102090000_mid_review_live.sql`。アプリ v1122。Edge Function `mid-review`：入力担当を 2 人以上にするところだけ変えた（8 節）。

## 1. 原因（v1121 まで）

- 中間レビューは「非公開確認」の段階で作ったので、デモ（架空の店・見本の数字・デモの切り替え・デモを作り直すボタン）が残っていた。デモの記録は本番と同じ表に `env = 'demo'` で入っていた。
- 中間レビューのサーバーは、担当・閲覧設定・期限・確認完了の取り消しなどに **メールのログイン** を求めていた（`mr_need_email`）。PIN のログインで入れるのは、前もって利用者の表（`mr_members`）に社員と結ばれた行がある人だけだった。CEO・GM の行は manager_auth のアカウントから作られ、社員 ID が無いことがあった。
- そのため、メールを登録していない人・メールでログインしていない人は、権限があっても設定を開けず、AM は SQL で足してもらうまで入れなかった。

## 6. 残ること・限界

- 入力担当が未設定の店は、だれも入力できない（GM・CEO が選ぶ。今までどおり）。店長を自動で入力担当にはしない（Moto さん 10/30：指名、複数選択可に → 8 節）。

- 店舗公開（店のスタッフみんなが見る）・通知は OFF のまま（別の段階）。
- 実機（iPhone・2 台）では確かめていない。Edge Function の 1 ファイル（PIN の確かめ入り）は、入力担当を 2 人以上にするために貼り直しが要る（8 節）。

### 関数（Edge Function `mid-review`）

- `access_save`・`month_input_save` で `input_emps`（配列・11 人まで送る・中身は社員 ID の文字）をサーバーへ渡す。`update_app` を 409 に。
- **貼り直しが要る**。PIN の確かめの入った非公開の 1 ファイルは、Moto さんの部品（zip）から作る（リポジトリには置かない）。部品が無いので、Moto さんに添付をお願いしている。
- 関数がまだ前のままでも、データは壊れない：
  - 名簿が 2 人以上の店・月の保存は `update_app` で止まる（何も書かない）。
  - 名簿が 1 人以下のときは、選んだ人の先頭だけが保存される。画面は「保存しました」と出さずに「1 人だけ保存されたかもしれません」と出す（保存したあとの名簿が送った名簿と違うとき）。
  - SQL が前のままでも同じ（返事に名簿が無いので、画面が知らせる）。

### アプリ v1122（担当・閲覧設定）

- 店ごとの基本：入力担当は閲覧者と同じ形（名前の札・× で外す・「人を選ぶ」＋「＋ 足す」）。10 人まで。選んだ人は「人を選ぶ」に出さない。外した人は「外した人（未保存）」と出す（保存するまでは書ける）。
- その月だけ：同じ形。だれも選ばなければ「基本どおり（A・B）」。「基本どおりに戻す」。保存していない変更があれば、ほかの店・月へ移るときと画面を出るときに聞く。
- 先に保存された（`conflict`）ときの入れ直し（B）：入力担当も閲覧者と同じく 1 人ずつ（自分が足した人は足し、外した人は外す。ほかの人が足した人・外した人はそのまま）。前の「2 人とも変えていました」はなくなった。
- 左の店の一覧・店のページの「入力担当：」は全員の名前。
