### A 総労働時間
- 今は「月の総労働時間（h）」と月間計画。今月は計画を「前日までの営業日の割合」で割って比べる（`k2Actuals`）。
- 勤怠を取り込んでいない日を分母から外す考えが無い（売上がある日に勤怠が無いと「暫定」と出すだけ）。休業日の仕込みも同じ合計に入る。
- 業務用アカウントは名前の決まり（`toastSystemAccount`：Order Only・Kiosk・Toast Generic Login・LaLa の Server Default）と、その名前だったことのある Toast ID（`k2SysGuids`）で外す。`isOrderOnlyAccount` は名前の一部（`orderonly` を含む・`order` ちょうど）でも外す。給与・Tip・人件費も `getTipLabor` で Order Only を名前で外している（これは変えない）。
- 日次進捗の人件費率の内訳の「1日あたりの総労働時間」（`laborHoursForYm`）は業務用アカウントを外さず、勤怠のある日で割る（KPI と数字が合わない）。
- 無給休憩：hyper-worker は Toast の timeEntries の出勤〜退勤の時間だけ保存し、breaks を保存していない → 今は引けない。11/13 の決定は「引かない」。

### B アップセル対象商品
- ①〜④：模擬の画面（`tests/e2e-pcsp/upsell-save-v1175.mjs`）で確かめた。店（G3）が選んで保存 → `kpi_config.byStore[店].upsellGuids` に入り、読み込み直しても残る。本部（GM・別の端末）が同じ店を開くと、店の設定ではなく全店共通（`kpi_config.upsellGuids`）を見せ、何もチェックされていない。GM が選んで保存すると全店共通に入り、その店は店の設定のまま（率に効かない）。
- ⑥：選んだ商品は「トッピング/アップセル比率（出数÷客数・`upsellRate`）」にだけ使い、日次進捗の「アップグレード率」（`misoRate`）には使っていない。アップグレード率は hyper-worker がモディファイヤーの名前で数える（crab・today・udon の味噌汁と CHAZUKE ÷ 丼に付けた味噌汁と CHAZUKE）。

- 機会ごと（味噌汁・茶漬け 1 つ）にモディファイヤーとアラカルトを重ねずに数えるには、注文ごとのアラカルトの行とモディファイヤーの Toast ID が要る → hyper-worker（非公開）と SQL を直して取り込み直す（その日から）。

## 2. このコミットで入れたもの（答えを待たずにできる分）

- `k2HoursDays(sid, ym, opts)`：1 営業日あたりの総労働時間の元（日ごとの区分・対象営業日の実働の合計・営業日数・未集計の日・休業日の時間・外した時間・平均）。対象営業日＝月初〜前日・定休日と臨時休業（`dayClosureMode` が closed）を除く・開店日（店舗マスター `openDate`）より前を除く。勤怠を取り込んでいない日は分子・分母から外す。取り込んで 0 時間の日は 1 日。休業日の時間は期間の総実働に入れる。`opts.incomplete` で未集計にする日を足せる（決めてほしいこと 2 の答えで使う）。
- `k2HoursDaysAll(sids, ym)`：全店＝実働の合計 ÷ 延べ営業日数。
- `k2SysMatcher`・`k2SysAcctList`：店ごとの Toast ID の一覧（`kpi_config.byStore[店].sysAcct`）がある店は一覧だけで外す。ID の無い前の勤怠の写しは、一覧のアカウントの名前とちょうど同じ名前のときだけ。一覧が無い店は今までの決まり。
