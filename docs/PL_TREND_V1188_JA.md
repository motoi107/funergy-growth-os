## 2. 会計 PL（管理者セキュアページ）で変わったところ

- タブ「費用」→「推移」（中身を作り直した）。概要のタブは、前の推移のグラフの代わりに同じ 3 つの数を上に出す（その下の FL の表は前のまま）。
  - 店（全社・各店・合算の行）と月を選ぶ。上の 3 つの数と前の月との差（額と ％）。全社で前の月と店の数が違うときは、その店を書いて知らせる（差はそのまま出す）。
  - 最終利益の棒（月ごと・押すとその月を選ぶ）。暫定の月は斜線。数の無い月は棒を描かず「—」（0 と分ける）。
  - 選んだ月の 営業利益 → ＋ その他の収入 → − その他の費用 → 最終利益 の図。その他の費用の中身（本部費・減価償却・ほか）。
  - 月ごとの表（売上 → 原価 → 粗利益 → 人件費 → 販管費（▾ で 変動費・光熱費・固定費・裁量費・要分類）→ 営業利益 → その他の収入・費用 → 最終利益 → 最終利益率）。金額／売上に対する ％。
  - 区分の名前を押すと、その区分の科目ごとの画面（左に科目・右に月ごとの棒・最初の月からの差・売上に対する ％・店ごと）。GM・CEO・経理は「区分を変える」。
- 名前（2A）：月次のタブの「営業利益」の行は前のまま簡易 PL の数で、実 PL の Net Operating Income と比べる。最終利益の行（実 PL の Net Income だけ）を足した。採算のタブの KPI は 最終利益（Net Income）・営業利益（Net Operating Income）・EBITDA・本部費控除後。本部予算のタブの「計画 営業利益」は前のまま（本部予算の計画の言葉で、PL ブックの数ではない）。
- その他の費用（UI案76 の表）は「最終利益 − 営業利益 − その他の収入」から出す（表の足し算が合うように）。その他の収入は v1162 から c に入る。前の版で取り込んだ月（c が無い）は「± その他（収入 − 費用）」の 1 本にまとめる。Net Income の無い店がある月の最終利益は「—」。

## 3. 取り込みの前の差分（6A）

「PLブックを取り込む」でファイルを選ぶと、今までの確かめの画面の上に「保存すると変わること（この端末の PL と比べて）」を出す。

- 数：新しく入る店・月／暫定 → 確定／確定の月で額が変わる（赤）／暫定のまま額が変わる／額は同じ／取り込まない店・月（検算が合わない）。
- 額が変わる店・月の表（変わる額の大きい順）：項目ごとに 今・取り込んだあと・差。両方にセントの数（c）があればセントで、無ければドルに丸めて比べる。片方だけ分からない項目は「変わる」に数えない。
- 新しく入る店・月と、暫定 → 確定 の店・月（会議タブ・中間レビューの印も変わる）。区分の決まっていない科目の数。
- 店ごとの売上の表（前からあったもの）は「売上の表（店 × 月）」の中にたたんだ。ボタンは「この内容で保存する（N の店・月）」。保存の中身・順番は前と同じ。

## 4. 要分類の科目を決める（7A・8A・9A）

- 9A の 3 科目は初期の区分（`PL_EXPENSE_CLASS_DEFAULT`）に足した。ほかの新しい科目は「要分類」のまま。
- 「N 科目・決める」（GM・CEO・経理だけ）：取り込んだすべての月・店の要分類の科目（出ている店・最後の月の額・合計）。区分を選ぶと、選んだ月の全社で区分ごとにいくら移るかを出す（販管費の合計・営業利益は変わらない）。決めた記録（ハワイ時間・だれ・前 → 後）。
- 保存：`pl_expense_class`（app_state の行・`OP_SYNC_KEYS`・合流は `mergeMapByTime`・`cas`・`LS_NEVER_FREE`）。1 科目 1 件 `{c, name, prev, by, at, hist（10 件まで）, _at}`。キーは科目番号を外して名前をそろえたもの（`plClsKey`）＝番号が変わっても同じ科目。
  - 金額・メールは入れない。`by` は社員の名前（メールのログインの社員 ID から）、無ければ役割の名前。
  - 保存はクラウドの行を読み（`_fetchOpRow`）、その最新（＋この端末のまだ送っていない分）で開いたときの `_at` と比べ、読んだ行が変わっていないときだけ書く（`_opCasWrite`）。ほかの端末が先に書いたら読み直して比べ直す（5 回まで）。**クラウドに書けたときだけ**「保存しました（全部の端末で共有）」と出して画面を閉じ、端末の写しを書き換える（`plClsCasSave`・下の 8）。読めない・書けない・オフライン・クラウド同期 OFF なら保存しない（画面はそのまま・押し直せる）。
  - ほかの端末が先に決めていた科目は上書きしない（知らせる）。区分の中身の画面の「区分を変える」も、画面に出したときの `_at` と比べる。
  - 前の形（`'科目':'区分'` の文字）も読む。同じ科目に両方あれば記録の形が先。
- 決めた区分は表示だけに効く（販管費の区分の内訳）。売上・原価・人件費・営業利益・最終利益と、会議タブ・中間レビューの数は変わらない。

## 5. 業務用アカウントの ID の無い前の記録（UI案91・表示だけ）

KPI設定 › 業務用アカウント（GM・CEO・担当の AM）：

- 月を選ぶ（今月〜13 か月前・選んだ月はこの端末のメモリだけ）。選んだ月の打刻から名前を取る。
- 「ID の無い前の記録（名前で決めている）」の表：名前ごとに 外す／数える・理由・日数・時間。人の勤怠はたたんで 1 行。理由は数え方と同じ関数（`k2SysWhy`。`k2SysMatcher` はこれの ex だけ）。
- 「勤怠データでこの月を開く」（取り込み直すのは人が勤怠データの画面で押す）。
- 日次進捗の総労働時間の内訳で、外した時間を「ID で」と「名前で（ID の無い日）」に分けた（合計は前と同じ）。説明の文を本当の決まりに合わせた。
- 数え方・保存は変えていない（ランダムな月 300 通りで v1187 と同じ）。
