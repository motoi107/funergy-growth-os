## 2. OJT の合格（「OJTはGMの承認を通す」）

前：OJT のモジュールが合格になると、`g2AutoReflect` がその場でスキル Lv2（M1・M3・M5 など）と Career Score の分野の下限（2 か 3）を**直接**書いていた（サインした人がだれでも）。

v1135（使い始めたあと）：

- **GM・CEO がサイン・合格にしたとき**：今までどおり直接（GM・CEO は評価の変更を直接決める人なので）。
- **G3・G4・Head Chef・AM がサイン・合格にしたとき**：正式な値は変えず、ワークセンターに「GM に変更を申請」を自動で出す。
  - スキル：上がるポジション（今の Lv が 2 未満）を 1 本の申請（SK）に。同じ人のスキルの申請が決まっていなければ、その申請に**無いポジションだけ**足す（前の申請の値は変えない・聞かない）。全部入っていれば何もしない。
  - Career Score：下限より下の項目を Career Score の申請（前からの画面の承認待ち）と、ワークセンターの申請（CS）に。同じ人の Career Score の申請が決まっていなければ**置き換えない**（止めて GM に知らせる・Career Score の承認待ちに残る＝GM が前からの画面で決められる）。
  - 申請の理由：「OJT 合格の自動反映：M5 マルチタスク（サイン：〇〇）」。
  - 出せなかったとき（同じ人の申請が決まっていない・社員 ID が無い・権限・通信）：GM に知らせる（通知「OJT の合格の反映を GM に申請できませんでした」）。
- **使い始める前**：今までどおり直接。
- 申請しただけでは何も変わらない。GM が承認すると、v1133 の押さえ（30 分・v1134 の 25 分）を通して反映する。

## 3. G3 の申請（6）

- G3＝肩書き・役割のグレードが 3（役割 sl は 3 以上・肩書きで G4 の人は G4）。サーバーも同じ（`wr_grade`：肩書きと役割の大きいほう。GM・CEO が確かめていない人は 3 まで）。
- **Tip Rate**：Tip Rate の画面に「Tip Rate の変更を GM に申請」。自分の店（所属・応援）の、自分より下のグレードの人。引き上げの画面・承認は開かない（G4 と同じ）。
- **Career Score**：Career Score の一覧に、自分の店（所属・応援）の **G2** を出す（見られるのもその人だけ）。採点すると Career Score の申請（承認待ち）＋ワークセンターの申請（CS）。G1・同じ G3・上のグレードは出さない。
- **スキル Lv**：今までどおり直接（申請にしない）。
- AM：OJT の合格の反映を申請に使う（AM がスキル・Career Score を直接変えるのは今までどおり）。
- GM・CEO が確かめていない G4 は、確かめるまで G3 として申請できる（G3 以下の人だけ）。

## 4. 店の表示対象（9B）

- 表 `wr_store_views`（店・非表示の人の社員 ID・版・変えた人と時刻）。サーバーの鍵だけ。
- 読む（`view_get`）：ログインした人みんな。`store_view: true`・`can_edit`（GM・CEO だけ true）・最後に変えた人。
- 保存（`view_save`）：GM・CEO だけ。読んだ版で止める（ほかの GM・CEO が先に保存したら読み直して「もう一度選んでください」）。
- アプリ：ボタン「表示対象（店の設定）」は GM・CEO だけ。帯に「非表示 N 人（GM が決めた店の表示）」。
- 前の「自分の表示設定」（表 `wr_views`）は残すが使わない（9A のあと半日しか使っていない。引き継がない）。
- SQL が前の段（答えに `store_view` が無い）なら表示対象は使わない（全員を出す・ボタンも出さない）。
- 関数の名前は前と同じなので、関数（handler）は変えない（handler のコメント「自分の表示設定」は古いまま）。
