# 2026-10-17 Tip Rate をほかの端末へすぐ出す（アプリ v1091）

依頼：Moto さん 10/17 16:23 HST「Tip Rate を A 端末で更新しても B 端末に即時反映されない不具合を見つけました／Tip Rate を適切に保存し、即時他の端末にも反映されるようにしてください」。

この文書は、コードで確かめたこと・試験で確かめたことと、推測を分けて書く。本番のデータ・端末は見ていない。

## 1. 原因（コードと合成データで確かめた）

- Tip Rate の記録は `tip_requests`（申請・承認・却下・管理者の直接の引き上げ）。保存は人ごとの行 `spl_tip_requests_<名前>`（app_state）に分けて、保存のたびにクラウドへ送っている（`lsSet` → `opMergePush`・合流 `mergeSkillReq`）。**送るほうは動いている。**
- **ほかの端末が取り直すのは、ログインのときの全件の取り込み（`supaPullAllMasters`）だけ。** 通知（`notifications`）や LaLa のタスクのような即時の仕組み（Realtime・60 秒ごとの取り直し）が Tip Rate には無かった。だから B 端末はログインし直すまで前の率のまま。
- あわせて見つけたこと：
  - いまの率（`effectiveTipRate`）は「承認の記録の並びの最後」で決めていた。前からある申請をあとで承認しても、そのあいだに直接引き上げた記録のほうが並びで後ろにあると、承認した率にならない。
  - 同じ申請を 2 台で別々に決めると（片方が承認・片方が却下）、合流は「どちらも決めてあれば手元が勝つ」なので、どちらの端末も自分の決定を残し、端末によって率が違ったままになる。
  - 決める前にクラウドを読み直さないので、古い写しの端末が、ほかの端末で決まった申請を決め直せた。
- 変えていないもの：従業員マスターの「評価係数（Tip Rate）」の欄は、初回勤務日も勤務開始日も空の人にだけ効く（前から）。ほかの人のいまの率は Tip Rate の記録・3 か月・No Tip の期間で決まる。この欄を変えても率が変わらないのは今回の不具合ではない（Moto さんに伝える）。

## 2. 直したこと（index.html・sw.js。SQL・関数なし）

- 決めた時刻 `decAt`（ミリ秒）を記録に残す（承認・却下・直接の引き上げ）。この人の記録のどの決定よりも後の時刻（時計が遅れた端末でも）。
- いまの率は、承認のうち決めた時刻のいちばん新しいもの（`_tipLatestApproved`）。時刻の無い前の記録どうしは今までどおり並びの最後。時刻のある記録は前の記録より新しい。人の詳細（PGD）とシフトの配置の表示も同じ。
- 合流 `mergeTipReq`（tip_requests だけ。skill・Leadership の申請は前のまま）：決めたものが申請中に勝つ（前と同じ）。どちらも決めてあれば決めた時刻の新しいほう。同じ時刻なら却下。時刻のある記録は時刻の無い記録に勝つ。書いたあとの確かめ `_coversTipReq` も、クラウドの決定がこの決定より古ければ「まだ書けていない」。
- 決める前（「承認」「却下」）に、クラウドのその人の行を読み直す（8 秒で打ち切り）。ほかの端末でもう決まっていれば「この申請はほかの端末でもう「承認」になっていました（変えていません）」と出して何もしない。読めなければ、知らせてからこの端末の内容で決める。
- ほかの端末へすぐ：
  - 保存した端末は、その人の行をクラウドへ送り終えたのを待ってから、合図の行 `live_tip_rate`（中身は時刻と書いた人の名前）を書く。送れなかったら「Tip Rate をクラウドへ送れていません。通信が戻ると自動で送り、ほかの端末にも届きます」。未送信キューから送れたときも合図を書く。
  - ほかの端末は、ログインのときから合図の行を Realtime で受け（`rt-tip-rate`）、受けたらすぐ取り直す。Realtime が届かなくても、画面を開いているあいだ 20 秒ごと（合図が一度でも届いた端末は 60 秒ごと）・画面に戻ったとき・Tip Rate の画面（Tip Rate・チップ管理・マイページ）を開いたとき（10 秒に 1 回まで）に取り直す。
  - 取り直すのは、前に読んだ時刻の 5 分前から変わった人の行だけ（`updated_at`・端末の時計の差のため 5 分さかのぼる）。合流なので、この端末のまだ送っていない変更は消さない。同じ行がまた来ても、中身が同じなら書かない・描き直さない。
  - 変わっていれば今の画面を描き直す（Tip Rate・チップ管理の画面なら「ほかの端末で変わった Tip Rate を取り込みました」）。モーダルが開いている・打っている途中なら、次に取り直したときに描き直す。
  - 合図の行は端末に書かない・端末から送らない（`LS_LOCAL_ONLY`）。ログアウトで止める。
- スタッフの申請（Tip Rate の画面・スキルの条件達成から）も同じく合図を書く（承認する人の端末にすぐ出る）。

## 4. 限界・残したこと

- Realtime が本番の app_state で有効か（`supabase_realtime` の publication）は Claude からは見えない。有効でなくても 20 秒ごとに届く（有効なら 1〜2 秒）。
- 端末の時計が 5 分より大きくずれていると、取り直しで拾えないことがある（次のログインで届く）。
- v1090 以前の端末は決めた時刻を書かず、合図も書かない（その端末の変更は、ほかの端末では 20 秒ごとの取り直しで届く。決め直しの比べ方は前のまま）。承認する人・店長・スタッフの端末を v1091 にそろえる。
- 承認センターで Tip Rate の申請を承認しても、Tip Rate の記録は変えない（v1087 から。Tip Rate の画面で承認したときに反映）。
- Leadership の「Tip Rate 申請」の承認は率を変えない（申請に率が無い・前から）。
- 従業員マスターの変更（初回勤務日・役職・店）による率の変わり方は、従業員の表の取り直し（従業員マスターの画面・ログイン）のまま。
