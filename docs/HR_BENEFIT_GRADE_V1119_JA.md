Moto さん 10/30 の依頼「修正・改善依頼（全7項目）」の ⑤。回答（10/30・選択肢）は「今日から」。

## 1. 前の作り（コードで確かめたこと）

- 休暇申請の画面（`openVacationModal`）は、`myGradeNum()` が 2 以上なら福利厚生の種別（有給・Sick・忌引き・出産・結婚・祝日・バースデー）を出していた。
  - `myGradeNum()` はログインした人の権限の役割（`curRole`）から決まる。そのため、G2 でも管理の役割なら出ることがあった。
- HR・福利厚生の一覧（`renderHR`）は、`gradeNum(empGrade(e)) >= paid.minGrade`（`minGrade` は 2）で絞っていた。
  - 今の役職のグレードだけを見ていた。グレードの履歴（昇格・降格の日）は見ていなかった。
- 手動消化の入力も G2 以上だった。
- 決まりの表は「全員」と出ていた。

## 2. 決めたこと

- 対象は、その日のグレードが G3〜G6 の人。
  - グレードの履歴があれば、その記録の適用日から決める（`ghSegments`）。無ければ従業員マスターの今の役職のグレード（`empGrade`・G1-P は G1）。
  - 専門職も、役職名ではなくグレードで決める（役職名からはグレードを読むだけ）。
- G1・G2 は対象外。
  - G2 は **2026-10-30 から**対象外（`BENEFIT_G3_FROM`）。それより前の日は前の決まり（G2 以上）。
  - 前の申請・消化・調整・手動消化の記録は書き換えない。
- グレードが無い人は対象外で「グレード未設定（従業員マスターで設定が必要）」と出す。
- 権限の役割は使わない。見られる人・直せる人（`renderHR` の役割）、付与日数、ほかの決まりは変えない。
