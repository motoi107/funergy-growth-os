# 業務Botの案件終了（1015）

既定では勤怠の修正はToastの正常化確認後に終了する。Void・未決済、変更なし、その他終了は本部確認待ちとし、本部承認で終了、差し戻しで店舗対応へ戻す。GM/CEOは画面の「本部確認の条件」で種類・回答・金額条件を変更できる。複数条件はOR。本部確認待ちになった案件は設定変更や機械照合だけで終了させない。

番号は全店通しの #1 形式。既存案件にも作成順で番号を付け、旧B-番号は返信用別名として保持する。UUIDとsource_keyは変更しない。番号は再利用せず、同じ検知では番号を消費しない。

LINEの明示コマンド（番号と理由が必要）:
- `#123 修正済み 退勤時刻を修正` / `#123 fixed corrected clock-out`
- `#123 確認済み・変更なし 正当な取消` / `#123 confirmed no change valid cancellation`
- `#123 その他・終了 重複案件のため` / `#123 other close duplicate case`
- `#123 対応中 YYYY-MM-DD 対応内容` / `#123 in progress YYYY-MM-DD action`
- 本部: `#123 承認して終了 確認内容` / `#123 approve reason`
- 本部: `#123 差し戻し 追加確認内容` / `#123 return reason`

通知の選択ボタンは入力欄に番号と回答種別を入れる。理由を追記して送信する。自由文、質問、「了解」「完了」のみでは終了しない。古い発注コマンドは維持し、異常案件終了から発注承認を迂回できない。

## 本人・権限登録

メンション登録から回答権限を自動付与しない。本人が有効グループで「担当者登録 名前」と発言し、本部がLINEプロフィールと担当店舗を照合して「LINE回答権限の登録」で登録する。店舗管理者には担当店舗だけ、本部承認者には当該グループの店舗範囲を許可する。本部承認者の登録はGM/CEOのみ。既存のbot_users（事務Crew相当）は完了・本部承認を行えない。未登録のLINE返信は履歴のみ。実在人物の新規権限登録はこの移行には含めない。

## 通知と再検知

朝レポートの勤怠は検知時の各勤務について、開始/終了をHSTの日付付きで表示し、打刻間隔（休憩控除前）と既存設定に基づく理由を示す。退勤未打刻、時刻不正、IN/OUT逆転、重複、日跨ぎを区別。対象者・担当者・進捗・案件番号は同じブロックに保持。最大4勤務を対象優先で表示、残りは画面確認。詳細の取得失敗は明示する。保存された検知時の打刻であり、修正後の最新打刻や給与用の実働時間とは区別する。

本部確認待ち・修正反映待ち・完了には店舗向けの新規催促を送らない。対応継続の期限前は毎朝の催促候補から外す。修正反映が24時間後も確認できず実際の異常が残る場合は対応継続へ戻す。取得エラーを修正失敗と断定しない。

状態変更はトランザクション内で履歴と通知予約を保存。本部確認は既存の朝レポート用本部グループへ、差し戻しは回答元グループ（なければ本部）へ通知する。既存workerの次回実行時に最大5件を配信し、同じLINE retry keyで23時間以内のみ再試行。状態が変わった古い通知は破棄。通知失敗は案件履歴のlifecycle_noticeに残る。
