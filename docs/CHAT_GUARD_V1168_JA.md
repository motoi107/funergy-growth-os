## 1. 決まり（依頼書の 5・6 と UI案79 の答え）

- **個人のチャット暗証番号**：ログインの PIN とは別。本人が任意に決める・変える・外す（初めはオフ）。決めた人は、チャットを開くとき・ロックのあとに入れる（どの端末でも）。
- **グループのキー**：グループごとに任意。そのグループを管理する人が、作るとき・設定画面で決める・変える・外す。参加者でなければキーを知っていても入れない。暗証番号とキーの両方があれば両方。
- キーを変えたら、その会話を開いている端末でもう一度聞く。暗証番号を忘れたら本人の確かめ（ログインの PIN）で外す。キーを忘れたら管理する人が決め直す。
- 暗証番号・キーはそのまま置かない・ログに出さない。続けて間違えたら止める。
- 共有 PC：ログインし直したあと・ロックのあと、暗証番号を決めている人には暗証番号を聞く。決めていない人は本人の確かめ（ログインの PIN・v1167 のまま）。ログアウトで別ウィンドウ・画面・この端末の開けた印を消す。
- サーバーは、一覧・会話・画像・ファイル・リアルタイムの合図を返す前に、ログインした人・参加者か・（必要なら）開けているかを確かめる。
- プッシュ通知は「新着メッセージがあります」だけ（送った人・会話の名前・本文・画像は出さない）。会話から外された・抜けた人には送らない。iPhone はホーム画面に追加したアプリ（iOS 16.4 以上）。

## 2. Claude が決めたこと（Moto さんに伝える・違えば直す）

- 暗証番号は **4〜8 桁の数字**（全角の数字も同じ）。キーは **4〜32 文字**（全角・半角は同じ・前後の空白は無視）。
- 続けて **5 回**間違えると止める：15 分 → 30 分 → 1 時間 … 24 時間まで（正しく入れると数え直し）。数えるのは確かめる**前**（同時にたくさん送っても 5 回で止まる）。キーは人 × 会話ごと。
- 暗証番号を **変える・外す**には今の暗証番号が要る。変えると、ほかの端末は暗証番号をもう一度聞く（変えた端末は開いたまま）。
- **ロック**（今すぐ・操作がない）でサーバーの開けた印から暗証番号の分を消す（キーの分は残す＝ロックのあとは暗証番号だけ聞く）。**ログアウト**で印を全部消す。印は 12 時間・2 時間使わなければ使えない。
- 暗証番号を開けていないとき、新着の**数だけ**は出す（右下のボタン・メニューの数。中身・名前は出さない）。
- キーのある会話の一覧の行：名前・数・時刻だけ（最後のメッセージの中身・送った人は出さない）。キーを入れなくても**抜ける**ことはできる。管理する人はキーを忘れても新しいキーを決められる（前のキーを入れなくてよい）。
- キーを付けられるのはグループと申請のチャット（DM には付けない）。
- 申請の領収書にする（チャットの写真・PDF → 申請）も暗証番号・キーを確かめる。申請に付けたあとの領収書は申請の記録（申請を見られる人が開ける・前のまま）。
- プッシュ通知は 1 つの送り先に 30 秒に 1 回まで・同じ印（tag）で 1 つにまとまる。押すと新しいメッセージのある会話を開く（暗証番号を決めている人は開けてから）。送り先は、ログインのあとこの端末の送り先が前の人のものなら消す（今の人のものにはしない）。
- 暗証番号を決める人は、自分の端末をすべて 1168 にしてから（1167 以前の端末では、その人のチャットが空に見える・送れない）。

## 3. サーバー

SQL `supabase/migrations/20261128090000_chat_guard.sql`（UI案79 の SQL のあと・2 回流しても同じ・`chat_stage` 4）。

- 表（どれも RLS ON・公開の鍵では読めない・書けない）：
  - `chat_guard`：本人の暗証番号の印（PBKDF2-SHA256・150,000 回・塩 16 バイト）・決めた時刻・続けて間違えた数・止める時刻・版。
  - `chat_sess`：開けた印（印そのものでなく sha256）・だれの・暗証番号を開けた時刻・最後に使った時刻・期限（12 時間）。
  - `chat_sess_keys`：開けた印 × 会話 × キーの番号（`key_rev`）。
  - `chat_key_fails`：人 × 会話の続けて間違えた数。
  - `chat_push_subs`：プッシュの送り先（endpoint だけ・だれの・失敗の数）。
  - `chat_threads` に `key_hash`・`key_salt`・`key_iter`・`key_rev`・`key_at`・`key_by`。
- `chat_actor`：どのチャットの関数もここを通る。暗証番号を決めていて、この頼みの開けた印に暗証番号の分が無ければ `chat_pin_required`（暗証番号を変えたあとに開けた分だけ有効）。
- `chat_find`：参加者か（`chat_find_nokey`）→ キーがあれば、この印でこの番号のキーを開けているか（`chat_key_required`）。`chat_msg_find`・`chat_files_access`・`chat_my_mentions`・`wr_receipt_from_chat` も同じ。
- `chat_sync`：暗証番号を開けていなければ数だけ（一覧・合図の印は返さない）。開けていれば一覧（キーを開けていない会話は `chat_row` が中身を出さない）。
- `chat_pin_begin`／`chat_pin_end`・`chat_key_begin`／`chat_key_end`：回数を先に数え、関数が PBKDF2 で比べた結果で開けた印を作る（初めてなら印そのものを 1 回だけ返す）。
- `chat_pin_save`（set・change・clear・reset）・`chat_key_save`（管理する人・`expect` で前のキーの番号）・`chat_relock`（pin・all）。
- `chat_push_save`（暗証番号を開けていること・送り先はブラウザの送り先のサーバーだけ）・`chat_push_drop`・`chat_push_check`・`chat_push_targets`（今の参加者・送った人を除く・30 秒）・`chat_push_result`（410／404 は消す・5 回の失敗で消す）。

関数 work-requests（fn 10）：

- 本文の `unlock`（64 桁の 16 進だけ）を SQL に渡す（形が違えば無いものとする）。
- 暗証番号・キーの印は関数が作る（`secretMake`・`secretOk`・比べるのは同じ時間）。暗証番号を忘れたときの本人の確かめは auth-pin の verify（ログインの PIN・続けて間違えると auth-pin が止める）。
- 送れたら（同じ鍵の送り直しでなければ）答えのあとに裏でプッシュ（`EdgeRuntime.waitUntil`）。中身の無いプッシュ（VAPID・ES256・`TTL` 3600・`Topic`・リダイレクトは追わない）。送り先はブラウザの送り先のサーバー（FCM・Apple・Mozilla・Windows）だけ。鍵は Secrets の `CHAT_VAPID_PUBLIC`・`CHAT_VAPID_PRIVATE`・`CHAT_VAPID_SUBJECT`（無ければ送らない・`push_off`）。
- 頼み：`chat_guard`・`chat_pin_verify`・`chat_pin_set`・`chat_pin_clear`・`chat_pin_reset`・`chat_key_verify`・`chat_key_set`・`chat_relock`・`chat_push_key`・`chat_push_sub`・`chat_push_unsub`・`chat_push_check`。`chat_create_group` は `key` も受ける（作ったあとにキーを決める・決められなければ `key_failed`）。
- エラー：`chat_pin_required`・`chat_key_required`（423）・`guard_old`（SQL がまだ・503）・`push_off`（503）。

## 4. アプリ（v1168）

- 開けた印（`L.utok`）はこのタブのメモリだけ（localStorage・IndexedDB に書かない）。頼みに付けて送る。ロックで暗証番号の分を、ログアウトで全部をサーバーで消す。
- 暗証番号：🛡（チャットの守り）に「チャットの暗証番号（あなた）」（決める・変える・外す・2 回入れる）。決めている人のロックの画面は、端末の種類によらず暗証番号を聞く。「暗証番号を忘れた」→ ログインの PIN で外す。サーバーから `chat_pin_required` が来たらロックする。
- キー：一覧に 🔑 と「（キーで守られています）」。開くとキーの入口（中身・入力欄は出さない・読みに行かない）。管理する人は「参加者」→「グループのキー」と、キーの入口の「新しいキーを決める」。グループを作るときに「キーで守る（任意）」。キーが変わると、開いている会話の写しをメモリから捨ててもう一度聞く。
- プッシュ通知：🛡 の「この端末で受け取る」（押したときに許可を聞く・iPhone の Safari では「ホーム画面に追加したアプリで」と出す）。Service Worker は届いた中身を使わず「Funergy+／新着メッセージがあります」（tag `funergy-chat`）。押すと開いているアプリに知らせる（無ければ `?chat=1` で開く）→ 新しいメッセージのある会話を開く。
- **v1167 の直し**：PC は `body{zoom:1.1}` が掛かるので、パネルの初めの位置・大きさ・動かす・大きさを変えるの計算を zoom で割る（前はパネルが右・下に約 1 割はみ出していた。v1167 の e2e はパネルを動かしてから見ていたので気づかなかった）。

## 7. 限界

- 暗証番号は 4〜8 桁の数字なので、サーバーの印（PBKDF2）が漏れれば総当たりで分かる。守りの中心は回数の制限（サーバー）と、印がサーバーの鍵でしか読めないこと。
- 開けた印はこのタブのメモリだけだが、ロックのあとも（暗証番号の分を消すまでの一瞬）サーバーの印は有効。ロックの頼みが届かない（通信が切れている）と、サーバーの暗証番号の分は 2 時間・12 時間で切れるまで残る（このタブの画面はロックしたまま）。
- ロックのあと、この端末のメモリにある会話（ロックの前に読んだもの）は画面に出さないだけで、タブのメモリには残る（v1167 と同じ）。キーが変わった会話はメモリからも捨てる。
- プッシュ通知の送り先（FCM・Apple など）には「この端末に通知がある」ことだけが伝わる（中身は無い）。送り先の時刻・回数は送り先の会社に見える。
- iPhone は「ホーム画面に追加」したアプリだけ（Safari のタブでは使えない）。実機では確かめていない（この環境に iPhone が無い）。Chrome の Service Worker の表示は確かめた（push の購読は送り先のサーバーにつながらないので代わり）。
- 1167 以前の端末：暗証番号を決めた人のチャットは空に見え、送れない。キーのある会話は開けない（端末を 1168 に）。
- E2EE（端末だけで暗号にする）は今回入れない（UI案79 の 6A・`docs/CHAT_UI79_V1167_JA.md` の 9）。サーバーの鍵を持つ人（Supabase の管理者）は本文を読める。
- チャットの SQL（v1156・v1161・v1167 の ②）をあとで流し直すと守りが外れる（③ の 1・4 で分かる）。
