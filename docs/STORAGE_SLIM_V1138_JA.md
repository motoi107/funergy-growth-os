# v1138：端末の保存領域（localStorage）をいっぱいにしない

- 依頼：Moto さん 11/03 16:37 HST「端末の保存領域がいっぱいにならないようにできますか？保存をいじると毎回この問題が起きるので」。Claude が「2b の前に v1138 として先に」と提案し、17:04 HST「次へ次へどんどん進めてください」。
- アプリだけ（index.html・sw.js）。SQL・Edge Function・サーバーの設定の変更なし。保存のキー・合流の決まり・クラウドへ送るもの・承認・権限は変えていない。
- ブランチ `claude/storage-1138`（PR #129＝v1137 の上）。

## 1. 原因（コードで確かめた）

- v764 で「localStorage と IndexedDB の両方に書く」を始め、v765 から読むのは IndexedDB が先（`_lsStoreGet`）になった。計画の次の段（二重書きをやめる）は入らないまま。
- そのため localStorage の写しは、読まない控えなのに、端末のデータ全部（約 5MB の上限まで）を持ち続けていた。GM・CEO の端末ほど早く埋まる（v1104 の調べ）。
- いっぱいになると、localStorage にしか置けない小さな印（送信待ち op_outbox・直した時刻・シフトや本人確認の送信待ち・送っている途中の印など）が書けない。保存のしくみを変えるたびに「書けなかったときの逃げ道」を足していた（v1104・v1136・v1137）。

## 2. 変えたもの

### 2-1. IndexedDB が使える端末では、大きなデータを localStorage に残さない

- 書くとき（`_lsWriteVerified`）：IndexedDB に積む（今までどおり・すぐ読める）。localStorage にも**すぐ**写しを書き、その前に中身の指紋の印（`_lsj:キー`＝長さと FNV-1a）を書く。閉じられても、次に開いたとき取り戻せるように（IndexedDB の書き出しは 0.3 秒まとめてから）。
- IndexedDB に**入り終えて**（書き出しの complete）、そのキーが**クラウドへの送信待ち・送っている途中・送信中でもなければ**、localStorage の写しと印を消す。
  - 送信待ち（op_outbox）・送っている途中（`_ux_inflight`）・送信中（`_pushBusy`）・シフトの表の送信待ち・従業員の送れていない変更（emp_dirty_q）・本人確認の情報の送信待ち。分からないときは残す。
  - 届いたら（送信待ちから外れたとき・送れた知らせ）すぐ外す。ほかに 1 分ごとに見直す。
- localStorage に写しを書けない（大きな取り込み）とき・とても大きい値（150 万文字より大きい）は、写しを書かずに IndexedDB だけで「保存できた」（v765 と同じ）。前の古い写しは消し（IndexedDB の新しい値と食い違う控えを残さない）、IndexedDB へは待たずに書き出す（同じ時の分はまとめて 1 回・つなぎが切れていたらつなぎ直す）。
- 写しを消すのは、入り終えた中身と localStorage の写し・印がまだ同じときだけ（ほかのタブがそのあと書いた写しは、そのタブのもの）。
- 消すとき（`_lsRawDel`）も印（`d`）を残し、入り終えたら外す。

### 2-2. 起動のとき

- IndexedDB を読み終えた直後（ready の前）：印の残っている写しを取り戻す（入り終える前に閉じられた書き込み・削除）。印と中身が合わない写し（写しを書く前に閉じられた）は使わない。
- 印の種類：（なし）＝書いている途中（必ず取り戻す）・`i`＝IndexedDB を読む前の書き込み・`u`＝IndexedDB を読めなかった起動の書き込み・`c`＝入り終えたが送信待ちなので残している写し（IndexedDB と同じ中身）・`d`＝消した（読めた起動だけ）。
- 取り戻すとき、IndexedDB にその名前があって中身が違えば：`i`・`c` は IndexedDB が勝つ（前の版の「写す」と同じ）。`u` は**送信待ちのキーだけ**取り戻す（合流の決まりのあるキーは IndexedDB の値と合わせる）。送信待ちでないキー・この端末だけのデータ（会計 PL など）は IndexedDB が勝つ（読めなかった起動は大きなデータの無い状態から書いたことがあり、履歴を消さないため。2 回目の独立レビュー P2-1）。IndexedDB が勝ったキーが送信待ちなら、写しを IndexedDB の値に書き直して `c` で残す（読めなかった起動の土台になる）。
- **IndexedDB を読めなかった起動**（開けない・読み込みが返らない）でも、その端末に IndexedDB があれば、保存に印 `u` を残す（印を書けない満杯のときは値だけ）。削除は IndexedDB に届けない（前の版と同じ）。このタブが読む前に書いた `i` は `u` にする（前に閉じたタブの `i` は `i` のまま）。IndexedDB の無い端末では印を消す。送信待ちの値が見えなくても送信待ちから外さない。一度きりの移し替え（起動・ログインのあと・v1136 の移し替え）はしない（次に読めた起動で）。
- IndexedDB を読む前（起動の途中）の書き込みは、IndexedDB にその名前が無いときだけ使う。あれば IndexedDB を残す（前の版の「写す」と同じ。localStorage を空けた端末では、読む前は大きなデータが無いので、空・古い値で上書きしない）。読む前の削除は IndexedDB に届けない（前の版と同じ）。
- そのあと（書き出しが入り終えてから）：**前の版の控え（印の無い写し）を消す**。IndexedDB にある・送信待ちでないものだけ。送信待ちのキーの写しは届くまで残し、中身が違う（前の版で満杯のため古いまま）なら IndexedDB の値に書き直す（`c`）。IndexedDB に無いものは消さない。書き出しを確かめられないときは何も消さない。消したら「設定 › 診断と記録」に「端末の保存領域を空けました（N 件・X MB）」を 1 行。
- 起動のときのデータの移し替え（migrate…・18 個）は、IndexedDB を読み終えてから（`_bootMigrations`）。前は起動の直後に localStorage を読んでいた（空けた端末では空に見える）。マスター自動同期の移し替え（v1137）とキャッシュチップの知らせ（今は何もしない）はそのまま。
- 起動（ログイン画面を含む）は IndexedDB を読み終えるまで待つ（前は 3 秒で先へ進み、そのあいだ localStorage の控えを読んでいた）。3 秒を過ぎたらログイン画面に「端末のデータを読み込んでいます…」。8 秒で返らなければつなぎ直してもう一度（12 秒まで）。開くときの 4 秒の時間切れは、その呼び出しの答えだけを決め、あとで状態を変えない（前からの不具合：つなぎ直しの途中だと使っている途中でも「使えない」になっていた。2 回目の独立レビュー P2-3）。つなぎが切れていたら（iOS）、ふだんの書き出しでもつなぎ直す。それでも返らなければ「使えない」にして localStorage だけで動く（上の `u` の印）。
- IndexedDB を読み終えたら店舗の表を読み直す（`refreshStores`）。棚卸の履歴の月ごとの分け方（`_registerInvHistSplit`）も店舗の表から作り直す（独立レビュー P1-1：LaLa・F07 が分けられなくなっていた）。
- Google Drive の連携の戻り（`checkDriveOAuthReturn`）は IndexedDB を読み終えてから。前の運用キーの送り直し（`migrateUploadLocalOps`・一度だけ）は IndexedDB のキーも見る。
- 「必要時の取り込み」（`_lsRequestDeferredPrefix`）の合流は、手元を IndexedDB から読む（前は localStorage の古い控えと合わせていた）。

### 2-3. localStorage に残すもの（今までどおり）

- 端末だけの小さな印（`_` で始まる・言語・同期 ON・触覚・`heavy_ready`）。
- 送信待ちの記録（op_outbox）・従業員と業者の送れていない変更（emp_dirty_q・vendor_touched_v1）・店舗の表（m_stores：起動の途中、IndexedDB を読む前に読む）。小さく、今までどおり両方に書く。
- アプリの保存の層を通らずに localStorage だけを読み書きするもの（`funergy_` で始まる＝Office の保存のモジュールの記録、`sb-` で始まる＝Supabase のライブラリ）。写さない・消さない（独立レビュー P2-2）。

## 3. 変えていないもの

- 読み方（IndexedDB が先・無ければ localStorage）・キーの一覧（両方）・クラウドへ送るもの・取り込みの合流・送信待ちのしくみ・承認・権限・画面。
- IndexedDB が使えない端末（プライベートモードなど）：localStorage だけ（容量の自動整理もそのまま）。

## 5. 限界（残ること）

- IndexedDB だけが消えた・開けなくなった端末（localStorage は残っている）では、前は localStorage の古い控えで動いた。v1138 からは控えが無いので、ログインでクラウドから取り直す（クラウドが正）。**この端末だけのデータ**（会計 PL の取り込み `pl_actual`・差分の取り込みの記録・業者を読んだときの姿など）は失われる（取り込み直し）。
- 届くまで localStorage にも控えを残すのは、アプリの保存の層（`_lsWriteVerified`）を通る送信待ち（op_outbox・送っている途中・送信中・シフトの表・従業員・本人確認の情報の送信待ち）。業者の送れていない欄（vendor_touched_v1）と従業員の送れていない変更（emp_dirty_q）は今までどおり両方に書く。売上・予算の保護の記録（v1104）は今までどおり IndexedDB だけ。
- ブラウザがサイトのデータを消すときは、localStorage と IndexedDB を一緒に消すので、前と変わらない。
- 前の版と新しい版のタブを同じ端末で同時に開くと、前の版のタブが localStorage にまた控えを書く（次に新しい版を開いたとき空ける）。
- 起動の途中に、クラウドから取り込んだ値で IndexedDB にある名前を書いても、IndexedDB の値が残る（前の版と同じ。起動の取り込みは IndexedDB を読み終えてから始まる）。
- IndexedDB の読み込みが遅い・こわれた端末では、ログイン画面が出るまで最長約 28 秒（開く 4 秒＋読む 8 秒＋開き直す 4 秒＋読む 12 秒）。3 秒を過ぎたら「端末のデータを読み込んでいます…」。前は 3 秒で先へ進んだ。
- IndexedDB を読めなかった起動で、送信待ちでないキー・この端末だけのデータに書いたもの（たとえば会計 PL の取り込み）は、次に読めた起動で IndexedDB の値に戻る（取り込み直し）。送信待ちのキーでも、土台の無いまま（取り込む前・オフライン）合流の決まりの無いキーを直すと、その値で IndexedDB とクラウドを書くことがある（まれ）。
- 読めなかった起動のタブが開いているあいだに、別のタブが読めた起動をすると、送信待ちでない `u` の写しを消す（その開いているタブの表示が空に戻る。IndexedDB の値は残る）。
- IndexedDB が使えない端末は、今までどおり localStorage が埋まることがある（容量の自動整理で逃げる）。
- 本人確認の情報の送信待ちがあるあいだは、`spl_onboardings_` で始まるキーはすべて控えを残す（キーごとに分けていない）。
- 容量の整理（古い勤怠の写しなど）が localStorage の写しを消すと、印だけが残ることがある（次の起動で捨てる。その写しは IndexedDB にある）。
- 前の版のタブと localStorage の満杯が重なると、前の版の古い写しに新しい版の印が残り、次の起動でその古い値を取り戻すことがある（まれ）。別のタブの削除と起動の取り戻しが重なったときも同じ（まれ）。
- IndexedDB を使えない端末（API が無い）では、起動の途中の書き込みの印は起動のあと消す。API はあるが開けない端末では印（`u`）が残る（キーの数だけ・小さい）。

## 6. 入れ方

- アプリだけ。PR #128（v1136）→ PR #129（v1137）→ この PR の順にマージ。端末で「更新」→ 次に開いたとき、自動で空ける（「診断と記録」に記録）。
- 戻すとき：前の版に戻しても、データは IndexedDB にある（前の版も IndexedDB を先に読む）。前の版は localStorage にまた控えを書き始める。
