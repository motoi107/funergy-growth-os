# v1202：紛失届をサーバーの申請へ（8B）を入れる手順

仕様と決めたこと：`docs/UNIFIED_UI_V1191_JA.md` の 25。

- **何が変わるか**：紛失届の「新規」が、ワークセンターの申請（種類「紛失届」・番号 LR-…）になります。GM が承認し、経理が確認して完了です（精算はありません）。経理レビュー › 確認する にも出ます。
- **前からの紛失届**（今の画面の一覧）はサーバーに写しません。今の画面で、前からの申請中のものを承認・差し戻しして終えます。
- **どの順に入れても、そろうまでは今のまま**：アプリ（1202）は、SQL の段 9 と関数 fn 14 の両方がそろったときだけ新しい紛失届を出します。

使うファイル：

| 番号 | ファイル | どこで |
|---|---|---|
| ① | `1_最初に確認_読むだけ.sql` | Supabase の SQL Editor |
| ② | `2_SQL_紛失届.sql`（`supabase/migrations/20261213090000_wr_lost.sql` と同じ） | Supabase の SQL Editor |

## A. Supabase

1. **① を Run**。1 が OK・2 が 8（初めて）か 9（もう入っている）・3 が 0 なら次へ。1 が NG なら止めて Claude に。
2. **② を Run**。「Success」なら次へ。「STOP: 先に…」なら何も変わっていません（① の 1 を見直す）。2 回流しても同じです。
3. **③ を Run**。1〜5 が全部 OK なら次へ。
4. **④ 関数 work-requests を差し替える**：今入っている非公開の 1 ファイル（v1190 のもの）の handler の部分を、このリポジトリの `supabase/functions/work-requests/handler.mjs`（v1202：紛失届 lost・fn 14）に差し替えて作ります。PIN の確かめの部分は今のまま。**Personal（または非公開のファイルを持っている Claude）が作って渡します**（Team のチャットでは非公開のファイルを持っていないため作れません）。Verify JWT は今の設定のまま。
   - 入れたあと、ワークセンターを開いて今までどおり動くこと（申請の一覧・承認）。

## B. アプリ

5. PR をマージし、全部の端末を 1202 にする。
6. 確かめる（実機）：
   - G1（Crew）でログイン → 紛失届 →「新規」→ 申請の画面（買った日・店（業者）・金額・カードを使った人・品目・メモ）→ 申請する → 番号 LR-… が出る。
   - GM：ワークセンター › 申請/承認 で承認。経理：経理センター › 経理レビュー › 確認する に出る → 確認 → 完了。
   - 紛失届の画面の上に「新しい紛失届は…ワークセンターの申請で出します」が出る。前からの紛失届は今までどおり承認・差し戻しできる。

## 戻すとき

- 関数：前の非公開の 1 ファイル（v1190）に戻す（前のアプリ・SQL のままでも動く）。
