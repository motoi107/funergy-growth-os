仕様：`docs/SECURE_STATE_V1139_JA.md`。行・値は動かしません（app_state のまま）。入口を関数 `secure-state` にして、最後に公開の鍵で読めなくします。

使うファイル（`deploy/secure-state-v1139/`。どれもこのまま貼れます。非公開の部品はありません）：

## A. 関数（いつでも。アプリより先でもあとでもよい）

1. **SQL Editor に ① を貼って Run。**表をそのまま Claude に貼ってください（数と決まりの名前だけ。中身は出ません）。
   - 1 行目が STOP なら止める。
   - 7 行目が NG（社員と結ばれていない GM・CEO のメールのアカウント）なら、その人は PIN のログインでは成長カルテ・賞与を読めません（管理者ページは使えます）。Claude に知らせてください。
2. **Edge Functions →「Deploy a new function」→「Via Editor」。名前は `secure-state`。② の中身を全部貼って Deploy。**
   - 「Verify JWT with legacy secret」は **OFF**（関数の中で確かめます）。
   - 鍵の設定（Secrets）は足さなくてよい（SUPABASE_URL などは Supabase が入れます）。
   - work-requests（v1133 以降）が入っていること（PIN のログインの確かめに使います）。

## B. アプリ

3. **v1139 の PR をマージ。**
4. **全員の端末で、アプリの「更新」を押す。**ログイン画面の版が 1139 になれば OK。とくに GM・CEO・経理・AM。
   - 関数が入っていなくても、アプリは今までどおり動きます（関数が入ったら、10 分以内に関数を使い始めます）。
5. **（確かめ）GM・CEO の端末で、ログインしてから「設定 › 診断と記録」を開く。**「成長カルテ・賞与：サーバー（secure-state）から 全部」と出ていれば関数が動いています。スタッフの端末では「本人の画面に使う分だけ」。
   - 出ないときは、Supabase の Edge Functions → `secure-state` → Logs を Claude に。
6. **GM・CEO の PIN が初期のまま（1234 など）なら、自分の PIN に変える。**初期の PIN のままだと、③ のあと PIN のログインの画面で賞与の設定などを読めません（管理者ページは使えます）。

## C. 公開の鍵から外す（全部の端末が 1139 になってから）

7. **SQL Editor に ③ を貼って Run。**「Success」なら次へ。
8. **SQL Editor に ④ を貼って Run。**ok の列に NG が無ければ終わり。
   - 5 行目「anon で読める対象のキーの行」が 0 なら、公開の鍵ではもう読めません。
   - NG があれば、表をそのまま Claude に。

## 変わること

- 成長カルテ（給与・ボーナスの履歴・面談・目標）・賞与（査定・確定した支給額・店の利益・原資）・成長カルテの PIN は、GM・CEO の端末にだけ届きます。ほかの人の端末には、画面が使う分（入社日・自分の「次期の目標」・査定の四半期）だけ。前に届いていた写しは、次のログインで端末から消えます（送れていない変更があるものは残します）。
- 成長カルテの PIN はサーバーで確かめます（端末には置きません。保存は印。5 回まちがえると 10 分止まります）。
- 画面・計算・承認・権限は変わりません。

## 困ったとき

- GM・CEO の端末で成長カルテ・賞与が出ない：
  - ③ の前なら、関数（②）を消すか、アプリを前の版に戻せば今までどおり。
  - ③ のあとなら、まず `戻す_SQL.sql` を流す（公開の鍵でまた読めるようになる＝前と同じ。行は何も変えない）。そのあと Claude に。
- ③ のあと、1138 以前の端末で GM・CEO が保存すると、送れずに送信待ちに残ります（更新して 1139 にすれば送れます）。
