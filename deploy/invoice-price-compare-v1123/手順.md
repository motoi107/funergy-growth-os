# 仕入れの単価の比較（v1123・10/30 の依頼 ②）を入れる手順

Moto さん 10/30「単位あたりで比べる案で進める」。食材管理 › 仕入分析 と、ダッシュボードの「価格変動アラート」を、**経理が確認した invoice** の単価を **1 LB・1 L・1 個（または入数の単位）あたり** に直して比べる形にします。

- 経理が確認した invoice＝人が反映したもの（アプリの登録と同じかもしれない印の無いもの）か、照合済みのもの（仕入れ集計と同じ決まり）。自動で反映したものは照合済みになってから。照合で差異ありにしたものは待つ。
- 比べるのは、同じ店・業者・食材・規格・仕入単位の、前の invoice との比較。数量（何ケース買ったか）では変わりません。税・送料・invoice 全体の値引きは入れません。
- 規格（入数・量）が分からず、仕入単位も重さ・量・個でないものは「比較不可」。同じ invoice に同じ食材・規格で 2 つの単価があるものは「結びの確認」。±50% を超える変化は「要確認」。
- アプリで入れた invoice の価格（新マスター・旧 invoice）は比べ方が違うので比較に入れず、仕入分析の下に「参考」としてたたんで残します。
- 元の invoice・明細・単価の記録・経理の確認・会計の記録は変えません。過去の確認済みの invoice も、比較を作るたびに入ります（書き換えはしない）。

貼るものは **全文をそのまま** 貼ります（書き換える所はありません）。

## 入れる

1. **Supabase → SQL Editor** に `1_追加のSQL_単価の比較.sql` を貼って Run（2 回流しても同じ）。
2. `2_確認のSQL_読むだけ.sql` を貼って Run → **`functions` が 120・`price_compare` が true**（ほかの行は今までどおり）。
3. **Edge Functions → invoice-intake** を `3_関数_invoice-intake_index.ts` に差し替えて Deploy（今の関数に、比較の行を書く所を足しただけ）。
4. （すぐ見たいとき）`4_すぐに作る.sql` を貼って Run → `changed` が true。ふだんは Invoice取込が 5 分ごとに作ります（反映・照合のあと、5 分以内に入ります）。
5. アプリ v1123 をマージ → 仕入分析を開いて、品目・比較単価・前回・増減・仕入日・根拠の invoice が出るか確かめる。

1 で「先に 20261029100000_invoice_purchase_posted.sql を流してください」と出たら、何も変わっていません。Claude に伝えてください。

順番を間違えても壊れません：関数（3）が SQL（1）より先なら、比較を作るところだけ失敗して記録に残り、ほかの取込は今までどおり動きます。アプリ（5）が先なら、仕入分析は「まだ集計がありません」と出て、ダッシュボードの価格変動アラートは出ません（アプリで入れた価格のアラートはもう出しません）。

## 止める・戻す

- 止める：確認済みの仕入れ集計と一緒に止まります（`db/invoice-purchase-stop.sql`）。アプリは「止めています」と出します。
- 関数を前に戻すときは `deploy/invoice-qb-gmail-v1094/3_関数_invoice-intake_index.ts`（比較の行が更新されなくなるだけ）。
- SQL の 3 つの関数は、ほかの何も変えていないので、残しておいても害はありません。消すときは Claude に伝えてください。
