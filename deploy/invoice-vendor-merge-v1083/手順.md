# 業者の統合を入れる（アプリ v1083）

Moto さん 10/15「アプリでインボイスを取り込んでいた時や今も複数の業者名（同じ業者なのに読み取りで若干違う）この複数いる同じ業者を統合したいです / 今も業者マスターの下部に業者名を整理という機能がありますが、統合できません」→ UI案51 → 決めてほしいこと 1〜7 はすべて A。仕様は `docs/VENDOR_MERGE_JA.md`。

- 業者マスターの一番上に **「業者の統合」**：候補（似た名前）・手動で選ぶ・統合の記録（「外す」）。今の「業者名の整理（自動反映）」はこれに置き換えた。
- **まとめる画面**：残す名前・まとめる名前・業者マスターの内容（残すカードのまま、空欄だけほかのカードから埋める）・食材／食材以外（分かれているときだけ選ぶ）・まとめると変わること（Invoice取込の件数を先に見る）。
- アプリ：どの名前をどの業者にまとめたかを共通データに（どの端末でも同じ）。記録の業者名は書き換えず、表示と集計をまとめた名前で。まとめた名前のカードはしまう（消さない）。
- Invoice取込：まとめた業者の名前を残す業者に足し（これから届く invoice はその業者）、締めていない月の書類・照合の記録・商品の対応表と、単価の履歴を付け替える。締めた月はそのまま。同じ番号で 2 件とも反映済みの invoice は付け替えずに知らせる。Drive の名前・QuickBooks は変えない。
- 請求書の登録で、マスターに無い名前に似た業者があれば **「この業者ですか？」**。Invoice取込の 1 件の画面の業者の選択肢は、印字された名前に似た業者が先。
- まとめる・外すのは経理・事務Crew・GM・CEO（Invoice取込と同じメール認証が要る）。AM・シェフは見るだけ。

## 入れる前に

- 仕入れ集計の SQL（`20261019090000`）が入っていること（本番は 10/14 に入れた）。入っていないと SQL は「先に 20261019090000 … を流してください」で止まる（何も変えない）。
- 段階 2・3 の SQL（`20261020090000`・`20261021090000`）は、`1_追加のSQL_段階2と段階3と業者の統合.sql` に入っている（もう入れていても同じ）。段階 3 の関数とアプリ（v1082）は入れなくてよい（この関数とアプリに入っている）。

## 入れる順番

1. **Supabase → SQL Editor** に `1_追加のSQL_段階2と段階3と業者の統合.sql` を貼って Run（段階 2 → 段階 3 → 業者の統合の順に 1 つにしたもの）。
   - 業者の統合：業者の表に「まとめた先」の列を 3 つと、統合の記録の表を 1 つ足し、関数を 4 つ置き換えて 4 つ足す。invoice・明細・設定・Drive は変えない。2 回流しても同じ。
   - 段階 3 がもう入っているのが確かなら、`1_追加のSQL_業者の統合だけ.sql` でもよい（段階 3 が無いと「先に 20261021090000 … を流してください」で止まる。何も変えない）。
2. `2_確認のSQL_読むだけ.sql` を Run → **vendor_merge＝true・multi_file＝true・reconciled_folder＝true・purchase_summary＝true・tables＝19・functions＝81・browser_can_read＝0・browser_can_run＝0**（ほかの行は今までどおり）。
3. **Edge Functions → invoice-intake** を開き、中身を `3_関数_invoice-intake_index.ts` に置き換えて Deploy（JWT の検証は OFF のまま）。
4. アプリ v1083 をマージ（この PR）。端末を更新する。
5. 業者マスター →「業者の統合」→ 候補を 1 つ「まとめる…」→ ④（まとめると変わること）を見て「この内容でまとめる」→ 請求書・Invoice取込・食材の原価で 1 つの業者になったか見る。

順番を入れ替えても壊れない：
- 関数を SQL より先に入れると、まとめる・外す・件数の読み込みが失敗する（何も変えない）。ほかの動きは今までどおり。
- アプリを先に入れると、業者の統合の画面は出るが、Invoice取込を確かめるところで止まる（まとめない・何も変えない）。

## 止めるとき・戻すとき

- 1 つの統合を戻す：業者マスター →「業者の統合」→「統合の記録」→「外す」（新しい統合から順に）。
- 関数を前に戻す：`deploy/invoice-stage3-v1082/3_関数_invoice-intake_index.ts` を貼って Deploy。SQL はそのままでよい。
  - **戻す前に、統合をすべて外す**。前の関数は「まとめた先」を見ないので、まとめた業者の名前が 2 つの業者に当たり、その名前の invoice が「業者がマスターと一致しない」になる。

## 気をつけること

- 締めた月の書類は付け替えない（数字が変わらないように）。まとめる前に別の業者に見えていた、同じ番号で 2 件とも反映済みの invoice は付け替えず、まとめる画面とお知らせに出る（二重に反映されている可能性がある。Invoice取込で見る）。
- 「業者を選ぶ待ち」（印字の名前がどの業者にも無い）の書類は、その名前をまとめると、まとめた業者になる（確認待ちのまま）。
- 確認待ちの書類は、まとめた業者で確かめ直す（1 回に 60 件まで。残りは開いたときに確かめる）。
- まとめた業者の「自動で反映する」は、残す業者の設定のまま。食材／食材以外を選んだときは、これから届く invoice に使う（今までの invoice の区分は変えない）。
- 発注リストは業者の名前ごとのまま（まとめた名前のカードの発注リストも、発注の画面でそのまま使える）。
- 外すと：まとめたときに動かした書類・照合の記録・対応表・単価の履歴を元の業者に戻す（そのあと直した書類はそのまま）。まとめたあとに届いた invoice は、残した業者のまま。
- 前の版の「業者名の整理」でまとめた名前は、押した端末にだけ残っていた（ほかの端末には届いていない）。その名前は「業者の統合」の候補に「以前この端末でまとめた」として出るので、まとめ直す（どの端末でも同じになり、Invoice取込も一緒になる）。
