# 仕入れタブに経理確認済みの invoice を入れる（2026-10-29・アプリ v1112）

Moto さん 10/29 の依頼「予実管理 ＞ 仕入れ に経理確認済みの invoice が入らない」と、決めたこと（確認済み＝人が反映したもの・自動で反映したものは照合済みになってから／QuickBooks へ送ったかは条件にしない）。
原因・変えたこと・試験は `docs/INVOICE_PURCHASE_POSTED_JA.md`。

- 変えるのは **集計の決まり（関数 1 つ）** と、**前の集計を残す表 1 つ** だけ。invoice・明細・照合・名前・QuickBooks の台帳・アプリの invoice・Drive・予算・売上は変えない。
- **QuickBooks へは何も送らない・送り直さない**（台帳はそのまま。送っていない分は「仕入れ」タブに「QuickBooks 未転送」として出るだけ）。
- 締めた月（Invoice取込の設定の「締め」まで）の集計は変わらない（今までの決まり：その月の invoice が変わったときだけ作り直す）。
- 関数（Edge Function）は変えない。

## 入れる順番

0. **Supabase → SQL Editor** に `0_前と後を比べる_読むだけ.sql` を貼って Run → 結果を Claude に。
   - 何も変えない。「前」（今の集計）と「見込み」（新しい決まりを今の集計の各 invoice に当てた数）が店ごとに出る。
   - 「後」はまだ前と同じ（後の決まり＝前の決まり）。
1. `1_追加のSQL_確認済みの決まり.sql` を貼って Run。
   - 今の集計を `invoice_purchase_snapshots` に残してから、決まりを変える（2 回流しても同じ・残すのは 1 回だけ・新しい決まりで作った月は残さない）。
   - 残したものはサーバーの鍵でも書き換え・消去できない。
   - 段階 3（20261021090000）が入っていないと「先に … を流してください」で止まる（何も変えない）。
2. `2_確認のSQL_読むだけ.sql` を Run → **tables 25・purchase_posted true**（ほかの値は今までどおり。functions は 117 のまま）。
3. `3_すぐに集計を作る.sql` を Run → `changed` に `2026-10`。
   - 流さなくても、5 分ごとの取込で作られる。ここから「仕入れ」タブと 10 月の原価率に、人が反映した invoice が入る。
4. もう一度 `0_前と後を比べる_読むだけ.sql` を Run → 結果を Claude に。
   - 「前の出どころ」が「残した集計」、「後の決まり」が `posted_or_reconciled`。「後」が「見込み」と同じなら決まりどおり（入れたあとに反映・照合が進んだ分だけ「後」が増える）。
   - 月を変えて流すこともできる。入れたあとに初めて集計した月（11 月など）は「この月は残していない（前も新しい決まり）」と出る（前の決まりの数は無い）。
5. この PR をマージ（アプリ v1112）→ 端末で「更新」。
   - 画面の言葉が新しい決まりになる（「確認済みのうち QuickBooks 未転送」・「うち経理が反映（照合はまだ）」）。
   - v1111 のままの端末でも数字は新しいものが出る（タイルの名前だけ前のまま）。
6. `4_開始前の分_読むだけ.sql` を Run → 結果を Claude に。
   - 取込の開始日時より前に Drive に入った invoice は、今までどおりアプリの登録で数える（推測で足さない）。アプリに登録が無いものがあるかを見る。

## 気をつけること

- 照合で「差異あり」にした invoice と、Invoice取込で「アプリに同じものがあるかもしれない」と出た invoice は、人が反映していても照合済みになるまで「確認待ち」（アプリの登録と二重に数えない）。
- 自動で反映した invoice は、照合済みになるまで「確認待ち」。
- 締めた月（Invoice取込の設定の「締め」まで）は前の決まりの集計のまま。その月の invoice があとで変わる（照合・訂正など）と、その月全部が新しい決まりで作り直されるので、変えた invoice のほかに、人が反映した invoice もそのとき一度に確認済みになる（その月が 10 月以降なら原価率も変わる）。締めがどの月までかは設定で確かめる。
- 確認済みには照合がまだのもの・QuickBooks へまだ送っていないものも入るので、原価のカードの「確定」はそれらが残っていても出ることがある（未転送は「QuickBooks 未転送」、照合の進み具合は業者ごとの照合で見る）。
- 古い SQL（`20261019090000`・`20261021090000`、`deploy/invoice-purchase-v1077/1_…`、`deploy/invoice-stage3-v1082/1_…` など）を流し直すと、集計の決まりが前に戻る（2 の purchase_posted が false になる）。そのときは 1 をもう一度。

## 戻すとき

`戻す.sql` を Run → `3_すぐに集計を作る.sql`。決まりが前（照合済みかつ QuickBooks 送信済み）に戻り、人が反映しただけの invoice はまた確認待ちになる（10 月の原価がまた低く出る）。
残した前の集計（`invoice_purchase_snapshots`）はそのまま。アプリは v1112 のままでよい（前の決まりの月は「確認済み・未転送」のタイルで出る）。
