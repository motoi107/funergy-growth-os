# v1192 人件費の合計をサーバーで出す（経理・AM の端末に全員の時給を届けない）

仕様・限界：`docs/LABOR_TOTALS_V1192_JA.md`。SQL はありません。

## 入れる順番（この順番で）

1. **関数 secure-state を差し替える**
   - Supabase › Edge Functions › secure-state を開き、このフォルダの `1_関数_secure-state_index.ts` の中身をそのまま貼って Deploy します（Verify JWT は OFF のまま）。
   - この 1 ファイルは `node scripts/build-secure-state-one.mjs` で作ったものです（`labor-core.gen.mjs` → `labor.mjs` → `handler.mjs`）。手で直さないでください。
   - 入れたあとも、前の版のアプリ（1191 まで）の動きは変わりません（前の版は人件費の合計を頼みません）。
2. **PR をマージし、全部の端末を 1192 にする**
   - とくに経理・AM・事務Crew の端末です。ログイン画面の版が 1192 になっていることを確かめてください。
   - この時点の emp-private は前の版なので、経理の端末にはまだ時給が届いています。数字はサーバーの合計を使います（CEO の端末と同じ数になります）。
3. **emp-private を v1192 にする**
   - Supabase › Edge Functions › emp-private を、Claude が直接渡した `emp-private_v1192_index.ts` に差し替えます。このファイルは公開しないため、リポジトリにはありません。
   - これで経理・AM の端末に全員の時給・月給が届かなくなります。本人の分と、ほかの人の連絡先だけが届きます。
   - 1191 以前の端末が残っていると、その端末の人件費は役職の時給で出した仮の値になります。その端末で従業員を保存しても時給は消えません（emp-private v1192 は、経理・AM の保存の時給の欄を使いません）。

## 入れたあとに確かめること（実機）

- CEO の端末と経理の端末で、同じ店・同じ月の予実の人件費と人件費率が同じか。
- 経理の端末の従業員マスターで、ほかの人の時給・月給が出ないか（自分の分は出る）。連絡先を直して保存できるか。
- AM の端末で、担当外の店に「担当外の店（…）」の帯が出るか。

## 戻すとき

1. **先に** emp-private を前の版（v1186・Moto さんの手元の 1 ファイル）に戻します。経理の端末に時給がまた届きます（1192 のアプリのままで動きます）。
2. 関数も戻すときは、`deploy/secure-notifications-v1152/2_関数_secure-state_index.ts` を secure-state に貼ります。1192 のアプリは「関数が前の版」と判断して、今までどおり端末で計算します（時給が届いていれば帯は出ません）。

関数だけを戻して emp-private が v1192 のままだと、経理の端末には時給も合計も無く、仮の値になります。必ず emp-private から戻してください。

## 困ったとき

- 帯「サーバーの関数が前の版です」が出る：1 の Deploy を確かめてください。
- 帯「この権限では人件費の合計をサーバーで読めません」が出る：AM は、GM・CEO が「承認・閲覧の権限の確かめ」で確かめてから読めます。
- 帯「ログインの印が無い」が出る：ログインし直してください。
