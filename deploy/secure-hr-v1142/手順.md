## 変わること

- **応募者・不採用ログ**を読めるのは、今の画面と同じ人だけ（サーバーが決めます）：
  - CEO・GM・経理：全部
  - AM：GM・CEO が確かめた担当の店＋「未分類」
  - G4（GM・CEO が確かめた）：配属の店＋「未分類」
  - 店長・リーダー（SL・G2）・確かめがまだの AM と G4：配属の店
  - 事務Crew・Head Chef・Crew：なし（今の画面でも応募者は出ていません。**前は「過去の不採用者リスト」が全店分出ていましたが、出なくなります**。Moto さん 11/04：全部は CEO・GM・経理だけ）
- 応募者の入力の「過去に不採用の応募者と一致」は、**全店の不採用ログから当たった分だけ**（日付・店・理由・メモ）を出します（Moto さん 11/04）。一覧の「過去応募履歴あり」も同じ。
- **お悩み相談室**：CEO・GM・経理は全部、AM は担当の店、G4・店長（Store Manager）は配属の店（どちらも GM・CEO が確かめた人）、ほかの人は自分の相談だけ（今の画面と同じ）。
- 保存は 1 件ずつで、**クラウドに入ったときだけ「保存しました」**。通信できないときは入力の画面を閉じません（つながってから、もう一度押してください。押し直しても 2 つ入りません）。
- 応募者を直すと、自分が変えたところだけが入ります（ほかの端末で同じところが変わっていたら「同じところが変わりました」と出るので、読み直してからもう一度）。
- 応募者を足す・直すのは、応募者を見られる人だけ（事務Crew・Head Chef は足せなくなります。前は足せても一覧に出ませんでした）。
- 店舗のタブレットのログイン・PIN が初期のままの人は、③ のあと採用・相談を見られません（ログインの印が無いため。v1139・v1140 と同じ）。
- 相談した人・返信した人の名前はサーバーが決めます（端末の言う名前は使いません）。

## 困ったとき

- 「サーバーから読み込んでいます…」のまま：「最新に更新」。続くなら Supabase の Edge Functions → `secure-state` → Logs を Claude に。
- 「このアカウントでは、この操作はできません（見られる範囲の外です）」：その人の範囲の外の応募者・相談です。AM なら、GM・CEO が「承認・閲覧の権限の確かめ」で担当の店を確かめてください。
- 「ほかの端末で同じところが変わりました」：画面に最新が出ているので、確かめてからもう一度押してください（何も消えていません）。
- 「採用・相談の記録をサーバーから読み直せていないので、保存していません」：関数が前の版に戻った（または関数が無い）ときに出ます。「最新に更新」してからもう一度。③ のあとは、関数を戻すまで保存できません。
- 「前の版で送れていなかった採用・相談の変更は送りませんでした」：その端末で 1141 以前に入れて送れていなかった分です。もう一度入力してください（この端末の `_hr_unsent` に控えがあります）。
- ③ の前に関数でうまくいかない：関数を v1141 に戻す（`deploy/secure-settings-v1141/2_関数_secure-state_index.ts` を貼って Deploy）。アプリ 1142 はそのままで、10 分以内に今までどおり REST で読み書きします。
- ③ のあとに見られない・保存できない：まず `戻す_SQL.sql` を流す（この 3 つのキーをまた公開の鍵で読み書きできるようにする。ほかは変えない）。そのあと Claude に。
- 気をつけること：v1140 の戻す SQL（`deploy/secure-cs-v1140/戻す_SQL.sql`）・v1139 の戻す SQL を ③ のあとに流すと、採用・相談のキーも公開の鍵で読めるようになります（それぞれの版より前の決まりに戻すため）。
