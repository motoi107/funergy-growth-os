# Tip の期間の確定と注意ログを「見られる人・決めた人」だけにする手順（v1147・段階 2b の 9 つ目）

仕様：`docs/SECURE_TIP_CF_V1147_JA.md`。行・値は動かしません（app_state のまま）。
読み書きを関数 `secure-state` だけにして、最後に公開の鍵（ブラウザーの鍵）で読めない・書けないようにします（v1139〜v1144 と同じ決まりにキーを足すだけ）。

決めたこと（Moto さん 11/10「読む人も書く人も絞る」。範囲は今の画面と同じ）：

- **Tip の期間の確定（tip_cf_。人ごとの最終チップ額が入る）を見る・確定する**：チップ管理を開ける人の、見られる店だけ。
  CEO・GM・経理・事務Crew（メールのアカウントの役割）＝全店／GM・CEO が確かめた AM＝担当の店と自分の店・応援の店／
  GM・CEO が確かめた Head Chef＝全店／ほかの G2〜G4・店長・リーダー（GM・CEO が確かめた写しのある人）＝写しの店（自分の店と応援の店）／
  確かめがまだの人・G1 など・店のログイン（店舗の PIN）＝なし。
- **店のある範囲は、GM・CEO が「承認・閲覧の権限の確かめ」で確かめた写しで決めます**（Codex #141 の P2-1）。社員の表の役割・店・応援は公開の鍵で書けるので、
  それだけでは見せません。G2（リーダー）も確かめられるように、1b の SQL で写しに入れる人を G2 以上にします。
  同じ決まりを応募者・不採用ログ（v1142）と Career Score の店の人（v1140）にも使います（確かめがまだの人は自分の分だけ）。
- **確定の解除・例外承認**：CEO・GM・経理だけ（今の画面と同じ）。
- **注意ログ（warnings_）を見る**：必須チェックを開ける人の、同じ店（事務Crew は開けない）。
- **注意ログを記録する**：CEO・GM・GM・CEO が確かめた AM・G4・Head Chef。**足すだけ**（だれも消さない・書き換えない）。

## 変わること

- Tip の期間の確定（最終チップ額）と注意ログは、見られる店の分だけが端末に届きます。見られない店の写しは端末から消えます（送れていない変更のある行は残します）。
- 確定の解除・例外承認のボタンは、CEO・GM・経理だけに出ます（今の画面と同じ。サーバーでも確かめます）。
- 注意ログの「記録」のボタンは、記録できる人だけに出ます。**AM・G4・Head Chef は、GM・CEO が「承認・閲覧の権限の確かめ」で確かめた人だけ**（v1131 からの決まり。社員の表は公開の鍵で書けるので）。
- **店の Tip の確定・注意ログ・応募者・不採用ログ・Career Score の店の人を見るのは、GM・CEO が確かめた人だけ**（G2 も。Codex #141 の P2-1）。
  確かめがまだの人は自分の分だけ（前は、確かめがまだの AM・G4・店長も自分の店と応援の店を見られた＝社員の表を書き換えると、ほかの店も見られた）。
  社員の表で応援の店を足しても、GM・CEO が確かめるまでその店は見えません（減らしたときはすぐ見えなくなります）。
- Tip Rate を決める人（GM・CEO など）は、社員の表で自分の名前を変えても、前の名前の自分の申請を決められません（社員の変更記録で前の名前を見ます。Codex #141 の P2-2）。
  前にその人が使っていた名前の、いまのほかの人の申請も、その人は決めません（ほかの GM・CEO が決めてください）。
- 店のタブレット（店舗の PIN）では、チップ管理の確定の欄と必須チェックの警告は「このログインでは見られません」と出ます（未確定・0 件には見せません）。
- マイページの成長の画面の「注意ログ」の欄（名前が入っている警告）は、見られる店の分だけ数え・出します。見られない店の注意ログが送信待ちでこの端末に残っていても出しません（Codex #141 の P2-3）。
  その人の店を見られないログイン（G1 など）では「注意ログなし・良好」ではなく「このログインでは見られません」と出ます。
- Tip Rate を前の期間から効かせるときの確かめ（その人の店のその期間が確定しているか）は、関数が店の名前だけを返します（額は返しません）。Tip Rate を決められる人は店によらず確かめられます。
- 2 台で同じ店を同時に確定・記録しても、両方が残ります（読んだあとにほかの端末が変えていたら、読み直して合わせてから書きます）。

## 困ったとき

- 「この Tip の期間の確定は、このログインでは変えられません（…サーバーが断りました。送信待ちに残しています。…）」と出た：
  - 解除・例外承認なら、CEO・GM・経理に頼んでください。
  - 見られない店の確定なら、その店を見られる人が自分の端末で確定し直してください。
  - そのあと、その端末で（その人のログインのまま）右上の「保存」→「断られたものを外す…」→「外す（クラウドの値に戻す）」で送信待ちから外れます（見られない店の分は、この端末の写しを消すだけ）。
- 「注意ログを記録できるのは、その店を見られる CEO・GM・AM・G4・Head Chef（GM・CEO が確かめた人）です…」と出た：記録できる人に頼んでください。要らなければ同じように外せます。
  AM・G4・Head Chef なのに出るなら、GM・CEO の確かめがまだです（① の 7 行目）。**外さずに**、確かめてもらってから「最新に更新」。
- 「…をサーバーが断りました（形の合わない記録があります…）」と出た：Claude に。
- 「Tip の期間の確定・注意ログを受け取っている途中です…」と出た：ログインし直した直後です。少し待ってから、もう一度押してください。
- ③ の前に関数でうまく読めない・書けない：関数を v1146 に戻す（`deploy/secure-tip-prep-v1146/2_関数_secure-state_index.ts` を貼って Deploy）。アプリ 1147 はそのままで今までどおり（REST で読み書き）。
- G2・店長などが「見られない」と言う：まず GM・CEO の確かめ（1c）がまだでないかを見る（① の 7 行目）。確かめたら、その端末で「最新に更新」。
- ③ のあとに見られるはずの人が見られない・書けない：まず `戻す_SQL.sql` を流す（Tip の期間の確定・注意ログをまた公開の鍵で読み書きできるようにする。ほかは変えない）。そのあと Claude に。
  関数を v1146 に戻すときも、先に `戻す_SQL.sql` を流してください（v1146 の関数は REST で読むので、③ のままだと何も見えなくなります）。
- v1144 より前の戻す SQL（`deploy/secure-pii-v1144/戻す_SQL.sql` など）を v1147 のあとに流すと、決まりの関数が前の形になり、Tip の期間の確定・注意ログもまた公開の鍵で読めるようになります。
  この 2 つだけを戻すときは、この一式の `戻す_SQL.sql` を使ってください。
- ③ のあと、1146 以前の端末では Tip の期間の確定・注意ログを読めず保存できません（送信待ちに残ります）。更新して 1147 にすれば使えます。
