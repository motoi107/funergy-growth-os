## A. 確かめと関数（いつでも。アプリより先でもあとでもよい）

1. **SQL Editor に ① を貼って Run。**表をそのまま Claude に貼ってください（グレード履歴の中身・名前は出ません。人数と大きさだけです）。
   - 1 行目・6 行目が STOP なら止める（Claude に）。
   - 2 行目（RLS）・3 行目（v1141・v1143 の決まりの数）は info のことがあります。そのまま進めてよい。
   - 4 行目（グレード履歴）が NG（全体がオブジェクトでない・600 万字を超える）なら Claude に（GM・CEO も保存できなくなります）。info（形の合わない記録がある・300 万字を超える）も Claude に（保存は止まりません）。
   - 5 行目が info（社員と結ばれていない GM・CEO のメールのアカウント）なら、その人は PIN のログインではグレード履歴を変えられません（メールのログインなら変えられます）。PIN で使う人なら `db/invoice-signin-emp-check.sql` で確かめて manager_auth に社員 ID を入れてください（Claude に）。
2. **Edge Functions → `secure-state` → コードを ② の中身に全部置き換えて Deploy。**
   - 「Verify JWT with legacy secret」は **OFF のまま**。鍵の設定（Secrets）は足さなくてよい。
   - ② は v1144 の関数（Head Chef の確かめ・個人の欄）をそのまま含みます。v1144 の ② をまだ入れていなければ、v1144 の手順（`deploy/secure-pii-v1144/手順.md`）の ①・①b・①c を先に済ませてから、この ② を入れてください。
   - 今のアプリ（1144 以前）は、この関数でも今までどおり動きます（グレード履歴は今までどおり REST で書きます）。

## B. アプリ

3. **v1141〜v1144 の PR をマージしてから、v1145 の PR をマージ。**
4. **全員の端末で、アプリの「更新」を押す。**ログイン画面の版が 1145 になれば OK。とくに GM・CEO・AM・Head Chef・G4・経理・事務Crew の端末（PC・スマホ・タブレットすべて）。
   - 1145 からは、GM・CEO 以外の人がグレードの変わる役職の変更・昇格申請の承認・Leader 昇格を押すと「グレードが変わる変更（G1 → G2）は GM・CEO が行います」と出て、何も変わりません（却下・グレードが変わらない役職の変更は今までどおり）。

   - 関数が v1144 のままでも、アプリ 1145 は今までどおり動きます（グレード履歴は REST で書きます。関数を v1145 にしたら、10 分以内に関数を使い始めます）。
5. **（確かめ・③ の前に）GM か CEO が、アプリを一度閉じて開き直し（関数を v1145 にする前に開いていたアプリは 10 分 REST で書くため）、自分の PIN でログインし、成長カルテ › 「グレード履歴」タブで、記録のある人を 1 人押して、何も変えずに「保存」。そのあと「設定 › 診断と記録」を開く。**
   - 「グレード履歴：サーバー（secure-state v1145）が書きました（役割 GM／CEO）」と出れば OK（関数が決めた人として書いた）。
   - 「公開の鍵（REST）で書きました（関数が v1145 でない…）」と出たら ③ を流さない。② をやり直して、開き直してから、もう一度。

## 変わること

- グレード履歴を変えられるのは **GM・CEO だけ**。サーバーでも確かめます。読むのは今までどおり（どの端末でも賞与の日割りに使えます）。
- グレードが変わる変更（従業員マスターの役職・権限ロール・昇格申請の承認・Leader 昇格）は **GM・CEO だけ**。前は G1 から上がる変更（Crew → Crew Leader など）を AM・Head Chef・G4・経理も保存・承認できました。
- GM・CEO 以外が登録した新しい人には、グレード履歴の「入社の記録」を作りません（計算は同じ。GM・CEO があとで足せます）。
- GM と CEO が同時に別の人のグレード履歴を保存しても、両方の変更が残ります（読んだあとにほかの端末が変えていたら、読み直して合わせてから書きます）。
- GM・CEO でない端末が、クラウドにもう入っているグレード履歴を送り直しても止まりません（書かずに済ませます）。

## 困ったとき

- 「グレードが変わる変更（G1 → G2）は GM・CEO が行います」と出た：その変更は GM・CEO に頼んでください（昇格申請は GM・CEO が承認する）。役職を元に戻せば、ほかの変更は保存できます。
- 「グレード履歴を変えられるのは GM・CEO です（サーバーが断りました。送信待ちに残しています）」と出た：その端末のログインが GM・CEO と確かめられませんでした。ログインし直してから「最新に更新」。続くなら Claude に（① の 5 行目）。GM・CEO でない端末に出たなら、その端末に前の版で書いたグレード履歴が残っています（Claude に）。
- 「グレード履歴をサーバーが断りました（形の合わない記録があります…）」と出た：Claude に。
- ③ の前に関数でうまく書けない：関数を v1144 に戻す（`deploy/secure-pii-v1144/2_関数_secure-state_index.ts` を貼って Deploy）。アプリ 1145 はそのままで今までどおり（グレード履歴は REST で書く）。
- ③ のあとに GM・CEO がグレード履歴を変えられない：まず `戻す_SQL.sql` を流す（グレード履歴をまた公開の鍵で書けるようにする。ほかは変えない）。そのあと Claude に。
- v1143 の `戻す_SQL.sql`（`deploy/secure-settings-v1143/`）を流すと、v1141 の 2 つ以外（v1143 の 8 つとグレード履歴）がまた公開の鍵で書けるようになります。グレード履歴だけを戻すときは、この一式の `戻す_SQL.sql` を使ってください。
- ③ のあと、1144 以前の端末ではグレード履歴を保存できません（送信待ちに残ります）。更新して 1145 にすれば保存できます。
