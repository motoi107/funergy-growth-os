# チャット（DM・グループ・申請のチャット）を入れる手順（v1156：UI案69 の答え）

全スタッフ（G1 から）が、アプリの中で DM・グループ・申請ごとのチャットを使えるようにします。
知らせはアプリの中だけ（数と自分宛ての @）。LINE には送りません。

使うファイル：

| 番号 | ファイル | どこで |
|---|---|---|
| ① | `1_最初に確認_読むだけ.sql` | Supabase の SQL Editor |
| ② | `2_SQL_チャット.sql` | Supabase の SQL Editor |
| ③ | `3_確認_読むだけ.sql` | Supabase の SQL Editor |
| ④ | `work-requests_v1156_index.ts`（非公開・リポジトリには無い・Claude が直接渡す） | Supabase の Edge Functions |

## A. Supabase

1. **SQL Editor に ① を貼って Run。**「STOP」が 1 つも無ければ次へ。
   - 2 の行が 0 なら初めて、5 ならもう入っています（② をもう一度流しても同じ）。
   - 1 が STOP のときは、先に `deploy/work-requests-v1155`（申請の段階 2）を入れる。
2. **SQL Editor に ② を貼って Run。**「Success」なら次へ。
   - エラーなら止めて、エラーの文を Claude に。直してからもう一度 ② を流せば同じ結果になります。
3. **SQL Editor に ③ を貼って Run。**「result」の列に NG が 1 つも無ければ次へ。
   - 9 が「—」なら Realtime がありません。チャットは動きます（新しいメッセージは 1 分ごとに確かめる）。
4. **Edge Functions で `work-requests` を開いて、④ の中身を全部貼って Deploy（Verify JWT は OFF）。**
   - ④ は申請（ワークセンター）も今までどおり動かします（v1155 の中身にチャットを足したもの）。

## 決まり（Moto さんの答え 11/03「全部 A」）

- **だれと**：だれとでも DM・グループを作れる（3A）。店のタブレット（店舗の PIN）では使えない（だれが書いたか分からないため）。
- **申請のチャット**：申請した人・決める人・確かめる人が自動で入る（4A）。ほかの人は参加者か GM・CEO が加える。自動で入った人は、その申請を見られなくなったら読めない。
- **直す・消す**：自分のメッセージは 24 時間まで直せる（「編集済み」）・いつでも消せる（「削除されました」）。GM・CEO はほかの人のメッセージを理由つきで見えなくできる（元に戻せる・本文はサーバーに残る）（5A）。
- **送り方**：Ctrl（Mac は ⌘）＋ Enter で送る。Enter は改行。日本語の変換中は送らない。
- **@**：参加者にいない人を @ すると「参加者に加えて、これまでの会話を見せますか？」と聞く。
- **送れなかったとき**：「もう一度送る」「消す」。同じメッセージが 2 つにはならない。
- **既読**：自分のメッセージに「既読 N」。
- **この端末には残さない**：書きかけ・送れなかったメッセージはこのタブの中だけ。ログアウトで消える。
- **添付（写真・PDF）**：あとで（6A）。
