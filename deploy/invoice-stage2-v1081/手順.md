# invoice 取込 段階 2 を入れる（アプリ v1081）

Moto さん 10/14 の「経理のinvoice処理追加変更点」（UI案50・決めてほしいこと 1〜8 は A）の段階 2。仕様は `docs/INVOICE_ACCOUNTING_REQUESTS_JA.md`。

- 照合済みにした原本は、店舗フォルダの中の **「照合済み / 年-月」**（請求日の月。例 `照合済み/2026-10`）へ移す。店舗フォルダの直下や「○月 Uploaded」に置いた原本も移す。名前は今までどおり反映のときに変える。
- **Packing list** は AI が見分けて invoice として扱う（自動では反映しない。経理が 4 項目を確かめて反映する）。同じ業者・店舗・請求日・合計の invoice があれば「重複の可能性」を出す（片方を「重複にする」）。
- 人が店舗を選んだファイルは、自動では反映しない（要確認に戻る。まとめて反映はできる）。
- 読み取れなかった書類は、値を入れても「読み取れない」のまま（読み直すか対象外に）。
- 要確認の一覧の順が、同じ日付・時刻の行でもページをまたいで変わらない。

## 入れる前に（確かめるだけ）

- 今の設定の「原本を月ごとのフォルダに整理する」が ON か OFF か（設定タブ）。
  新しいスイッチ「照合したら原本を『照合済み / 年-月』フォルダへ移す」は、決めるまではこのスイッチと同じに動く。
  - 今 ON なら：入れたあと、照合済みの原本は新しい場所（照合済み / 年-月）へ移る。店舗フォルダの直下や「○月 Uploaded」の原本も移る。
  - 今 OFF なら：入れたあとも何も移らない。移したいときは新しいスイッチだけ ON にする。
  - 新しいスイッチを決める前に「整理する」だけを変えると、新しいスイッチはそのときの動き（変える前の「整理する」と同じ）のまま残る。
  - 関数を前の版に戻すと、新しいスイッチは見られない（前のスイッチだけで動く）。
- すでに照合済みで、前の場所（年 / 月 / 照合済み）にある原本は動かさない（新しく照合したものから）。

## 入れる順番

1. **Supabase → SQL Editor** に `1_追加のSQL_照合済みフォルダ.sql` を貼って Run。
   - フォルダの役割を 2 つ足し、関数を 5 つ置き換えるだけ（invoice・明細・設定・Drive は変えない）。2 回流しても同じ。
   - `20261012120000`（反映したら名前を変える）が入っていないと「先に … を流してください」で止まる（何も変えない）。
2. `2_確認のSQL_読むだけ.sql` を Run → **reconciled_folder＝true・browser_can_read＝0・browser_can_run＝0**（ほかの行は今までどおり）。
3. **Edge Functions → invoice-intake** を開き、中身を `3_関数_invoice-intake_index.ts` に置き換えて Deploy（JWT の検証は OFF のまま）。
4. アプリ v1081 をマージ（この PR）。端末を更新する。
5. 設定タブで「照合したら原本を『照合済み / 年-月』フォルダへ移す」を確かめる（GM・CEO）。ON にして、1 件照合 → 5 分以内に Drive の店舗フォルダの「照合済み / 年-月」に入るのを見る。

順番を入れ替えても壊れない：
- 関数を SQL より先に入れると、照合済みの原本を移すときにフォルダを記録できず「整理のエラー」になる（取込状況に出る。SQL を入れたあと自動でやり直す）。ほかの動き（読み取り・反映・名前・QuickBooks）はそのまま。
- アプリを先に入れても、関数が前のままなら Packing list の印は付かない（選んだ Packing list は「書類の種類が分からない」のまま保存できない）。SQL と関数を入れてから使う。

## 止めるとき・戻すとき

- 照合済みの原本を移すのを止める：設定タブで新しいスイッチを OFF（すでに移した原本はそのまま）。
- 関数を前に戻す：`deploy/invoice-purchase-v1077/3_関数_invoice-intake_index.ts` を貼って Deploy。SQL はそのままでよい（前の関数とも合う）。

## 気をつけること

- 店舗フォルダの外にある原本は動かさない（取込状況に「店舗フォルダの外」と出る）。
- 照合を取り消すと、「照合済み / 年-月」から「年 / 月 / 未照合」へ出す（前に置いてあった「○月 Uploaded」には戻さない）。
- 店舗フォルダの「照合済み」を店舗の外（アーカイブなど）へ移したら、その中の原本はもう動かさない。次に照合した原本には、店舗フォルダに新しい「照合済み」を作る。
- 同じ業者・店舗・請求日・合計の書類が 2 つあると「重複の可能性」が出る（Packing list が関わるときだけ。番号の違う invoice どうしは今までどおり出さない）。日付や合計が違う invoice（税・重量など）は見つけられないので、Packing list を反映するときは同じ納品の invoice が来ていないかも見る。
- AI の読み方の版が上がる（`intake-2026-10-15.1`）。前に読んだ原本は読み直さない（AI に頼むのは新しく届いた原本だけ）。
