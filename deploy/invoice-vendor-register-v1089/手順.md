# 新しい業者を決める を入れる（アプリ v1089）

Moto さん 10/16 08:54 HST ③「インボイス取り込みで、新しい業者を検知した場合に、統合（読み間違い等で）か新規登録かを選択して選べるようにしたい」→ UI案52 → 10:58 HST「全部Aでお願いします」（9A・10A・11A）。仕様は `docs/VENDOR_DECIDE_V1089_JA.md`。

- 要確認の一覧で「業者がマスターにない」行と、1 件の画面に **「業者を決める」**。印字された業者名と、似ている業者（綴りが少し違う・Inc. などを除くと同じ・名前の一部が同じ）を出す。
  - **今の業者に統合**：業者マスターの「業者の統合」と同じ（印字名をその業者の名前として覚える。記録が残り、業者マスターの「業者の統合」から外せる）。
  - **新しい業者として登録**：業者名（印字のまま、または直す）と食材／食材以外。Invoice取込とアプリの業者マスターの両方に作る（11A）。もうある業者と同じ名前は登録しない（統合をすすめる）。
  - どちらも、同じ印字名で待っている invoice もその業者にする（9A。締めていない月・1 回に 60 件まで）。
- 決めるのは経理・事務Crew・GM・CEO（10A）。Invoice取込と同じメール認証。
- 1 件の画面の「マスターから選ぶ」は、業者が決まっていない invoice では「業者を決める」に置き換えた（前は選ぶと印字名を黙って覚えていた）。

## 入れる前に

- 業者の統合（`20261022090000`・v1083）の SQL が入っていること。入っていなければ、`1_追加のSQL_段階2と段階3と業者の統合と新しい業者.sql` を使う（段階 2・段階 3・業者の統合・新しい業者を順に 1 つにしたもの。もう入っている部分は同じになる）。
- 仕入れ集計の SQL（`20261019090000`）は 10/14 に入れた。入っていないと SQL は「先に 20261019090000 … を流してください」で止まる（何も変えない）。

## 入れる順番

1. **Supabase → SQL Editor** に `1_追加のSQL_段階2と段階3と業者の統合と新しい業者.sql` を貼って Run。
   - 業者の統合（v1083）がもう入っているのが確かなら、`1_追加のSQL_新しい業者だけ.sql` でもよい（業者の統合が無いと「先に 20261022090000_invoice_vendor_merge.sql（業者の統合）を流してください」で止まる。何も変えない）。
   - 新しい業者：関数を 2 つ足すだけ（invoice・明細・業者・設定・Drive は変えない）。2 回流しても同じ。
2. `2_確認のSQL_読むだけ.sql` を Run → **vendor_register＝true・vendor_merge＝true・multi_file＝true・reconciled_folder＝true・purchase_summary＝true・tables＝19・functions＝83・browser_can_read＝0・browser_can_run＝0**（ほかの行は今までどおり）。
3. **Edge Functions → invoice-intake** を開き、中身を `3_関数_invoice-intake_index.ts` に置き換えて Deploy（JWT の検証は OFF のまま）。
4. アプリ v1089 をマージ（この PR）。端末を更新する。
5. 経理センター → Invoice取込 → 要確認で「業者を決める」を 1 つ押して確かめる（統合なら業者マスターの「業者の統合」の「統合の記録」に出る。登録なら業者マスターにカードが出る）。

順番を入れ替えても壊れない：
- 関数を SQL より先に入れると、「新しい業者として登録」と「この業者にする」が失敗する（何も変えない）。「今の業者に統合」とほかの動きは今までどおり。
- アプリを先に入れると、「新しい業者として登録」と「この業者にする」は「Invoice取込のサーバーが前の版のままです」と出て止まる（何も変えない）。「今の業者に統合」は v1083 の関数でも動く。

## 止めるとき・戻すとき

- 統合を戻す：業者マスター →「業者の統合」→「統合の記録」→「外す」。
- 登録した業者が間違いだったとき（本当はもうある業者だった）：業者マスターの「業者の統合」で、その業者ともうある業者をまとめる（書類も付け替わる）。
- 関数を前に戻す：`deploy/invoice-vendor-merge-v1083/3_関数_invoice-intake_index.ts` を貼って Deploy。SQL はそのままでよい（足した 2 つの関数は呼ばれなくなるだけ）。登録した業者・統合はそのまま残る。

## 気をつけること

- 新しい業者は確認モード（自動で反映しない）から始まる。自動にするのは今までどおり GM・CEO（Invoice取込の設定）。
- 締めた月の待っている invoice はそのまま（その invoice を開いて「業者を決める」を押すと、その 1 件だけ直す）。1 回に 60 件まで直す。残りは、もう一度「業者を決める」を押すと続きを直す（「もう〇〇の名前です」と出て、その業者にする）。
- 印字名が 2 つ以上の業者の名前になっているときは、どちらか決められないので、その invoice の業者を選ぶだけ（名前は覚えない）。Invoice取込の設定の業者で、どちらかの名前から外す。
- 印字が無い（読めなかった）invoice は、選んだ業者・登録した業者をその invoice だけに付ける。
- アプリの業者マスターのカードは、同じ名前のカードがあればそれを使う（作らない）。区分が空なら選んだ区分を入れる。カードの ID は Invoice取込の業者と同じにする（あとで「業者の候補」を流しても 2 つにならない）。
