# 従業員の変更記録を入れる手順（2026-10-29）

なぜ：従業員の表は、アプリの公開の鍵で書けます（前から）。Toast での名前（別名）・Tip Rate（評価係数）・名前・役割・肩書き・権限・店・応援店が変わると、勤怠とチップの配分が変わります。書き込みを止める作業（人ごとの権限）はあとの段階で行います。いまは「いつ・だれの・どの欄が・前 → 後」を残し、気づけて元に戻せるようにします。

変えるのはデータベースだけです。アプリ（index.html）・関数（Edge Function）・従業員の表の中身・書き込みの決まりは変えません。記録に失敗しても、従業員の保存は止まりません。

## 入れる順

1. Supabase の SQL Editor で `1_追加のSQL.sql` を流す（2 回流しても同じ）。
   - 「社員の表（employees）がありません」「id・data の列がありません」と出たら、何も変わっていません。その文を Claude に。
2. `2_確認のSQL_読むだけ.sql` を流す。上の 3 行が「OK」なら入っています。
   - 「退職の守り（v1085）もそのまま」が「無い」でも、v1085 の SQL を入れていなければそのままで大丈夫です。
   - 「これまでの記録の数」は、入れた直後は 0 行です。

## 見方

`3_変更記録を見る_読むだけ.sql` を流すと、30 日分の変更が新しい順に出ます（読むだけ）。

- 日数は SQL の中の `30`、特定の人は `''` の中に名前の一部を入れます。
- 「鍵」が `anon` の行はアプリからの変更です（正しい操作でも、アプリを改変した書き込みでも `anon`。だれが押したかまでは分かりません）。
- 心当たりの無い変更（とくに別名・Tip Rate）があれば、その行の「記録 ID」を Claude に伝えてください。元に戻す SQL を渡します（この手順の中では戻しません）。

## 止めるとき

`止める.sql` を流すと見張りだけ外れます（記録は残ります）。また始めるときは `1_追加のSQL.sql` をもう一度流します。

## 気をつけること

- 記録の表はサーバーだけが読めます（公開の鍵では読めない・書けない）。中身には従業員の名前と欄の値が入るので、結果を外に出さないでください。
- 記録が残るのは、入れたあとの変更だけです。入れる前の変更は分かりません。
