# 確認済み invoice の仕入れ集計を入れる（アプリ v1077）

Moto さん 10/14 の依頼と決定（照合済み＝経理確認・業者の区分で仮分類・明細の割合で按分・見るのに認証なし・予実管理の原価率は 2026 年 10 月から確認済みで・請求明細との照合は業者ごと・台帳の前の原本は照合済みなら入れる）。仕様は `docs/INVOICE_PURCHASE_SUMMARY_JA.md`。

## 入れる前に（確かめるだけ）

- Invoice取込の設定で、QuickBooks の **送り先（qb.to）** と **送り始め（qb.since）** が今の転送と同じこと（10/13 7:00 HST から台帳が動いている）。
  集計は「その送り先に送った記録」で確認済みにする。送り先が違うと、照合済みでも「未転送」に出る。

## 入れる順番

1. この PR をマージ（アプリ v1077）。端末を更新する。
   - 集計がまだ無いので、何も変わらない（今までの数え方のまま）。
   - 先にアプリを入れるのは、古い版（v1076 まで）の端末がログインのたびに集計の行をまとめて取るのを減らすため（v1077 は見る月だけを取る）。
   - マージしただけでは端末の更新は終わらない。2 に進む前に、使っている端末（とくに GM・CEO・経理・店長）が v1077 になったかを確かめる。古い版の端末は 10 月の原価率を今までの数え方で出すので、端末によって数字が違って見える。
2. **Supabase → SQL Editor** に `1_追加のSQL_仕入れ集計.sql` を貼って Run。
   - 表 2 つと関数 4 つを足すだけ（invoice・明細・照合・QuickBooks の台帳・アプリの invoice・Drive は変えない）。2 回流しても同じ。
   - `20261012120000`（反映したら名前を変える）が入っていないと「先に … を流してください」で止まる（何も変えない）。
3. `2_確認のSQL_読むだけ.sql` を Run → **表（2）＝2・関数（4）＝4・ブラウザーから読める表＝0・動かせる関数＝0**。
   （「集計がある月」はまだ空でよい）
4. **Edge Functions → invoice-intake** を開き、中身を `3_関数_invoice-intake_index.ts` に置き換えて Deploy（JWT の検証は OFF のまま）。
   - 5 分ごとの動きと、反映・訂正・照合・対象外・QuickBooks の結果のあとに集計を作り直すようになる。
5. （すぐ見たいとき）`4_すぐに集計を作る.sql` を Run → もう一度 3 を Run → 「集計がある月」に `2026-10`。
   - 流さなくても、4 のあと 5 分以内に作られる。
   - ここから **予実管理 ›「仕入れ」** に数字が出て、**10 月の原価率が確認済み（照合済み・送信済み）の invoice で出るようになる**（会議・ダッシュボード・PL・成長カルテの原価も同じ）。
     今は照合済みが少ないので低く出る。経理が照合を進めると上がっていく。9 月以前と、Drive の取込の外の店は今までのまま。
6. `5_照合の結果_読むだけ.sql` を Run して、結果を Claude に貼る（店舗・月ごとの照合の報告を作る）。

順番を入れ替えても壊れない：SQL と関数を先に入れても、アプリ v1077 が入るまで画面は今までどおり（古い版の端末が集計の行を取るだけ）。関数を SQL より先に入れても、SQL が入るまで集計を作らないだけ（反映・照合などはそのまま動く）。

## 止めるとき・取り消すとき

`止める.sql` を Run。アプリはすべての月で今までの数え方（Drive の写しを含む invoice の合計）に戻り、「仕入れ」タブは「止めてあります」と出す。何も消さない。
再開は `4_すぐに集計を作る.sql`。

取り消すときも **先に `止める.sql`**（アプリが今までの数え方に戻る）。そのあと関数 invoice-intake を前の版に戻してよい。
集計の表と関数は残しておいても何もしない（消さなくてよい）。

## 気をつけること

- 集計はアプリの共通データ（app_state）に書くので、アプリを使う人はだれでも読める（Moto さん「だれでも見れるように」）。画面に出すのは今までどおり自分の店だけ。ほかの共通データと同じく、技術的にはアプリの鍵で読み書きできる（業者名・invoice 番号・原本のファイル名と Drive のファイル ID・照合した人の名前とメモが入る）。書き換えられた行は 5 分以内に作った中身で新しい版として書き戻し、端末は取り直す（端末は画面を開くたびにも 1 回確かめる）。照合の報告（5）はサーバーが書いた中身から読むので、書き換えの影響を受けない。
- 請求明細との照合（「そろった」の記録）は、Invoice取込と同じメール認証（経理・事務Crew・GM・CEO）。締め済みの月には書けない。
- 締め済みの月（Invoice取込の設定の「締め」）の集計は、締めたときに 1 回作り直す。そのあとは、その月の invoice が変わったとき（締めたあとに照合した・QuickBooks へ送った・訂正した）だけ作り直す。商品マスターや業者の名前・区分を変えただけでは変えない（締めを戻すと、また作り直す）。
- ログインのときのまとめ取りには集計を入れない（端末は見る月の集計だけを取る・10 分ごとに一覧を確かめる）。
- 仕入れは消耗品を除いた額。棚卸（期首・期末）は今までどおりなので、棚卸に消耗品を入れている店は、消耗品の在庫の増減が原価に出る。
- 集計が 3 時間より前から確かめられていない（5 分ごとの動きが止まっている）ときは、「仕入れ」タブと予実管理の原価率の内訳に出る。
