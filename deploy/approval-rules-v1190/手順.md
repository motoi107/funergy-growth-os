仕様と確かめたこと：`docs/APPROVAL_RULES_JA.md`

- **入れてもすぐには何も変わりません**。CEO・GM が「承認・閲覧設定」の画面で 16 種類のルールを確かめて有効にし、「共通ルールで動かす」を押すまで、今までの決まりのまま動きます。
- 画面（「設定 → 承認・閲覧設定」・申請のルートの表示・一括承認の結果）は**次の PR** です（UI案93）。この PR はサーバーと試験だけで、アプリの版は変わりません。

## A. Supabase

1. **SQL Editor に ① を貼って Run。**「STOP」が無ければ次へ。
   - 2 が「0（初めて）」なら初めて。「1」ならもう入っています（② をもう一度流しても、決めたルール・代理・記録は残ります）。
   - （参考）は数だけです。**表は Claude との会話にだけ貼ってください**（GitHub には貼らない）。
   - 「CEO・GM のアカウント（社員と結ばれている数 / 全部）」の 2 つの数が違うとき：社員と結ばれていない CEO・GM のアカウントは、共通ルールで動かしたあと承認できません（役割は社員 ID で決まる）。`db/invoice-signin-emp-check.sql` で確かめて、社員 ID を入れてください。
   - 「まだ確かめていない AM・Head Chef」が 1 以上：その人は、GM・CEO が「承認・閲覧の権限の確かめ」で確かめるまで、共通ルールでは AM・Head Chef として承認も閲覧もしません（今までと同じ考え方）。
2. **SQL Editor に ② を貼って Run。**「Success」なら次へ。
   - 「STOP: 先に…」なら何も変わっていません。① の案内のとおりに。ほかのエラーなら止めて、エラーの文を Claude に。
   - ② のあとも今までどおり動きます（今の関数 work-requests のままでも。試験で確かめた）。
3. **SQL Editor に ③ を貼って Run。**「result」の列に NG が 1 つも無ければ次へ。
   - 1〜4・6・7 が NG：② をもう一度流してください。
   - 3 だけ NG：② のあとに申請の前の SQL（v1131〜v1184 のどれか）をもう一度流しています → ② をもう一度。
   - 5 が NG：Claude に。
   - （参考）「共通ルールで動いているか」は入れたばかりなら `false`、「ルール」は `0 / 16`（全部下書き）、「ルートが付いている承認待ち」は `0 / 0` です。
   - （参考）「承認上の役割の人数」は、従業員マスターとアカウントから決まった人数です（例：`ceo 1・gm 1・am 2・chef 1・acct_mgr 1・office_crew 1`）。思っている人数と違えば Claude に（名前は会話にだけ）。
4. **④（関数 work-requests）は、Claude が渡してから。**
   - 今の非公開のファイル（PIN の確かめ入り）に新しい処理（ルール・代理・一括承認）を足して作ります。済（11/17 19:55 HST）：Moto さんが今のファイルを添付 → Claude が `work-requests_v1190_index.ts`（sha256 の先頭 `59a201315ee9`）を直接渡しました（リポジトリには入れない）。
   - 添付のファイルは「事務Crew と確かめる」の直し（v1184 の作り直し）の前の版でした。④ を貼ると、その確かめも効くようになります。
   - Edge Functions で `work-requests` を開いて、④ の中身を全部貼って Deploy（Verify JWT は OFF のまま）。
   - ④ を貼らなくても壊れません（新しい処理が使えないだけ）。② の前に ④ を貼っても壊れません（新しい処理は「SQL がまだ」と出る）。

## B. GitHub

5. **この PR をマージ**（サーバーのコード・SQL・試験・文書だけ。アプリは変わりません。端末の更新は不要）。

## C. 使い始め（次の PR の画面ができてから・CEO・GM）

6. 「設定 → 承認・閲覧設定」で、16 種類の下書きを 1 つずつ確かめて「有効にする」（プレビューで、店・金額・申請した人ごとの承認者と閲覧者が見られます）。
7. 16 種類すべてが有効になったら「共通ルールで動かす」。そのとき承認待ちの申請にルールの記録が付き、もう済んでいる承認（AM の承認など）は同じ段に写ります（していない承認は作りません）。
8. 画面ができる前に有効にしたいときは Claude に（API で確かめながら進めます）。

## 困ったとき

- 共通ルールで動かしたあと止めたいとき：画面の「今までの決まりに戻す」（次の PR）。申請とルールの記録は残ります。
- 全部を ② の前に戻すとき：`戻す_SQL.sql`。関数を前の形に戻し、共通ルールで動いていれば止めます。承認待ちの申請のルートは記録に写してから外し、今までの決まりで続きます。ルール・代理・一括承認の記録は消さずに残します（もう一度 ② を流したら、CEO・GM が「共通ルールで動かす」をもう一度押すまで今までの決まりのまま）。
- 申請の前の SQL（v1131〜v1184）をもう一度流したら、そのあとに ② をもう一度流してください（③ の 3 が NG になります）。
