# 紐づけ 段階 1 を入れる（アプリ v1093）

Moto さん 10/18「新マスターと現マスターの紐づけからいきます」→ UI案55 → 08:45 HST 決まったこと 1〜8（8 は Claude に任せる → Drive 取込から）→ 09:03 HST「A」（Head Chef・AM にもメールのアカウント）。仕様は `docs/ITEM_LINK_V1093_JA.md`。

- **食材管理 › 食材マスター › 紐づけ**（新しいタブ）。Drive 取込の invoice の品目（業者の品番、無ければ印字名と規格）を、今の食材マスター（棚卸表の品目）のコードに結ぶ。
  - 候補はこの端末で今のマスターと比べて出す（同じ仕入先の品目から。語ごとに比べ、名前の一部が同じだけでは「確かさ高」にしない。数字が違えば印）。決めるのは人。
  - **まとめて確定**：仕入先を選ぶと、その仕入先の「確かさ高」で印の無い品目を、確かめの画面のあとにまとめて確定（決まったこと 3）。
  - **比べる**：1 件ずつ候補を比べる・今のマスターを探す・新しい品目・対象外・あとで。
  - **戻す**：結びを戻す（記録は残る。また結べる）。
  - 食材以外の業者の品目は最初から「対象外」（決まったこと 6）。「紐づけの対象に戻す」で入れられる。
  - 「棚卸表の品目から」：店ごとに、棚卸表の品目に結んだ invoice の品目と候補。
- 結ぶと：その品目の明細（要確認・反映済み）に今のコードが付く。**反映済みの invoice は単価の記録（仕入れ履歴・最新単価）ができる**。これからの invoice は Invoice取込が自分で結ぶ。
- 今のマスター・棚卸表・過去の棚卸しと原価の記録は変えない（決まったこと 1）。invoice の金額・反映・照合・QuickBooks も変えない。
- 確定できるのは 経理・事務Crew・GM・CEO・Head Chef・AM（決まったこと 5）。Head Chef・AM は紐づけだけ（Invoice取込のほかの画面は使えない）。Head Chef・AM は、経理が確かめた対応（Invoice取込の画面で登録したもの）は変えない・戻さない。

## 気をつけること（金額の見え方）

- 確認済みの仕入れ集計（予実管理 ›「仕入れ」・原価）は、明細にコードがあれば**そのコードの区分**（食材・お酒・飲料・消耗品）で数える（v1077 からの決まり。コードが無い明細は業者の区分で仮に数えていた）。
  食材の業者の品目を、今のマスターで消耗品（カテゴリー 40000 など）の品目に結ぶと、**締めていない月**ではその額が原価から消耗品に移る。締めた月はそのまま（締めたときのまま）。
- 串など原価に入れたい物は、今までどおり今のマスターの区分を食材にする（10/14 の決定のまま）。

## 入れる前に

- 新しい業者を決める（`20261024090000`・v1089）の SQL が入っていること（10/17 に入った）。入っていなければ SQL は「先に 20261024090000_invoice_vendor_register.sql（新しい業者を決める）を流してください」で止まる（何も変えない）。

## 入れる順番

1. **Supabase → SQL Editor** に `1_追加のSQL_紐づけ.sql` を貼って Run。
   - 表 2 つ（Head Chef・AM のアカウント、品目の印）と関数 10 個を足し、3 つを置き換える（戻した結びを使わない）。対応表に「戻した」の列を足す。invoice・金額・設定・Drive は変えない。2 回流しても同じ。
2. `2_確認のSQL_読むだけ.sql` を Run → **item_link＝true・tables＝21・functions＝94・browser_can_read＝0・browser_can_run＝0**（ほかの行は今までどおり：vendor_register＝true など）。
3. **Edge Functions → invoice-intake** を開き、中身を `3_関数_invoice-intake_index.ts` に置き換えて Deploy（JWT の検証は OFF のまま）。
4. アプリ v1093 をマージ（この PR）。端末を更新する。
5. Head Chef・AM のアカウント（Claude が直接渡す SQL。公開のリポジトリには書かない）：
   1. **Authentication → Users → Add user** で、その人のメールとパスワードのアカウントを作る（Auto Confirm User に印）。もうあればそのまま。
   2. 渡した `4_足すSQL_〇〇.sql` を 1 人ずつ Run（ひな形は `db/invoice-link-add-member.sql`）。最後の表で **ok＝true** なら使える。
   3. 名前が見つからない・役割が違うと止まる（何も変えない）→ 従業員マスターの名前と役割（Head Chef／AM）を確かめる。
6. 食材管理 › 食材マスター › 紐づけ を開く（最初の 1 回だけメール認証）→ 仕入先を選ぶ → 「確かさ高」を 1 件「比べる」で確かめて結ぶ → その品目を食材マスターで開き「仕入れ履歴（Drive 取込の invoice）」に単価が出るのを確かめる（反映済みの invoice があれば）。

順番を入れ替えても壊れない：
- 関数を SQL より先に入れると、紐づけの画面が読み込めない（エラーが出る。何も変えない）。Invoice取込のほかの動きは今までどおり。
- アプリを先に入れると、紐づけのタブはエラーを出すだけ（何も変えない）。ほかの画面は今までどおり。

## 止めるとき・戻すとき

- 結びを 1 つ戻す：紐づけ →「確定済み」→「戻す」（その品目の明細からコードが外れ、その結びでできた単価の記録は取り消しになる。記録は残る）。
- 関数を前に戻す：`deploy/invoice-vendor-register-v1089/3_関数_invoice-intake_index.ts` を貼って Deploy。SQL はそのままでよい（足した関数は呼ばれなくなるだけ）。結んだものは対応表に残り、Invoice取込はこれからも使う（使わせたくなければ、戻す前に紐づけの画面で「戻す」）。
- Head Chef・AM を止める：`db/invoice-link-add-member.sql` の一番下（enabled を false に）。退職・役割が変われば、従業員マスターのとおり自動で使えなくなる。
