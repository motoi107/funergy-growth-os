# チャットの守り（v1168）を止めたいとき

## まず：だれかが暗証番号・キーを決めているか

③ の（参考）の「暗証番号を決めている人・キーのある会話・通知を受け取る端末の数」を見ます。

- **どれも 0 なら**：関数・アプリを前の版に戻しても何も困りません（下の「関数だけ戻す」「アプリだけ戻す」）。
- **暗証番号・キーを決めた人がいるなら**：関数やアプリだけ戻すと、その人のチャット・その会話が開けなくなります（サーバーの SQL が暗証番号・キーを確かめ続けるため）。先に本人に外してもらうか（🛡 →「暗証番号を外す」・管理する人が「グループのキー」→「キーを外す」）、Claude に知らせてください。

**SQL（②）を戻す SQL は用意していません。**② を戻すと、決めた暗証番号・キーが確かめられずに開いてしまうためです。

## 関数だけ戻す

- Edge Functions → `work-requests` に前の非公開のファイル（`work-requests_v1167_index.ts`、#163 のもの）を貼って Deploy（Verify JWT は OFF）。
- 暗証番号・キーを決めた人がいなければ、v1167 と同じに動きます。プッシュ通知は送られなくなります。
- 戻すときはもう一度 `work-requests_v1168_index.ts` を貼るだけ（SQL は流し直さなくてよい）。

## アプリだけ戻す

- 1167 のアプリでは、守りの画面・暗証番号の入力・キーの入力はありません。暗証番号を決めた人・キーのある会話は開けません（上の「まず」）。

## プッシュ通知だけ止める

- Secrets の `CHAT_VAPID_PRIVATE` を消すと、関数は通知を送りません（暗証番号・キーはそのまま）。端末の「受け取る」はそのまま残り、鍵を戻すとまた届きます。

## 気をつけること

- ② のあとにチャットの SQL（v1156・v1161・v1167 の ②）を流し直すと、守りが外れます（暗証番号・キーを確かめなくなる）。③ の 1・4 が NG になったら、添付の ② → チャット改修の ② → この ② の順にもう一度流してください。v1169 から、いまのリポジトリのチャットの SQL は、新しい段の上では止まります（「STOP: これより新しいチャットの SQL…」・何も変えない）。それでも NG になったら、v1169 より前に渡したファイル（`まとめ_v1163-v1168.zip` など）を流した可能性があります。
