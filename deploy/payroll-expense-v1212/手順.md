# v1212：Payroll 別のガソリン代・立替経費（B-2）を入れる手順

仕様と確かめたこと：`docs/PAYROLL_EXPENSE_V1212_JA.md`（UI案100・Moto さん 11/24 の答え）

- **何ができるか**：経理センター › 履歴・帳票 › 経理出力 に「Payroll 別 ガソリン代・立替経費」の区画が出ます。1〜15 日／16 日〜末日／月の両方のタブで、1 人 1 行（申請者｜ガソリン代｜立替経費｜精算額合計｜既払・他経路支給額｜今回Payroll支給額合計）。「内訳」から元の申請へ。PC は表、スマホはカード。
- **期間は自動**：精算確定（経理の「確認した」）の日（ハワイ時間）の期間に入ります。その期間が支給済みなら次の期間。理由をつけて変える・分けることができます（支給済みの期間は変えられません）。
- **前に精算済みにしたもの**は支払日の期間の「既払・他経路支給額」（今回の支給には入れない）。前の画面の立替経費「支払済」は日本時間の記録をハワイの日に直します。日付だけで期間の境目をまたぐものは「支給期間要確認」、ガソリン代の「月末処理」は「支払状況要確認」（どちらも支給に入れない・確かめて「期間に入れる」）。
- **支給日**：1〜15 日 → 同じ月の 22 日、16 日〜末日 → 翌月 7 日。土日なら前の金曜、平日の祝日なら前の営業日。祝日は米国の銀行の休日（Federal Reserve）が初めの値で、「支給日の決まり」で足す・外すことができます（CEO・GM・経理）。
- **出力（Excel：まとめ・明細・要確認。月の両方は合計も）**：出すたびにサーバーに版（写し）を残します（同じ中身なら前の版）。**出力しただけでは支給済みになりません。**
- **支給済みにする**：期間ごとに 1 回。いちばん新しい版のときだけ（出力のあとに変わったら出し直し）。その版の「今回Payroll」の申請は精算済み（Payroll・支給日）になります。押せるのは CEO・GM・経理・事務Crew。
- **事務Crew**は経理出力でこの区画だけを見ます（Tip・給与の出力は今までどおり経理・GM・CEO）。CEO・GM の「まとめて出力」の Excel にも「ガソリン代・立替経費」のシートが 1 枚足されます。
- 負の差額は給与から引きません（その人は「要確認」・今回の支給の合計に入れない）。金額と日付が同じだけの申請を自動で消しません。

## A. Supabase

1. **SQL Editor に ① を貼って Run。**「STOP」が 1 つも無ければ次へ（4 が「注意」なら、先に v1211 の ② を流すと PIN だけの事務Crew も使える）。6〜8 は数だけです。
2. **SQL Editor に ② を貼って Run。**「Success」なら次へ。「STOP: …」なら何も変わっていません（その行を Claude に）。2 回流しても同じです（割当・版・支給の記録は消しません）。
3. **SQL Editor に ③ を貼って Run。**1〜5 が OK なら次へ。7〜10 の支給日が本当の Payroll の日と違えば、アプリの「支給日の決まり」で休日を足す・外す。
4. **Edge Functions → Deploy a new function → 名前 `payroll-expense`**。中身を ④ に置き換えて Deploy。**Verify JWT は OFF**（関数の中で PIN のログインの印を確かめる）。鍵（Secrets）を足す必要はありません。

## B. GitHub とアプリ

5. **#218 をマージしたあとで、この PR をマージ**（アプリ v1212）。マージは Moto さん。
6. **経理・事務Crew・GM・CEO の端末で「更新」**。ログイン画面の版が 1212 になれば OK。

## C. 確かめ（本番・経理か事務Crew）

7. 経理センター › 履歴・帳票 › 経理出力 を開き、「Payroll 別 ガソリン代・立替経費」に今月の精算確定の申請が人ごとに出るか。経理レビュー › 申請の「支払・精算待ち」と件数・金額が合うか（前に精算済みのものは「既払・他経路」）。
8. 「要確認」の帯（支払状況要確認・支給期間要確認 など）を開いて、内容を確かめる。必要なら「期間に入れる・直す」（理由を書く）。
9. 「Excel で出力（版を残す）」を押して、まとめ・明細・要確認のシートを確かめる。**まだ「支給済みにする」は押さない**（本当に Payroll で払ったあとに 1 回だけ）。
10. 事務Crew の端末で、経理出力にこの区画だけが出て、Tip・給与の出力が出ないこと。

## 気をつけること

- 「支給済みにする」は取り消せません（まちがえたら押した版と期間を Claude に。記録から戻します）。押す前に、その期間の Payroll が本当に済んだかを確かめてください。
- 精算確定のあとに金額が変わった申請・差し戻した申請は「要確認」に出ます。分けた割当は、申請の額が変わると「額が合わない」になります。
- 支給済みの期間に、あとから前の画面の支払済の記録などが入ったときは「支給済みのあとに入った記録」として出ます（支給済みの写しは変えません）。
- 経理レビュー › 申請で 1 件ずつ「支払」を記録したものは、その期間の「既払・他経路」になり、今回の支給には入りません（二重に払わない）。

- 区画を止めるとき：`戻す_SQL.sql`（関数だけを外す。割当・版・支給の記録は残す）。関数 payroll-expense は Supabase で消してもよい。もう一度使うときは ② を流す。
