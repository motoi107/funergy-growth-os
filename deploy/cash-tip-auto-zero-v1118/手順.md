# v1118 キャッシュチップ：未登録を自動で 0 にする（入れる手順）

Moto さん 2026-10-30 の依頼 ①。仕様は `docs/CASH_TIP_AUTO_ZERO_V1118_JA.md`。

## 何が変わるか

- 未登録（記録が無い・片方だけ・空欄）は、エラー・警告・通知・未対応の数に出なくなります。計算は前から 0 でした（支給額・配分は変わりません）。
- サーバーが、終わった営業日（売上かクレジットチップのある日）のまだ入っていない側に「自動の0」を書きます。
  - 対象は全店・全期間で、締めた期間も含みます。FSP と Waikiki Garlic Shack はキャッシュチップの対象外なので書きません。
- 入っている値は変えません。0 も、数でない値・マイナスも変えません（数でない値・マイナスはエラーのまま、人が直します）。
- あとから本当の金額を入れると、その値が自動の0 より優先されます。前の版のアプリの端末でも同じです。
- 売上の取り込みに失敗した日（Toast の行が無い日）には書きません。今日の分は書きません。

## 順番（どれも Supabase の SQL Editor か Edge Functions の画面）

1. `1_追加のSQL.sql` を流します。表 1 つと関数 4 つが増えます。この SQL だけでは何も書きません。
2. `2_確認と見込み_読むだけ.sql` を流します。読むだけで、何も書き換えません。結果の 3 つの表を Claude に貼ってください。
   - 1 つ目は 4 つとも true になるはずです。
   - 2 つ目は、今の「未登録」の形ごとの数です（店・側ごと）。
   - 3 つ目は、全期間で 0 を書く日と側の数の見込みです。
3. `3_全期間を埋める.sql` を流します。全期間の未登録に 0 を書きます（2 回流しても同じ）。
   - 結果の `run_id` を控えてください。
   - 下の確認の行は `filled_days: 0` になるはずです。
4. Edge Functions → `ops-bot` に `4_関数_ops-bot_index.ts` を貼って Deploy します。
   - 朝 9:00 のキャッシュチップの知らせが、不正な値だけになります。
   - 前の版の ops-bot のままでも、0 を書いた日は「入っている」ので知らせは出ません。
5. `5_毎日動かす.sql` を流します。毎日 2 回（ハワイ時間 4:17 と 8:47）、直近 62 日の未登録に 0 を書きます。
6. PR（アプリ v1118）をマージします。端末で「更新」して、ログイン画面の版が 1118 になるのを確かめます。
   - 前の版の端末のままでも、0 を書いた日はエラーに出ません。

## 戻すとき

- 毎日の回を止める：`止める.sql`。書いた 0 はそのまま残ります。
- 書いた 0 を戻す：`戻す_埋めた0.sql`。先に止めてから流します。
  - その回で書いた側のうち、まだ自動の0 のままの側だけを、書く前の形に戻します。人があとで入れた値は変えません。
- ops-bot を戻す：`deploy/ops-bot-job-check-v1105/1_関数_ops-bot_index.ts` を貼ります。
- アプリを戻す：PR を戻します。前の版のアプリは自動の0 を「入っている」と読むので、エラーには戻りません。
