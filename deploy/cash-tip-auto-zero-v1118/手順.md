# v1118 キャッシュチップ：未登録を自動で 0 にする（入れる手順）

Moto さん 2026-10-30 の依頼 ①。仕様は `docs/CASH_TIP_AUTO_ZERO_V1118_JA.md`。

## 何が変わるか

- 未登録（記録が無い・片方だけ・空欄）は、エラー・警告・通知・未対応の数に出なくなります。計算は前から 0 でした（支給額・配分は変わりません）。
- サーバーが、終わった営業日（売上かクレジットチップのある日）のまだ入っていない側に「自動の0」を書きます。
  - 対象は全店・全期間で、締めた期間も含みます。FSP と Waikiki Garlic Shack はキャッシュチップの対象外なので書きません。
- 書くのは値が無い・空・0 の側だけです。次のものは変えません。
  - 人が入れた値（0 も）
  - 印の無い 0 でない金額（前からある記録）
  - 数でない値・マイナスの値（エラーのまま、人が直します）
- 自動の 0 には「入力済み」の印を付けません。だから前の版の端末が混ざっていても、人が入れた値が必ず優先されます。
- あとから本当の金額を入れると、その値が自動の 0 より優先されます。
- 売上の取り込みに失敗した日（Toast の行が無い日）と、今日の分は書きません。

## 順番（どれも Supabase の SQL Editor か Edge Functions の画面）

1. `1_追加のSQL.sql` を流します。表 1 つと関数 6 つが増えます。この SQL だけでは何も書きません。
2. `2_確認と見込み_読むだけ.sql` を流します。読むだけで、何も書き換えません。結果の 3 つの表を Claude に貼ってください。
   - 1 つ目は 4 つとも true になるはずです。
   - 2 つ目は、今の「未登録」の形ごとの数です（店・側ごと）。
   - 3 つ目は、全期間で 0 を書く日と側の数の見込みです。
3. Edge Functions → `ops-bot` に `3_関数_ops-bot_index.ts` を貼って Deploy します。朝 9:00 のキャッシュチップの知らせが、不正な値だけになります。
4. PR（アプリ v1118）をマージします。端末で「更新」して、ログイン画面の版が 1118 になるのを確かめます。
   - 前の版の端末では、未登録のエラーが更新するまで出続けます。
5. `4_全期間を埋める.sql` を流します。全期間の未登録に 0 を書きます（2 回流しても同じ）。
   - 営業時間の外（朝早く）に流してください。流しているあいだ、その店のキャッシュチップの保存が数秒待たされることがあります。待たされた保存は、あとで自動で送り直されます。
   - 結果の `run_id` を控えてください。下の確認の行は `filled_days: 0` になるはずです。
6. `5_毎日動かす.sql` を流します。毎日 2 回（ハワイ時間 4:17 と 8:47）、直近 62 日の未登録に 0 を書きます。

## 戻すとき

- 毎日の回を止める：`止める.sql`。書いた 0 はそのまま残ります。
- 書いた 0 を戻す：`戻す_埋めた0.sql`。先に止めてから流します。
  - その回で書いた側のうち、まだ自動の 0 のままの側だけを書く前の形に戻し、「戻した印」を残します。人があとで入れた値は変えません。
  - 戻した側は、毎日の回でもまた書きません。
  - v1118 の端末は戻した印を優先するので、端末が持っている 0 で元に戻りません。
  - 前の版の端末が自動の 0 をまた送ることはあります。計算は 0 のままで変わりません。
- ops-bot を戻す：`deploy/ops-bot-job-check-v1105/1_関数_ops-bot_index.ts` を貼ります。
- アプリを戻す：PR を戻します。前の版のアプリは自動の 0 を「まだ入っていない」と読むので、未登録のエラーがまた出ます。データは壊れません。
