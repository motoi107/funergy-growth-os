# ワークセンターの申請を入れる手順（v1131・v1132・v1133 をまとめて）

前に渡した v1132 のファイルをもう入れていても、入れていなくても、**この手順だけ**で大丈夫です（SQL は何回流しても同じになります）。
v1132 のファイル（`2_SQL_1段目と2段目.sql`・`work-requests_v1132_index.ts`）はもう使いません。

使うファイルは 4 つ（Moto さんに直接渡したもの）：

| 番号 | ファイル | どこで |
|---|---|---|
| ① | `1_最初に確認_読むだけ.sql` | Supabase の SQL Editor |
| ② | `2_SQL_まとめて.sql` | Supabase の SQL Editor |
| ③ | `3_確認_読むだけ.sql` | Supabase の SQL Editor |
| ④ | `work-requests_v1133_index.ts`（非公開・リポジトリには無い） | Supabase の Edge Functions |

## A. Supabase

1. **SQL Editor に ① を貼って Run。**「STOP」が 1 つも無ければ次へ。
   - STOP があれば止めて、結果の画面を Claude に。
   - 「mileage rate」が NG なら、先にアプリのガソリン代の画面の「設定」で単価を入れる。
2. **SQL Editor に ② を貼って Run。**「Success」なら次へ。
   - エラーなら止めて、エラーの文を Claude に。途中で止まっても、直してからもう一度 ② を流せば同じ結果になります。
3. **SQL Editor に ③ を貼って Run。**「result」の列に NG が 1 つも無ければ次へ。
4. **Edge Functions で関数 `work-requests` を開く（無ければ作る）→ ④ の中身を全部貼って Deploy。**
   - 設定の **Verify JWT は OFF**。新しく入れる秘密の設定はありません。

## B. GitHub

5. **v1133 の PR をマージ。**（#122・#123・#124 はマージ済み）

## C. アプリ

6. **G4・GM・CEO・経理・事務Crew の端末で、アプリの「更新」を押す。**ログイン画面の版が 1133 になれば OK。
   - 1132 の端末のままだと、評価の変更を「正式な値に反映する」ボタンが出ません（書かない・こわれない）。
7. **GM か CEO が、ワークセンター →「申請」→「使い始める」。**（もう使い始めていれば不要）
   - 先に「承認・閲覧の権限の確かめ」が開きます。合っている人に印を付けて確定してください。

## うまくいかないとき

- 「申請のサーバー（work-requests）につながりません」：4 の関数が入っていない。
- 「申請のサーバー（work-requests）が前の版です」：4 で貼ったのが ④ ではない。④ を貼り直す。
- 「申請のデータベースが前の段のままです」：② をもう一度流す。
- 止めたいとき：`deploy/work-requests-v1131/止める.sql`（申請の記録は残る）。止める前に Claude に相談。
