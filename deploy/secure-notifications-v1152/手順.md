# 通知を公開の鍵から外す手順（v1152・段階 2b の最後）

仕様：`docs/SECURE_NOTIFICATIONS_V1152_JA.md`。データの行・値は動かしません（通知は app_state の 1 行のまま）。

決めたこと（Moto さん 11/12）：

- **店のタブレット（店舗の PIN）には通知を出さない。**通知は各自の PIN でログインして見る。タブレットで作った通知（シフトの公開など）は今までどおり届く。
- 会社全体の賞与・Career Score の設定（係数の幅・基準ライン・強みの決まり・評価基準の文）は**今回は外さない**（個人の情報は入っていない）。

**順番：#135〜#145（v1141〜v1151）をマージしてから、この v1152 の PR をマージします。**
関数（②）はアプリより先に入れます。SQL（③）は**全部の端末（店のタブレットも）を 1152 にしてから**です。

使うファイル（`deploy/secure-notifications-v1152/`。どれもこのまま貼れます。非公開の部品はありません）：

| 番号 | ファイル | どこで |
|---|---|---|
| ① | `1_確かめ_読むだけ.sql` | Supabase の SQL Editor |
| ② | `2_関数_secure-state_index.ts` | Supabase の Edge Functions（今ある関数 `secure-state` を置き換え） |
| ③ | `3_SQL_公開の鍵から外す.sql` | Supabase の SQL Editor（全部の端末が 1152 になってから） |
| ④ | `4_確かめ_読むだけ.sql` | Supabase の SQL Editor（③ のあと。最後に取り消すので何も変わりません） |
| 戻す | `戻す_SQL.sql` | 困ったときだけ（通知をまた公開の鍵で読み書きできるようにする） |
| 戻す（関数） | `deploy/change-signal-v1151/2_関数_secure-state_index.ts` | 困ったときだけ（先に「戻す」の SQL を流してから） |

## A. 確かめと関数

1. **SQL Editor に ① を貼って Run。**表をそのまま Claude に貼ってください（通知の中身・名前は出ません）。
   - STOP が 1 つでもあれば止める（Claude に）。
   - 7 行目（確かめがまだの店長・リーダー・G4・Head Chef）と 8 行目（確かめがまだの AM）が 1 以上なら、その人には ③ のあと
     「crew あての通知」だけが届きます（AM あて・店長あての通知が届かない）。GM・CEO が「承認・閲覧の権限の確かめ」で確かめると届きます。
   - 9 行目が info（v1151 の SQL がまだ）なら、v1151 の ③ を流したあとに、この v1152 の ③ をもう一度流してください（順番どおりなら OK になります）。
2. **Edge Functions → `secure-state` → コードを ② の中身に全部置き換えて Deploy。**
   - 「Verify JWT with legacy secret」は **OFF のまま**。Secrets は足さなくてよい。
   - ② は v1151 の関数をそのまま含み、通知の読み書き（`nt`）を足しただけです。今のアプリ（1151 以前）もこの関数で今までどおり動きます。

## B. アプリ

3. **v1141〜v1151 の PR をマージしてから、v1152 の PR をマージ。**
4. **全員の端末と店のタブレットで、アプリの「更新」を押す。**ログイン画面の版が 1152 になれば OK。
5. **確かめ**：
   - 自分の PIN でログイン → 右上のベル（または「通知」）に、今までどおり自分あての通知が出れば OK。
   - 店のタブレット（店舗の PIN）では、ベルを開くと「店舗の PIN のタブレットでは通知を出しません」と出ます（出ないのが正しい）。
   - **確かめのためだけに本当の通知を作らないでください**（いつもの操作で通知が出たときに見てください）。

## C. SQL（全部の端末が 1152 になってから）

6. **SQL Editor に ③ を貼って Run。**2 回流しても同じです。
   - 1151 以前の端末は、③ のあと通知を読めず、作った通知も送れません（送信待ちに残る）。だから全部の端末を先に 1152 に。
7. **SQL Editor に ④ を貼って Run。**全部 OK（13 行目は v1151 の SQL がまだなら info）なら入っています。NG は表をそのまま Claude に。

## 困ったとき

- **通知が出なくなった**（自分の PIN でログインしているのに）：`戻す_SQL.sql` を流す（通知はまた公開の鍵で読める＝前と同じ）。表と画面の写真を Claude に。
- 関数を v1151 に戻すときは、**先に `戻す_SQL.sql` を流してから** `deploy/change-signal-v1151/2_関数_secure-state_index.ts` を貼る
  （前の版の関数は通知を扱わないので、アプリは REST で読み書きします。SQL を戻す前に関数だけ戻すと、だれも通知を読めません）。
- 「通知を見るには、自分の PIN を設定してログインし直してください」と出る人：PIN が初期のまま（ログインの印が無い）です。自分の PIN に変えてログインし直すと見られます。

## 変わること（知っておくこと）

- 通知の中身（退職の理由・採用した人の名前・相談の題名・個人あての知らせ）は、公開の鍵では読めなくなります。読めるのは、ログインした人の宛先の分だけ。
- 店のタブレットでは通知を出しません（Moto さんの決定）。タブレットで作った通知はそのまま届きます（出した人の名前は確かめていない印付き）。
- PIN が初期のままの人（GM・CEO 以外）は通知が見えません（自分の PIN にすると見える）。GM・CEO で PIN の印が無い人は、③ の前は今までどおり、③ のあとは見えません。
- GM・CEO の確かめがまだの店長・リーダー・G4・Head Chef・AM は、確かめるまで crew あての通知だけ（① の 7・8 行目）。
