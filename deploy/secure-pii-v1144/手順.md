# 従業員の個人の欄（生年月日・カードの下 4 桁・保険）を公開の鍵から外す手順（v1144・段階 2b の 6 つ目）

仕様：`docs/SECURE_PII_V1144_JA.md`。対象は従業員の表（employees）の 5 つの欄です：生年月日・会社カードの下 4 桁・医療保険の加入・歯科保険の加入・会社負担の保険料。
今は公開の鍵で全員の分を読めます（アプリはログインのたびに全員の行を取ります）。これを app_state の 1 行 `emp_pii` に移し、関数 `secure-state` だけで読み書きします。

見られる人（Moto さん 11/09「今の従業員マスターと同じ」）：

- 生年月日・カード・保険の加入：CEO・GM・経理・Head Chef は全員。AM は担当の店（応援を含む）の人と本部（ALL）の人。事務Crew は「生年月日があるか」だけ（エラーセンター用）。
- 保険料（人ごとの額）：GM・CEO だけ。店ごとの合計は人件費のため全部の端末に（店舗のタブレットも・ログイン不要）。
- カードの下 4 桁から社員を探すのは、サーバーが照らします（当たった人の名前だけ返す）。店舗の PIN のタブレットでは社員を手で選びます。

**順番：v1141（PR #135）→ v1142（PR #136）→ v1143（PR #137）→ この v1144 の順にマージします。**

使うファイル（`deploy/secure-pii-v1144/`。どれもこのまま貼れます。非公開の部品はありません）：

## A. 確かめと関数（いつでも。アプリより先でもあとでもよい）

1. **SQL Editor に ① を貼って Run。**表をそのまま Claude に貼ってください（生年月日・番号・金額は出ません。人数だけです）。
   - 1 行目・5 行目が STOP なら止める（Claude に）。
   - 2 行目が info（v1139〜v1143 の SQL をまだ流していない）でも進めてよい（③ が一緒に入れます）。
   - 3 行目は今、従業員の表に入っている人数です（③ で移す人数）。
   - 6 行目が info なら、全部の端末を 1144 にしてから、その人の欄をもう一度直してください（Claude に）。
   - 7 行目は「OK（まだ）」のはずです。
2. **Edge Functions → `secure-state` → コードを ② の中身に全部置き換えて Deploy。**
   - 「Verify JWT with legacy secret」は **OFF のまま**。鍵の設定（Secrets）は足さなくてよい。
   - 今のアプリ（1143 以前）は、この関数でも今までどおり動きます（5 つの欄は今までどおり従業員の表で読み書きします）。

## B. アプリ

3. **v1141・v1142・v1143 の PR をマージしてから、v1144 の PR をマージ。**
4. **全員の端末で、アプリの「更新」を押す。**ログイン画面の版が 1144 になれば OK。GM・CEO・経理・事務Crew・AM・Head Chef の端末と、**店舗のタブレット（人件費の保険料を使う）も全部**。
5. **（確かめ・③ の前に）GM か CEO が、アプリを一度閉じて開き直し、自分の PIN でログインして「従業員マスター」を開く。だれか 1 人の編集の画面を開く。**
   - 生年月日・カード・医療／歯科保険・保険料の欄に、今までと同じ値が入っていて、直せる（灰色でない）なら OK（関数から読めた）。
   - 「サーバーから読み込んでいます」のまま変わらない・「このアカウントでは…見る・直すことはできません」と出るなら ③ を流さない（Claude に）。
   - 何も変えずに閉じてよい（保存しなくてよい）。
6. **（確かめ）店舗の人件費の画面で、保険料の日割り（月額）が今までと同じか見る。**同じなら OK（店ごとの合計がサーバーから届いている）。
7. **③ の直前に ① をもう一度流す。**6 行目が OK なら次へ（info なら、前の版の端末で直した人がいます。Claude に）。

## C. 個人の欄を移して外す（全部の端末が 1144 になってから）

8. **SQL Editor に ③ を貼って Run。**「Success」なら次へ（下に移した人数・外した行の数が notice で出ます）。
   - ③ は、従業員の表の 5 つの欄を `emp_pii` に写し（もう `emp_pii` にある人はそちらが先）、従業員の表から消し、これからも書かれたら外す見張りを付けます。ほかの欄（名前・役職・店・状態など）は変えません。
9. **SQL Editor に ④ を貼って Run。**ok の列に NG が無ければ終わり。
   - 3 行目（キーの判定）が OK・19、4 行目（従業員の表に残っている個人の欄）が 0、5 行目（見張り）が 1、6 行目（試しに書いても入らない）が OK、7 行目（`emp_pii` の人数）が ① の 3 行目のいちばん大きい数以上なら入っています。
   - 8〜13 行目（anon で読めない・足せない・直せない・消せない・従業員の表の個人の欄が読めない）が OK、9 行目（ほかの行は今までどおり読める）が OK。
   - 15 行目（メールのログインで読める対象のキー）が 0。
   - 16 行目が CHECK（決まりを通らずに app_state を読める関数）なら、名前を Claude に。
10. **③ のあとにもう一度、5・6 の確かめをする。**（③ のあと、従業員の表には値がありません。アプリは関数から読みます）

## 変わること

- 生年月日・カード・保険の加入を見られる人は今の従業員マスターと同じ。サーバーでも確かめます。**保険料（人ごとの額）は GM・CEO だけ**（画面の保険料の欄は今も GM・CEO だけに出ています。今までは公開の鍵で全員の額を読めました）。
- 事務Crew のエラーセンターの「生年月日 未登録」は今までどおり出ます（関数が「あるか」だけ返します）。
- レシート管理の「カード下 4 桁から社員を自動特定」は、自分の PIN かメールでログインした人ならサーバーが照らします。**店舗の PIN のタブレットでは、社員を手で選びます**（「このログインではカードの下4桁から社員を選べません」と出ます）。
- 人件費の保険料は、店ごとの合計をサーバーから受け取ります（人ごとの額は端末に来ません）。
- 生年月日・カード・保険を直すと、変えた欄だけをサーバーに送ります。2 台で同じ人の同じ欄を直したら、あとの保存は「ほかの端末で同じ欄が先に変わっていました」と出て保存しません（開き直して確かめてから直す）。違う欄なら両方残ります。
- 「承認・閲覧の権限の確かめ」で確かめていない AM・Head Chef には、個人の欄は届きません（確かめれば届きます）。

## 困ったとき

- 従業員マスターで「サーバーから読み込んでいます」のまま：ログインし直してから開き直す。続くなら Claude に。
- 「生年月日・カード・保険を保存できませんでした（…）」と出た：右上の「保存」からもう一度送れます。「このアカウントでは直せません」なら、その人はあなたの担当の外です。
- ③ の前に関数でうまく読めない：関数を v1143 に戻す（`deploy/secure-settings-v1143/2_関数_secure-state_index.ts` を貼って Deploy）。アプリ 1144 はそのままで今までどおり（5 つは従業員の表で）。
- ③ のあとに困った：**先に `戻す_SQL.sql` を流す**（`emp_pii` の値を従業員の表に戻し、見張りを外し、`emp_pii` をまた公開の鍵で読めるようにする。行は残す）。そのあと必要なら関数を v1143 に戻す。逆の順（関数を先に戻す）にすると、③ のあいだはアプリが従業員の表（空）を読むので、生年月日・保険が消えて見えます（データは `emp_pii` に残っています）。
- ③ のあと、1143 以前の端末では生年月日・カード・保険が空に見え、保存しても入りません（見張りが外します）。エラーセンターに「生年月日 未登録」が並び、店舗のタブレットの人件費の保険料が 0 になります。更新して 1144 にすれば直ります。
- 前の版の流れとの関係：v1143 の手順は `deploy/secure-settings-v1143/手順.md`。v1139・v1140・v1142 の `戻す_SQL.sql`（`deploy/secure-state-v1139/`・`deploy/secure-cs-v1140/`・`deploy/secure-hr-v1142/`）を流すと `ss_secret_key` が前の形に戻り、`emp_pii` がまた公開の鍵で読めるようになります。流したあとは、この一式の ③ をもう一度流してください（2 回流しても同じになります）。v1141・v1143 の `戻す_SQL.sql` は書く決まりだけを変えるので、`emp_pii` の読み方は変わりません。
