# ボーナスの締め v1109 を入れる手順

Moto さん 10/28「キャリアスコアの強み表示・ボーナス仮締めと修正」の ②。中身は `docs/BONUS_CLOSE_V1109_JA.md`。

入れるものは 3 つ：SQL（表 4 つ・関数 21 個）・Edge Function `bonus-close`（新しい関数）・アプリ v1109（この PR をマージ）。
今ある表・行・関数・権限の決まり（RLS）・見張り（trigger）は何も変えません。業務のデータ（評価・賞与・給与の記録）は書き換えません。

## 入れる

| 順 | 何を | どこで |
|---|---|---|
| 0 | `0_最初に確認_読むだけ.sql` を貼って Run。上の 2 行が `OK`、3 行目が `0`（初めて）。4 行目（GM・CEO のアカウントの数）が 1 以上 | Supabase › SQL Editor |
| 1 | `1_追加のSQL_ボーナスの締め.sql` を全文そのまま貼って Run（2 回流しても同じ。版の記録は消えません） | SQL Editor |
| 2 | `2_確認のSQL_読むだけ.sql` を貼って Run → **最後の 1 行以外すべて `OK`** | SQL Editor |

Secrets は新しく要りません（`SUPABASE_URL`・`SUPABASE_SERVICE_ROLE_KEY`・`SUPABASE_ANON_KEY` は Supabase が入れています）。

順番を間違えても壊れません：アプリを先に入れると、締めの画面が「ボーナスの締めのサーバー（bonus-close）につながりません」と出すだけ（2026 Q3 の確定・記録はそのあいだできません。ほかの画面は今までどおり）。

## 入れたあと（GM・CEO）

1. 成長カルテ › 査定一覧（2026 Q3）の上の「ボーナスの締め」→「メールで認証」（業務Bot・Invoice取込と同じメール・パスワード）。
2. 状態が「作成中・試算中」になり、一覧に「未確定の部分に使う値」の列が出ます。
3. 未確定の人に値を選ぶ（「選ぶ」か「未確定部分を 1.00 で試算」）→「仮締めを保存」→ 中身を見て「支給額を確定」→ 支給したら「支給済みとして記録」（支給日）。
4. 前の版（v1108 まで）で 2026 Q3 をもう確定していたら、締めの画面の「今の確定をサーバーに取り込む」（数字は変わりません）。

## 困ったとき

- **SQL がエラーになった**：エラーの文をそのまま Claude に貼ってください。
- **確認で NG がある**：表をそのまま Claude に貼ってください（名前・金額は出ません）。
- **「このアカウントでは保存できません」**：そのメールのアカウントが manager_auth で GM・CEO になっているか（経理は読むだけ）。
- **「アプリの確定の記録が、サーバーの有効な確定版と違います」**：前の版の端末で確定・解除した可能性があります。端末を 1109 にしてから「アプリの記録を合わせる」。
- **関数を止めたい**：Edge Functions で `bonus-close` を消す（または Deploy し直さない）。表と版の記録は残ります（アプリは「つながりません」と出し、2026 Q3 の確定・記録は止まります）。
- **表を消したい（まだ一度も使っていないときだけ）**：`戻す_使う前だけ.sql`。版が 1 つでもあれば何も消さずに止まります。
