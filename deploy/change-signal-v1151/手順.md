## A. 確かめ・関数・SQL

1. **SQL Editor に ① を貼って Run。**表をそのまま Claude に貼ってください（名前・中身は出ません）。
   - STOP が 1 つでもあれば止める（Claude に）。
   - 5 行目（Realtime）が info なら、合図は 1 分ごとに読みに行きます（動きは同じ。少し遅いだけ）。
   - 11 行目（app_state_index）が info なら、成長カルテ・賞与・Career Score などの合図のたびに、端末が app_state を全部読み直します（今の 10 分ごとの同期と同じ重さ）。
     `deploy/perf-v1098/手順.md` で入れておくと、変わった行だけになります（任意）。
2. **Edge Functions → `secure-state` → コードを ② の中身に全部置き換えて Deploy。**
   - 「Verify JWT with legacy secret」は **OFF のまま**。Secrets は足さなくてよい。
   - ② は v1148 の関数をそのまま含み、①書き込みに確かめた人を付ける ②変更の記録を読む（`change_log`）の 2 つを足しただけです。今のアプリ（1150 以前）もこの関数で今までどおり動きます。
3. **SQL Editor に ③ を貼って Run。**2 回流しても同じです。
4. **SQL Editor に ④ を貼って Run。**全部 OK（Realtime が無ければ 6 行目は info）なら入っています。NG は表をそのまま Claude に。

## B. アプリ

5. **v1141〜v1150 の PR をマージしてから、v1151 の PR をマージ。**
6. **全員の端末で、アプリの「更新」を押す。**ログイン画面の版が 1151 になれば OK。
   - 1150 以前の端末の保存も記録に残りますが、名前は「名前なし（前の版の端末）」です。全部の端末を 1151 にすると、だれが変えたかが分かります。
7. **確かめ（2 台）**：同じ人でなくてよいので、2 台で同じ画面（たとえば会議・予算）を開き、片方で保存 → もう片方で数秒のうちに画面が新しくなり、左下に知らせが出れば OK。
   - 右上の保存・同期のボタンを押すと「リアルタイム：つながっています」と出ます。
   - GM・CEO・経理・事務Crew は「設定 › 診断と記録」の「変更の記録」に、いま保存した行（名前・時刻・どこ）が出ます。
   - **確かめのためだけに本当のデータを変えないでください**（記録に残ります。いつも変えている画面で、いつもの保存をしたときに見てください）。

## 困ったとき

- **保存がいつもより遅い・保存できない**（右上に「保存できなかった」）：`戻す_SQL.sql` を流す（見張りを外すだけ。保存はすぐ元どおり。アプリは 10 分ごとの同期に戻る）。表をそのまま Claude に。
- 「変更の記録」に「関数 secure-state がまだ前の版です」：② をやり直す。
- 「リアルタイム：つながっていません」のまま：1 分ごとに読むので、動きは同じです（少し遅いだけ）。Supabase の Database → Replication で `sync_signal` が入っているかを Claude と確かめます。
- 関数を v1148 に戻すときは `deploy/secure-grade-bonus-read-v1148/2_関数_secure-state_index.ts`（③ はそのままでよい）。

## 公開の鍵で見えるもの（知っておくこと）

- 合図の表（`sync_signal`）は公開の鍵で読めます（端末が合図を受け取るため）。入っているのは、キーの名前・時刻・回数・変えた人の社員 ID・端末のランダムの印だけです（値・名前は入りません）。
  成長カルテ・賞与・Career Score などの機密のキーは、区分（`_secure:bonus` など）の 1 行にまとめ、社員 ID も入れません。
- 変更の記録（`change_log`）は公開の鍵では読めません（関数 `secure-state` だけ）。
- 名前はアプリが送ったものです（関数を通った書き込みは関数が確かめた人）。公開の鍵を持つ人は名前を偽れます（記録は「気づいて戻す」ためのもので、証明ではありません）。
