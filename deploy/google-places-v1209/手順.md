# Google の評価・口コミ（Places API（新））を入れる手順（v1209・11/23 の更新）

Moto さん 11/23 10:49 HST の依頼と、14:36 HST の更新の依頼。ダッシュボード・会議のカード（Google の口コミ）・KPI設定 ›「Google の口コミ」で、店ごとの **Google の評価・口コミの件数・Google が返す口コミ（最大 5 件）** を見られるようにします。仕様：`docs/GOOGLE_PLACES_V1209_JA.md`（11/23 の更新は 11）。

## はじめに：「毎朝サーバーが取って残し、画面に出す」はしていません（Google の決まり）

- 依頼の「毎日決まった時刻にサーバーで 1 回取り、その結果をダッシュボード・会議・KPI に出す」は、**Google の決まりに合わないので作っていません。**
  - Google Maps Platform の利用規約 3.2.3(b)：Google マップの内容を前もって取っておく・ためておく・残す（キャッシュ・保存）のは、サービス別の決まりで許された物だけ。
  - Places API のサービス別の決まり：残してよいのは **place ID だけ**（緯度・経度は 30 日まで）。評価・件数・口コミ・投稿者・店の名前・住所は残せません。
  - 毎朝取って残して、あとでみんなに配るのは「残す」になります。
- かわりに作ったもの（A）：**「Google の評価と口コミを見る」を押したときに、その場で Google から取って、その画面を見ているあいだだけ出します**（ほかの画面に移ると消えます。サーバーにも端末にも残しません）。毎朝の自動の呼び出し（スケジュール）は入れません。
- ほかの道（B）：Business Profile API（自分の店の口コミ。v1157 で作り、Google の審査待ち）。自分の店のデータなので Places とは決まりが別です。毎日残して配ってよいかは、Business Profile API の決まりを Moto さんが確かめてから（Claude はまだ確かめていない）。

## A. Supabase（SQL を先に、関数はそのあと）

   - 4 に店の ID が出たら、その店は店舗マスターに無い（使っていない）のに Google の店が結んである。2b のあと KPI設定で「外す」か、Claude に。
   - 最後の（参考）に出た店は、今 v1157 で結んである店です。2b のあと、**GM・CEO が KPI設定で選び直して住所で確かめるまで、その店は Google を呼びません**（料金なし）。
2. **SQL Editor に ② を貼って Run。**「Success」なら次へ。エラーなら止めて、エラーの文を Claude に。2 回流しても同じです。
3. **SQL Editor に 2b を貼って Run。**「Success」なら次へ。2 回流しても同じです（確かめた店・目安・回数を消さない）。
   - 「STOP: 先に 20261215090000」と出たら ② がまだ。何も変わっていません。
4. **SQL Editor に ③ を貼って Run。**「result」の列に NG が 1 つも無ければ次へ。
   - 7 が NG：あとで v1157 か ② の SQL を流した。2b をもう一度。
   - v1209 のあとは v1157 の ③ を使わない（関数の数が違うので NG になる）。この ③ を使う。
5. **Edge Functions → `google-reviews` → コードを ④ の中身に全部置き換えて Deploy。Verify JWT は OFF のまま。**

## B. Google Cloud（料金の守り）

6. **1 日の割り当て（quota）を下げる。**「API とサービス」→「Places API (New)」→「割り当てとシステム上限」で：
   - 店の詳しい情報（Place Details／GetPlace）：1 日 **60**（店の評価と口コミ＝確かめた店の数（今は 6〜7）＋店を選ぶときの確かめ＝サーバーの「探す・確かめ」の 1 日 40 の中。合わせて 1 日 47 くらいまでなので 60）。
   - 店を探す（Text Search／SearchText）：1 日 **40**（サーバーの「探す・確かめ」の 1 日の上限と同じ）。
   - これより低くすると、はじめに 7 店をまとめて選ぶ日に Google が先に断ることがあります（「Google が断りました」と出る。その日は 0 時（太平洋時間）を待つ）。
   - サーバーの上限が効かなくなっても、Google 側で止まります。項目の名前は Google の画面で少し違うことがあります。店を足して上限を上げるときは、ここも上げる。
7. **予算のアラート。**「お支払い」→「予算とアラート」で月の予算（例：$10）とメールの知らせ。アラートは知らせるだけで、呼び出しは止めません（止めるのは 6 とサーバーの上限）。
8. **「アプリケーションの制限」は「なし」のまま。**
   - IP アドレスの制限：Supabase の Edge Functions には決まった送信元の IP アドレスが無いので、使えません（使うなら決まった IP のある中継のサーバーを別に用意する＝費用と管理が増える）。
   - HTTP リファラー（ブラウザ用）・Android／iOS アプリ（スマホのアプリ用）：サーバーからの呼び出しには使えません。
   - かわりに：鍵はサーバーの Secrets だけ・API の制限は Places API (New) だけ（今のまま）・6 と 7・サーバーの上限。
9. 鍵を作り直したときは、Secrets の `GOOGLE_PLACES_API_KEY` を変えるだけ（関数を作り直さなくてよい）。

## 店を選ぶ（place ID を住所で確かめる）

- 「選ぶ」を押すと Google マップの店の候補（名前・住所・「Google マップで確かめる」のリンク）が出ます。候補を押すと、サーバーが Google からその店の**名前と住所**を取り直し（1 回＝「店を探す・確かめる」の回数）、下の**住所の目安**と比べます。
  - 住所の語がすべて合い、名前も合う → **「住所で確かめた」**で結びます。
  - 住所は合うが、名前が合わない・同じ建物にほかの店がある（LaLa）→ **「この店で間違いないですか」と聞きます。** Google マップで開いて確かめてから OK を押したときだけ「手で確かめた」で結びます。
  - 住所が合わない → 結びません。
  - 同じ Google の店を 2 つの店に結ぶことはできません（ToriTon と Tenkichi・Totoya Piikoi と LaLa は同じ建物）。
- 店の名前だけでは決めません。住所の目安（SQL の `gr_place_hint`・2b ではじめの値を入れる）：

  | 店 | 住所の目安（すべて合う語） | 名前（どれか） | 気をつけること |
  |---|---|---|---|
  | ToriTon（F01） | 2334・King・96826 | toriton | Tenkichi と同じ建物 |
  | Tenkichi（F02） | 2334・King・96826 | tenkichi | ToriTon と同じ建物 |
  | Totoya Kaimuki（F04-K） | 1127・12th・96816 | totoya | |
  | Totoya Piikoi（F04-P） | 436・Piikoi・96814 | totoya | LaLa と同じ建物 |
  | Totoya Aiea（F04-A） | 99 115・Aiea・96701 | totoya | |
  | Marujuu（F05） | 1145・12th・96816 | marujuu | |
  | LaLa（F06） | 436・Piikoi・96814 | lala | **確かでない**：Google マップに店があるか未確認・同じ建物に Totoya Piikoi。いつも手で確かめる。Google マップに無ければ選ばない（**選ぶまで Google を呼ばない**） |

  Waikiki（F03・F03-G）など目安の無い店は「住所の目安がありません」と出て、Google を呼びません。
- **新しい店・店が移ったとき**（SQL Editor。店の ID・住所の語・名前を入れる）：

  ```sql
  insert into public.gr_place_hint (store_id, addr, names, unsure, note)
  values ('F03', array['番地', '通りの名前', '郵便番号'], array['店の名前'], false, null)
  on conflict (store_id) do update set addr = excluded.addr, names = excluded.names, unsure = excluded.unsure, note = excluded.note, updated_at = now();
  ```

  店が移ったときは、そのあと KPI設定でその店を「外す」→「選ぶ」でもう一度確かめる（前の店のままでは新しい住所と比べ直さない）。
  同じ建物に店がある（ToriTon と Tenkichi・Totoya Piikoi と LaLa のように番地・通り・郵便番号が同じ）ときは、**両方の店の目安をそろえて**入れる（片方だけ住所の語を変えると「同じ建物のほかの店」と分からず、名前が合わない方を自動で結ぶことがある）。新しい店がほかの店と同じ建物なら、その店の行と、もとからある店の行の両方を確かめる。
  住所の語は、カハコー（ā など）やʻokina が付いていても付いていなくても同じに比べます（文字と長音記号が別々になった形で入れても同じ）。ほかの記号で合わないと出たら、記号なしの形（`kalakaua` など）で入れ直してください。
- 今結んである店（v1157 で選んだ店）は、2b のあと選び直すまで Google を呼びません（① の最後の（参考）・③ の（参考））。

## 上限と料金（太平洋時間で日・月を区切る＝Google の請求と同じ）

| | 1 店 1 日 | 1 日 | 月 | 1 人 1 日 |
|---|---|---|---|---|
| 店の評価と口コミ（Place Details） | 1 回 | 確かめた店の数 × 1 回（天井 40 回） | 確かめた店の数 × 1 回 × その月の日数（天井 900 回） | 25 回 |
| 店を探す・選ぶときの確かめ（GM・CEO だけ） | — | 40 回 | 400 回 | — |

- 1 日と月の上限は、サーバーが**住所で確かめた店の数**から毎回決めます（店を足すと上がる・外すと下がる）。今日・今月の回数と残り・上限は GM・CEO の KPI設定に出ます。
- 数えるのは「Google を呼んだ回数」（Google が断った回も数える）。上限なら Google を呼ばずに「この店の今日の上限（1 回）に達しました」などと出ます（太平洋時間の 0 時＝ハワイの 21〜22 時に戻る）。
- 上限で取れなかった画面は、サーバーが数えた太平洋時間の日（月の上限は月）が変わると、開いたままでも「見る」に戻ります。押した直後に 0 時をまたいでも、翌日いっぱい残ることはありません（#216 の Codex の P2・2b と ④ の両方を入れたとき。片方だけでも、画面は押した時刻の日で戻します）。
- 上限を変えるとき（SQL Editor）：1 店 1 日を 3 回に → `update public.gr_settings set places_store_day_max = 3 where id = 1;`（確かめた店 6 店なら月 6 × 3 × 31＝558 回＝無料の中）。天井は `places_day_max`・`places_month_max`。0 にするとその呼び出しを止めます。
- 料金（Google Maps Platform の料金表・2026-11-23 に確かめた。変わることがある）：
  - 店の評価と口コミ（評価・件数・口コミを取る）は「Place Details Enterprise + Atmosphere」。**月 1,000 回までは無料**、こえた分は 1,000 回あたり約 $25。
  - 店を選ぶときの確かめ（名前・住所）は「Place Details Pro」。月 5,000 回までは無料、こえた分は 1,000 回あたり約 $17。
  - 店を探す（名前・住所）は「Text Search Pro」。**月 5,000 回までは無料**、こえた分は 1,000 回あたり約 $32。
  - 見込み：確かめた店 6 店（LaLa を除く）× 1 回 × 31 日＝**月 186 回まで**（全部押しても無料の中・$0）。LaLa を足しても 217 回。店を選ぶのははじめの 7 店で探す・確かめるが 20〜30 回くらい（無料の中）。上限をこえることはサーバーと 6 の割り当てが止めます。
  - 無料の回数は Google の請求先（請求アカウント）ごと・種類ごとです。同じ請求先でほかに Places API を使っていれば、その分も数えられます。
  - Business Profile（v1157）の口コミの取り込みは Places の料金ではありません。
- 本物の Google を使って確かめるのは、13 で押すときだけ（店ごとに 1 回＝上の無料の中）。Claude の試験は合成のデータと偽の Google だけで、本物の Google・本番にはつないでいません。
