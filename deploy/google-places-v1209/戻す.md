# Google の評価・口コミ（Places API）を止めたいとき（v1209）

いちばん軽い止め方から順に：

1. **Google（Places API）を呼ばないようにする**：SQL Editor で `止める_Places.sql` を Run。ダッシュボード・会議のカード・KPI設定の「見る」も、店を探す・確かめるのも、Google を呼ばずに「上限」と出ます。店の結び・住所で確かめた印・回数は残る。また始めるときは、同じファイルの「再開」の行（`update public.gr_settings set places_day_max = 40, search_day_max = 40 where id = 1;`）。1 店 1 日の上限（`places_store_day_max`）は変えないので、再開すると前と同じ（確かめた店の数 × 1 店 1 日の上限）に戻ります。
2. **1 つの店だけ止める**：GM・CEO が KPI設定 ›「Google の口コミ」でその店を「外す」。その店は Google を呼びません（選び直すと、もう一度住所で確かめる）。
3. **鍵を外す**：Supabase の Secrets から `GOOGLE_PLACES_API_KEY` を消す。アプリは「Places API の鍵がサーバーに入っていません」と出し、Google を呼びません。Google Cloud で API キーを無効にしたときは、Google が断り、アプリは「Google が断りました」と出します（呼んだ回数には数えます）。
4. **関数を v1157 に戻す**：Edge Functions → `google-reviews` に `deploy/google-reviews-v1157/4_関数_google-reviews_index.ts` を貼って Deploy。
   - **気をつけること**：v1157 の関数には、回数の上限と「見られる店だけ」の確かめがありません（関数に入れる人ならどの店の評価・口コミも見られる・KPI の数も全店）。v1209 のアプリは押したときだけ呼ぶので、勝手に呼ぶことはありません。アプリも v1157 まで戻すと、会議のカードを描くたびに呼びます（料金）。
   - 2b の SQL のあとは、v1157 の関数の「選ぶ」では店を結べません（SQL が `use_confirm` で断り、v1157 の関数はその理由を知らないので、画面には「うまくいきませんでした」などと出ます）。店を結ぶときは v1209 の関数に戻す。外すのはできます。
   - 2b の SQL のあとも、v1157 の関数が Google を呼ぶのは**住所で確かめた店だけ**です（`gr_place_of` が確かめた店しか返さない）。
5. **アプリを前の版に戻す**：この PR を revert。

SQL（② と 2b で足した欄・表・関数）は戻さなくても、v1157 の関数は困りません。消したいときは Claude に言ってください（回数の記録・確かめた印が消えます）。

## SQL を流し直したとき

- 2b のあとに v1157 の ② か v1209 の ② をもう一度流すと、店を結ぶ関数が前のもの（住所で確かめない）に戻ります。③ の 7 が NG になるので、2b をもう一度流してください（確かめた店・住所の目安・回数は消えません）。
- v1157 の ② をもう一度流すと、Google を呼ぶ店の関数も前のもの（確かめていない店も呼ぶ）に戻ります。同じく 2b をもう一度。
