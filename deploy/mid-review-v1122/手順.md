# 中間レビュー v1122（デモをやめて本番に・中間レビューだけのメールの認証をやめる）を入れる手順

Moto さん 10/30 の依頼 ⑥。中間レビューを本番のデータだけで使えるようにします。

- **デモをやめる**：架空の店・見本の数字・デモの切り替えは出ません。一覧と店のページは、本番の店・月・担当と、会議タブと同じ数字（読むだけ）だけです。
- **メールの認証をやめる**：中間レビューに入るときのメールとパスワードは聞きません。アプリの **PIN のログイン** で、サーバーがだれかを確かめ、役職と店で「見られる・入力できる・確認できる」範囲を決めます（アプリのログインと権限はそのまま）。
- **だれが入れるか**
  - CEO・GM：アプリのメールのアカウント（manager_auth）に社員 ID があれば、PIN で初めて入ったときに中間レビューの利用者になります。担当・閲覧設定・期限・確認完了の取り消しも PIN でできます。
    - manager_auth の社員 ID がその人を指しているあいだだけ入れます。社員 ID を直すと、前の人はすぐ入れなくなり、直した先の人が PIN で入ったときに行が移ります。退職した人は入れません。
  - AM：社員の表で在籍の AM は、この SQL で利用者になります（店舗の管轄で選べるようになります）。
  - Head Chef・Corporate Chef・入力担当・追加の閲覧者：今までどおり GM・CEO が担当・閲覧設定で選びます。
- **入力担当は名前で選ぶ・何人でも**（10/30「指名、複数選択可に」）：店ごと・その月だけの入力担当を、閲覧者と同じ形で何人でも（10 人まで）選べます。選んだ人はだれでも書けて提出できます。2 人が同時に書いたときは、あとから保存した人に「先に保存されました」と出ます（黙って上書きしません）。
- **スイッチ**：この SQL が「非公開確認（中間レビュー）」と「本番の店の入力」を ON にします（初めて流したときだけ。もう一度流しても、GM・CEO があとで OFF にしたものは OFF のまま）。店舗公開・通知は OFF のままです。
- **前の記録**：本番の店の下書き・提出版・返信・確認は消しません。デモの行は表に残りますが、読まれず書かれません。

関数（mid-review）は、入力担当を 2 人以上にするところだけ変えました。PIN の確かめの入った非公開の 1 ファイルは Claude が作って直接渡します（作るのに、前に渡した部品の zip が要ります）。貼るものは **全文をそのまま** 貼ります（書き換える所はありません）。

## 入れる

| 順 | 何を | どこで |
|---|---|---|
| 1 | `1_追加のSQL_本番にする.sql` を貼って Run（2 回流しても同じ） | SQL Editor |
| 2 | `2_確認のSQL_読むだけ.sql` を貼って Run → **`mid-review live (20261102090000)` が `OK`**、ほかの行も `OK` か `参考`。`注意` の行は、その行の文のとおりに直す | SQL Editor |
| 2b | 関数 `mid-review` を、Claude が直接渡す 1 ファイル（非公開・PIN の確かめ入り）に差し替えて Deploy | Edge Functions |

| 4 | 中間レビューを使う人の端末をすべて v1122 に更新（アプリの更新の知らせ） | 各端末 |
| 5 | GM・CEO が PIN でログインして、中間レビュー › 担当・閲覧設定で、店ごとの入力担当と店舗の管轄を確かめて保存 | アプリ |

1 で「先に 20261016090000・20261017090000・20261018090000 の中間レビューの SQL を流してください」と出たら、何も変わっていません。Claude に伝えてください。

順番は 1 → 2 → 2b → 3 → 4 → 5 です。2b（関数）が遅れても、ほかは進められます：関数が前のままのあいだは、入力担当を 2 人以上に保存できず、画面が「1 人だけ保存されたかもしれません」か「入力担当が 2 人以上います…」と出します（データは壊れません）。2b のあと 5 でもう一度選んで保存します。

- 3（マージ）を 1 より先にすると、サーバーがまだ前の決まりなので、v1122 の画面では CEO・GM が入れない、担当・閲覧設定が「サーバーがまだ v1122 になっていません」と出て開けない、ということがあります（何も書かれません。1 を流せば使えます）。
- 1 のあと 4 までのあいだ、前の版（v1121 以前）の端末でデモを開くと「前の版の画面の操作です。アプリを更新してください」と出ます（デモは使えなくなります）。
- 前の版の端末の本番の店は、ほぼ今までどおり使えます。ただし AM が、Invoice取込・業務Bot などでメールのログインをしたままの前の版の端末で開くと断られます（前の版はメールを先に使い、この SQL で作る AM の行にはメールのアカウントが無いため）。画面の「PIN で入る」を押すか、端末を v1122 にします。

## 入る人の注意

- PIN が初期のままの人は、PIN のログインの印が出ないので中間レビューに入れません。自分の PIN に変えてもらいます。店舗のログイン（共有の PIN）では入れません（今までどおり）。
- 2 の確認で `ceo / gm accounts without an employee id` が `注意` なら、その CEO・GM は PIN では入れません。`db/invoice-signin-emp-check.sql`（読むだけ）で確かめて、manager_auth に社員 ID を入れます。
- `ceo / gm rows whose account names another employee`・`ceo / gm accounts linked to someone resigned or not ceo / gm` が `注意` なら、manager_auth の社員 ID が正しいか確かめます（違う人に結ばれていると、その人が GM として入れてしまうので、v1122 では社員 ID が合う人だけを通します）。
- 入力担当が未設定の店は、だれも入力できません（2 の `live stores without an input person` が `参考` で数を出します）。5 で選びます。
- 入力担当を SQL で直すときは、`input_emps`（名簿）を直します。`input_emp` だけを変えても効きません（2 の `input_emp not the first of the list` が `注意` になります）。

## 困ったとき

- **SQL がエラーになった**：エラーの文をそのまま Claude に貼ってください。
- **止めたいとき**：GM・CEO が中間レビューの設定で「非公開確認」を OFF にします（PIN で開けます）。画面が開かないときは `db/mid-review-stop.sql`（記録は消しません）。
- **ある人だけを止めたいとき**：`db/mid-review-disable-member-by-employee.sql`（社員 ID で探して止める。AM の行はメールのアカウントを持たないので、メールで探す `mid-review-disable-member.sql` では止められません）。CEO・GM を外すのは manager_auth の役職の側が確かです。
- **あとで前の中間レビューの SQL（`20261015090000` から `20261018090000`）を流し直したとき**：この SQL が元に戻る（メールの認証が戻る）ので、続けて 1 をもう一度流します（2 の確認で `mid-review live (20261102090000)` が NG になって分かります）。1 をもう一度流しても、スイッチは今の状態のままです。
- **戻したいとき**：Claude に伝えてください（アプリと SQL を一緒に戻します）。
