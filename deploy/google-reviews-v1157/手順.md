# Google の口コミを入れる手順（v1157：UI案73 の答え）

会議の Google の口コミのカードと KPI の Google の欄を、手入力から Google のデータに変えます。

- **Business Profile API**（自分の店のデータ）：毎日 4:30（ハワイ）にその店の口コミを全部取って残します。会議にはその月の口コミをすべて出します。月はハワイ時間の投稿日。
- **Places API（新）**：Business Profile をつなぐまでのあいだ、店の総合評価と、Google が返す口コミ（最大 5 件）を、見るときに取って出します。Google の決まりで、残してよいのは店の place ID だけなので、総合評価・口コミの中身はどこにも残しません（見るたびに取る＝有料の呼び出し）。
- **手入力**：Business Profile で口コミを初めて取り終えるまでは、今までどおり手入力（Moto さんの答え「API 繋ぐまでは手入力」）。初めて取り終えたら、その前の月から自動になります（それより前の月は手入力のまま）。

## A. Google Cloud（Business Profile の審査は最大 14 日かかるので先に出す）

1. **Business Profile API の使用を申し込む**（Google の「Business Profile API の利用申請」のフォーム。申請は Google Cloud のプロジェクトごと）。
   - 審査が通るまで、つなぐことはできますが口コミは取れません（アプリには「審査待ち」と出て、手入力のまま）。
   - 同じプロジェクトで「My Business Account Management API」「My Business Business Information API」を ON。審査が通ると「Google My Business API」が出てくるので、それも ON。
2. **Places API（新）を ON にして API キーを作る**（請求先のあるプロジェクト）。
   - 「API とサービス」→「ライブラリ」→「Places API (New)」→ 有効にする。
   - 「認証情報」→「API キーを作成」→「API の制限」で **Places API (New) だけ**にする（アプリケーションの制限は「なし」：Supabase のサーバーから呼ぶため）。
3. **OAuth のクライアント**（Business Profile の審査を出したのと**同じプロジェクト**の「ウェブ アプリケーション」）。
   - 「承認済みのリダイレクト URI」に `https://tgbhgxzehzeouopklhje.supabase.co/functions/v1/google-reviews` を足す。
   - 同意画面のスコープに `business.manage` を足す。同意画面が「内部」なら、Business Profile を管理している Google アカウントが funergygroup.com のアカウントであること（そうでなければ「外部」にする）。
   - Gmail（v1094）のクライアントが同じプロジェクトならそれを使ってよい（リダイレクト URI を足すだけ）。違うプロジェクトなら新しく作る。

## B. Supabase

4. **Edge Functions → Secrets に入れる**（画面にもリポジトリにも出さない）：
   - `GOOGLE_PLACES_API_KEY`：2 の API キー。
   - `GBP_OAUTH_CLIENT_ID`・`GBP_OAUTH_CLIENT_SECRET`：3 のクライアント（入れなければ Gmail の `GMAIL_OAUTH_CLIENT_ID`／`SECRET` を使う）。
5. **SQL Editor に ① を貼って Run。**「STOP」が 1 つも無ければ次へ。1 の行が 0 なら初めて、7 ならもう入っています（② をもう一度流しても同じ）。4 が「あとで」でも ② ③ は流せます。
6. **SQL Editor に ② を貼って Run。**「Success」なら次へ。エラーなら止めて、エラーの文を Claude に。
7. **SQL Editor に ③ を貼って Run。**「result」の列に NG が 1 つも無ければ次へ。
8. **Edge Functions →「Deploy a new function」→「Via Editor」、名前を `google-reviews` にして、④ の中身を全部貼って Deploy。Verify JWT は OFF。**
   - 関数の設定で Verify JWT が ON になっていたら OFF にする（Google から戻ってくるときに鍵を付けられないため）。
9. **SQL Editor に ⑤ を貼って Run。**最後の表に `google-reviews-daily`・`30 14 * * *`・`true` が 1 行出れば OK（4:30 HST）。

## C. GitHub とアプリ

10. **この PR をマージ。**
11. **端末で「更新」**。ログイン画面の版が 1157 になれば OK。
12. **GM・CEO：KPI設定 →「Google の口コミ」タブ**
    - 店ごとに「Google の店を選ぶ」（名前で探して選ぶ＝Places の place ID だけを残す）。ここまでで、会議のカードに総合評価と最近の口コミ（最大 5 件）が出ます。
    - 「Google でログインしてつなぐ」→ Business Profile を管理している Google アカウントで許可 → アプリに戻る。
    - 審査が通っていれば、店ごとに「Business Profile の店を結ぶ」→「今すぐ取る」。初めて取り終えた店は「自動（YYYY-MM から）」になります。
    - 審査待ちのあいだは「審査待ち」と出て、手入力のまま。審査が通ったら「今すぐ取る」を押すだけ（つなぎ直さなくてよい）。

## 決まり（Moto さんの答え 11/13 18:42 HST）

- **毎日取る**（1）：4:30（ハワイ）。GM・CEO は「今すぐ取る」でも取れる。最後に取れた時刻の 3 日前から、新しく直された順に取り直す（直された口コミ・返信も入る）。
- **つなぐまでは手入力**（2）：Business Profile で初めて取り終えるまでは、KPI の手入力（gAvg・gCnt・総合評価）を今までどおり使う。自動になった月は手入力の欄を出さない。
- **会議に全部出す**（3）：その月の口コミをすべて（星だけの口コミも・名前なしも）。新しい順。5 件以上のときは「すべて広げる」。
- **設定は KPI設定の中**（4）：「Google の口コミ」タブ。決める・つなぐのは GM・CEO だけ。ほかの人は見るだけ。店のタブレットには出さない。
- **残さないもの**：Places の総合評価・口コミの中身（Google の決まり）。この端末にも残さない（画面を開いているあいだだけ）。
- **費用**：Places の呼び出しは Google Cloud の請求に入ります（月の無料枠あり）。Business Profile の総合評価があるときは Places を呼びません。1 人 1 分 30 回までに止めています。
