# 2b：事務Crew のメールのアカウントを作る手順（B-1 の書類・Invoice取込・照合・QuickBooks の状態）

Moto さん 11/24「GMやCEOの様にメールで登録（ログインはPINでも入れる様に）」。仕様：`docs/ACCT_VIEW_V1211_JA.md` の 9。

- **何ができるようになるか**：経理センター › 経理レビュー › 書類（Invoice取込・照合・QuickBooks の状態）を、事務Crew が経理リーダー・経理マネージャー・GM と同じに開けます（Invoice取込で事務Crew は前から経理と同じ・v1059）。
- **ふだんは PIN のまま**：PIN でログインして Invoice取込（書類）を開くと、その端末で最初の 1 回だけメール認証になります。そのとき「この端末で覚える」に印のままにすると、次からはその人の PIN のログインだけで開けます（v1063）。
- **メールの事務Crew と全く同じ**になります（11/24 の答え）。申請・セキュアな記録（Tip・通知・変更の記録など）も、メールのアカウントの事務Crew として決まります（GM・CEO の「事務Crew と確かめる」が無くても同じ）。GM・CEO だけのもの（給与・賞与・ほかの人の成長カルテ）は見えないままです。
- SQL の関数・表・アプリ・Edge Function は変えません。足すのは、その人の manager_auth の 1 行（役割 office_crew・社員の ID）だけです。
- 経理出力の中で事務Crew が開ける部分（ガソリン代・立替経費の Payroll 別）は B-2（v1212）で作ります。

**メール・名前・パスワードは GitHub・PR・共有の場所に書かないでください。** ひな形を書き換えたものも保存しないでください（このリポジトリは公開です）。

使うファイル：

| 番号 | ファイル | どこで |
|---|---|---|
| ① | `1_最初に確認_読むだけ.sql` | Supabase の SQL Editor |
| ② | `2_事務Crewのアカウントを足す_ひな形.sql`（1 人ずつ書き換えて） | Supabase の SQL Editor |
| ③ | `3_確認_読むだけ.sql` | Supabase の SQL Editor |
| 止める | `止める_ひな形.sql`（退職・異動のとき） | Supabase の SQL Editor |

## A. 確かめる

1. **SQL Editor に ① を貼って Run。**「STOP」が 1 つも無ければ次へ。
   - 1〜4 が STOP：何も変えずに止めて、その行を Claude に。
   - 5・6 が STOP：manager_auth の列が思っていたものと違います。② は流さずに、その行を Claude に（ひな形を合わせます）。
   - 8：メールのアカウントがまだ無い在籍の事務Crew の人数（B で 1 人ずつ足す）。9 が 0 でなければ、その人は社員の ID が空です（B の 2 で入れ直すと直ります）。

## B. 1 人ずつ足す

2. **Authentication → Users → Add user（Create new user）**で、その人のメールとパスワードのアカウントを作る（Auto Confirm User に印）。もうあればそのまま。パスワードは本人に直接・安全に渡す（チャット・GitHub に書かない）。
3. **SQL Editor に ② を貼り、上の 2 つを書き換えて Run。**
   - `v_email`：そのメール。`v_who`：従業員マスターの社員の ID（確か）か、名前（完全に同じ。在籍の事務Crew で 1 人だけ当たるとき）。
   - 「Success」と最後の表（`ok` が 1 つ増える）なら足せました。2 回流しても同じです。
   - 「STOP: …」なら何も変わっていません。文のとおりに直します（メールのアカウントが無い・社員が見つからない・退職・事務Crew でない・そのメールがもう CEO／GM／経理のアカウント（役割は下げません）・別の社員と結ばれている・その社員がもう別のメールと結ばれている）。分からなければ、STOP の文から名前とメールを消して Claude に。
4. **本人の端末で**：PIN でログイン → 経理センター › 経理レビュー › 書類（または インボイス取り込み）を開く → メール認証（その端末で最初の 1 回）→「この端末で覚える」に印のまま。次から PIN のログインだけで開けるか確かめる。
   - PIN が初期のまま（誰でも知っている番号）だと、毎回メール認証になります。先に PIN を変えてもらいます。
   - 共有のパソコンでは「この端末で覚える」を外します（その端末とその人の PIN を知っている人が使えてしまうため）。

## C. 確かめる

5. **SQL Editor に ③ を貼って Run。**事務Crew のアカウントの行がすべて `result`＝OK（`invoice_role`・`pin_role` が office_crew）なら終わりです。NG の行は `note` のとおりに。Claude に見せるときは no・result・note だけ（メールの列は貼らない）。

## 止めるとき（退職・事務Crew でなくなった・メールを変える）

- `止める_ひな形.sql` のメールを書き換えて Run。そのメールの事務Crew の行だけを消します（CEO・GM・経理の行・社員の表・申請・記録は変えない）。
- **退職のときは必ず**：Invoice取込はメールのアカウントの役割だけを見るので、従業員マスターを退職にしただけではメールのログインで入れてしまいます。メールのログイン自体も止めるなら Authentication → Users でその人を Ban（または Delete）。
- PIN のほう（申請・セキュアな記録）は、従業員マスターの退職か、GM・CEO の「確かめを外す」で止まります（セキュアな記録は最大 60 秒あと）。
- もう一度使うときは ② を流します。

## 試験（Claude・合成データ）

- `tests/office-crew-account-2b.test.mjs`：本物の申請の SQL（PGlite）に偽の `auth.users` と Invoice取込の `invoice_actor_role`（本物の SQL の写し）を足して、①②③・止めるを流す。名前・メールは架空。本番にはつないでいません。
