読むのを関数 `secure-state` だけにして、最後に公開の鍵（ブラウザーの鍵）で読めない・書けないようにします（v1139〜v1147 と同じ決まりにキーを足すだけ）。

  AM・G1〜G5・Head Chef・店長・リーダー＝3 つとも Career Score で見られる人と本人の分／店のログイン（店舗の PIN）＝受け取らない。
- **書くのは今までどおり GM・CEO だけ**（v1143・v1145）。

**順番：v1141（PR #135）→ … → v1147（#141）→ この v1148 の順にマージします。**
v1139〜v1147 の ③ をまだ流していなくても、この手順の ③ は単独で入ります。

## A. 確かめと関数（いつでも。アプリより先でもあとでもよい）

   - 2 行目（前の決まり）・3 行目（RLS）は info のことがあります。そのまま進めてよい。
   - 4〜6 行目（3 つの行の形と記録の数）が NG なら Claude に（関数はその行を読めません）。info（JSON の文字の行・社員 ID の読めない記録）も Claude に

   - 7 行目（書く決まり）が info なら、v1143・v1145 の ③ がまだです（この手順の ③ だけでも公開の鍵からは読み書きできなくなります）。
   - 8 行目（事務Crew のアカウントに結ばれていない事務Crew）が info なら、その人は関数 v1148 のあと、グレード履歴が自分の分だけになります（HR・福利厚生の画面で全員のグレードが分からない）。
     manager_auth に社員 ID を結んでください（Claude に）。
   - 9 行目が info（社員 ID が社員の表に無いアカウント）なら、その人は何も見えなくなります（v1142 からの決まり）。`db/invoice-signin-emp-check.sql` で確かめて直してください（Claude に）。
   - 10 行目（確かめがまだの AM・G2 以上・Head Chef・店長・リーダー）が info なら、その人は GM・CEO が「承認・閲覧の権限の確かめ」で確かめるまで、

## B. アプリ

3. **v1141〜v1147 の PR をマージしてから、v1148 の PR をマージ。**
4. **全員の端末で、アプリの「更新」を押す。**ログイン画面の版が 1148 になれば OK。とくに GM・CEO・経理・事務Crew・AM・G4・Head Chef・店長・リーダーの端末（PC・スマホ・タブレットすべて）。
   - **GM・CEO 以外の端末は、「更新」を押す前に**（まだ 1147 のうちに）右上の保存のボタンを見て、「送信待ち」が残っていればつながる所で「今すぐ送る」を押し、0 になってから更新してください。

5. **（確かめ・③ の前に）その端末の「設定 › 診断と記録」を見る。**関数を v1148 にする前に開いていたアプリは 10 分 REST を使うので、一度閉じて開き直してから。
   - ログインのあと「グレード履歴：全部・賞与の個人設定と G3 の職種：全部（サーバー secure-state v1148 から。…）」（GM・CEO）、

## 変わること

- グレード履歴・賞与の個人設定・G3 の職種は、見られる人の分だけが端末に届きます。前に端末にあったほかの人の分は消えます（送れていない変更のある行は残します）。
- 画面は今と同じです（Career Score の基準点・G3 の職種は見られる人の分、休暇の福利厚生の確かめは本人の分、グレード履歴・個別評価・査定一覧は GM・CEO だけ、HR・福利厚生は CEO・GM・経理・事務Crew）。
- 店のタブレット（店舗の PIN）では、この 3 つを受け取りません（Career Score と同じ）。
- GM・CEO 以外の端末から、この 3 つは保存できません（前から。同じ値の送り直しも断ります）。

## 困ったとき

- 「グレード履歴・賞与の個人設定・G3 の職種を変えられるのは GM・CEO です…」と出た：GM・CEO に頼んでください。
- 「…をサーバーが断りました（送信待ちに残しています）」と出た：前の版で入れた送れていない変更です。GM・CEO に入れ直してもらい、
  その端末で（その人のログインのまま）右上の「保存」→「断られたものを外す…」→「外す（クラウドの値に戻す）」で送信待ちから外れます。
- ③ の前に関数でうまく読めない：関数を v1147 に戻す（`deploy/secure-tip-cf-v1147/2_関数_secure-state_index.ts` を貼って Deploy）。アプリ 1148 はそのままで今までどおり（REST で読む）。
- 店長などが「見られない」と言う：まず GM・CEO の確かめがまだでないかを見る（① の 10 行目）。確かめたら、その端末で「最新に更新」。
- ③ のあとに見られるはずの人が見られない：まず `戻す_SQL.sql` を流す（この 3 つをまた公開の鍵で読めるようにする。ほかは変えない）。そのあと Claude に。
  関数を v1147 に戻すときも、先に `戻す_SQL.sql` を流してください（v1147 の関数は REST で読むので、③ のままだとだれも見えなくなります）。
- v1147 より前の戻す SQL（`deploy/secure-tip-cf-v1147/戻す_SQL.sql` など）を v1148 のあとに流すと、決まりの関数が前の形になり、この 3 つもまた公開の鍵で読めるようになります。
  この 3 つだけを戻すときは、この一式の `戻す_SQL.sql` を使ってください。
- ③ のあと、1147 以前の端末ではこの 3 つを読めません。更新して 1148 にすれば使えます。
